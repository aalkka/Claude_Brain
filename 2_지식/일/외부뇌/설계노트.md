# 외부뇌 설계노트 (통합)

> **이 문서는 무엇인가.** 외부뇌(External Brain)가 **왜 지금의 모양인지**를 설명하는 단일 설계 문서다. 어떻게 쓰는지는 [[사용자설명서]]의 튜토리얼과 [[찾아보기]]에 있고, 이 문서는 «왜 이렇게 지어졌나»를 적는다.
>
> **기준일 2026-11-03, as-built.** 제작자 볼트를 기준으로 지금 실제로 있는 것만 서술한다. 개인 기능(LMS·웹 수집기, 금고, 개인 실험, 공부 모듈)은 배포판에 없다. 구상됐다가 잘려나간 장치는 [[#10. DEFERRED 창고|§10 DEFERRED 창고]]에 복원 조건과 함께 둔다. 옛 설계의 까닭이 지금도 유효하면 남기고, 무엇이 바뀌었는지를 함께 적는다. 스펙과 코드가 어긋나면 코드가 진실이다. 숫자는 이날 파일에서 다시 잰 값이고, 기록에서 옮긴 값과 추정은 그렇게 밝혔다.
>
> 결정 기록(ADR)은 제작자 볼트에 있고 배포판에는 싣지 않는다. 본문은 까닭을 풀어 쓰고, 번호는 출처 표시다.

## 1. 목적 — 세 가지

외부뇌는 개인 1인 지식관리 시스템이다. Obsidian 볼트(마크다운) 위에서 Claude Code가 지식을 쌓고 검색하고 되살린다. 세 목적을 위해 존재한다.

1. **토큰 최적화** — 불필요한 토큰을 없애고, 필요한 작업을 최소 토큰으로 완수한다. (입력토큰×입력단가 + 출력토큰×출력단가를 낮춘다.)
2. **맥락 복원** — 매번 긴 프롬프트로 설명하지 않아도, 이전 흐름과 사용자 정보를 자동으로 되살려 대화한다.
3. **답변 질 향상** — 답변에서 쓸모없는 부분을 제거하고, 근거 있는 구조화된 답을 만든다.

이 세 목적이 모든 설계 결정의 저울이다. 어떤 장치가 셋 중 하나에 직접 지렛대가 되지 못하면, 그것은 기둥이 아니라 가지다([[#9. 설계 원칙|§9 설계 원칙]]).

저울의 기울기는 한 번 바뀌었다. 2026-11-02 코어 개혁(ADR-025)은 «목적은 토큰보다 성능»이라고 정했다. 짧게 쓴 규칙은 문체(압축·평문·강조·영어)가 달라도 행동이 같았고, 낡은 사실만 답을 틀리게 했기 때문이다(제출본 자리 질문의 현행 답 0/3 → 고친 뒤 3/3, 기록값). 그래서 개혁의 기준이 입력 줄이기가 아니라 낡은 사실·모순 정리가 됐다. 세 목적 자체는 그대로다.

## 2. 왜 다시 지었나 — 구 시스템의 두 뿌리 문제

외부뇌는 처음부터 이 모양이 아니었다. 전신은 **Claude_Obsidian**(Cowork 기반, 옛 볼트 `C:\Claude_Obsidian`)이었다. 사상과 골격(원자 노트·프론트매터·MOC·링크=메모리·3목적)은 견고했고 실제로 잘 작동했다. 문제는 골격 위에 얹힌 방어·최적화 장치들이 서로 얽히며 비대·불안정해진 것이었다. 사용자의 재설계 동기: *"기본 뼈대에 추가사항이 더해지며 계획안보다 비대해지고 그로 인해 불안정해짐. 해결 불가한 문제를 여럿 안고 있음."*

전수 진단 결과, 11종의 반복·치명 문제가 **두 개의 뿌리**로 수렴했다.

### 뿌리 ① — 샌드박스 ↔ PC 이중 실행 환경
Cowork(샌드박스)와 PC(Obsidian·git·스케줄러)가 같은 파일·같은 `.git`을 각자 만졌다. 여기서 치명 문제들이 파생됐다.
- **파일 꼬리 절단**: 쓰기 완료 전 외부 프로세스 경합으로 .md 뒷부분이 잘림. "모든 .md는 bash로만 쓴다"로 회피했으나 근본 해결은 아니었다.
- **git 인덱스 경합**: 두 주체가 같은 `.git/index`를 조작 → lock 충돌. "Claude git 쓰기 전면 금지"로 봉합했으나, 대가로 **매 세션 사용자가 수동 커밋**해야 루프가 닫혔다. 자동화 시스템이 마지막 1미터를 사람에게 떠넘긴 셈.
- **샌드박스↔PC stale**: PC에서 git 복구해도 샌드박스는 구본/손상본을 계속 봄.

### 뿌리 ② — 방어 규약의 누적
문제가 터질 때마다 CLAUDE.md·conventions에 규약을 얹었다. 그 결과:
- **기본 로드 토큰 단조 증가**: 규약 누적으로 455 → 1,575토큰. 상한 관리에 매 세션 주의를 소모.
- **설계 ≠ 실작동**: 기능을 "노트로 존재"시키는 것과 "매 세션 발동 경로에 연결"하는 것이 분리 → 죽은 규약 발생. 발동을 보장하려 또 다른 장치(트리거 로그)를 얹는 악순환.
- **방어 규약 비대·복잡**: 한 방어가 새 취약성을 낳는(bash 강제 → sed 편집 불안정) 얽힘.

### 재설계의 방향
두 뿌리를 정면으로 겨냥한다.
- **뿌리 ① → 실행 환경 단일화.** Cowork를 버리고 **Claude Code**로 이전. Claude가 볼트에 직접 읽고 쓰는 단일 주체 모델 → 샌드박스↔PC 분리가 사라지고 꼬리 절단·git 경합·stale·수동 개입이 대부분 소멸.
- **뿌리 ② → 규약을 설계 시점에 최소 코어로 확정.** 사후 누적이 아니라, 기본 로드를 구조적으로 작게 고정하고([[#3.3 계층 로드|§3 계층 로드]]) 강제는 규약이 아니라 **결정론적 훅**으로([[#7. 훅 — 결정론적 보증층|§7 훅]]) 옮긴다.

구 시스템의 문제 12건(11종 + inbox 손실 버그)은 신 설계에서 전수 대응됐고, 그중 대부분이 봉합이 아니라 뿌리 제거(ROOT)다. 봉합책(bash 강제·git 금지 A규칙)이 낳던 부작용(수동개입·sed 불안정)은 뿌리를 없애자 **봉합 자체가 불필요**해졌다.

## 3. 핵심 아키텍처

### 3.1 Obsidian + Claude Code — 읽는 곳이 일하는 곳이 됐다
- **마크다운 = 진실 원본.** 모든 지식은 사람이 읽을 수 있는 .md 다. 인덱스·임베딩은 다시 만들 수 있는 파생물이라 잃어도 해롭지 않다.
- **쓰는 주체는 셋이다 — Claude Code, 옵시디언에서 쓰는 사람, 대본.** 옛 설계의 «Claude 단일 쓰기 주체»는 샌드박스↔PC 이중 환경의 꼬리 절단·git 경합을 없앴고(뿌리 ①) 그 효과는 그대로다. 달라진 것은 사람도 같은 볼트에 쓴다는 점이라, 지우기·옮기기·이름 바꾸기만은 `fileops.py` 하나로 모았다(§3.8).
- **Obsidian 은 뷰어이면서 작업대다.** 옛 서술은 «뷰어일 뿐 임베드하지 않는다»였다. 2026-10-30 제작자가 «그냥 옵시디언에 Claude 를 넣는 것은 별 도움이 안 된다»고 하면서 목표가 읽는 곳에서 일을 맡기고 되돌리는 곳으로 넓어졌고, 곁창 대화창을 포함한 바탕 플러그인이 생겼다(§3.7). 그래도 훅·검색·색인·행위 층은 Obsidian 이 꺼져 있어도 돈다.
- **플러그인 정책.** 옛 서술의 «3rd-party 플러그인 의존 = 0»은 2026-10-29 제작자 결정으로 철회됐다. 기본은 자체 제작이고 외부는 자체 제작이 비합리적일 때의 예외다. 배포판에 실린 플러그인 3개는 모두 자체 제작이다. 2026-08-17 에 뺀 Dataview 는 정책이 아니라 기술 사정이라 §10 에 있다.

### 3.2 폴더 구조 — 네 층, 네 영역
옛 서술은 «누가 읽고 쓰는가»로 세 갈래(1_수집·2_지식·3_시스템)를 나눴다. 2026-10-18 에 작업 자리 `0_작업`이 더해져 층이 넷이 됐고(ADR-014), 2026-10-31(R9)에 2_지식 안이 «이 파일은 무엇을 위해 있나»라는 물음 하나로 다시 짜였다.
```
Claude_Brain/
├── CLAUDE.md · README.md
├── 0_작업/<영역>/<주제>/   # 진행 중 작업. 끝나면 승격하거나 지운다
├── 1_수집/                # 받은 원본(§3.5): _inbox(받은함) · _색인 · _lms · 배움/<과목>/
├── 2_지식/                # MOC·recent·open-loops·주제·보존·장부 + 배움/ 일/ 생활/ 분야/ + 기록/ 일정/ modules/
└── 3_시스템/              # 기계: roles.json · conventions.md · 대본 · hooks/ · _index/ · _eval/ · _ref/ · ledger/ · tutorial/ …
```
- **네 영역**: 배움(배우는 일) · 일(만들거나 버는 일 — 외부뇌의 결정 기록도 `일/외부뇌/결정/` 에 있다) · 생활(계속 돌보는 삶) · 분야(어느 일 없이도 남는 앎). 일어난 일은 `기록/`, 날짜가 붙은 줄은 `일정/` 에 둔다. 옛 `노트` 칸은 없앴다. 분류기가 못 가르면 «확신 낮음»으로 내서 사람이 고른다.
- **자리는 역할 이름으로 묻는다.** 정본은 `3_시스템/roles.json` 이고 코드·훅·스킬은 경로를 글자로 박지 않는다(§3.9). 설계노트·사용자설명서는 이름으로 찾는다(ADR-021).
- **1_수집**: 원본은 내용을 고치지 않는다. 시스템이 하는 일은 색인 생성·갱신, 받은함에서 분류 폴더로 이동(복사 금지, 같은 sha256 은 들이지 않고 보고), 제출본 PDF 보관, 승격 시 원본을 `_inbox/_promoted/` 로 이동이다. 메모 md 는 사용자가 요청할 때만 쓴다. 옮기고 지우는 것은 사용자가 자유롭게 하고 시스템이 따라가며(§3.10), Claude·대본은 보존 일정표대로 휴지통을 거쳐서만 지운다(옛 서술: «삭제는 사용자가 직접 지시한 경우에만»).
- **0_작업**: 넣고 지우기 자유이고 «원본 불변»이 적용되지 않으며 md 아닌 파일은 git 에 안 들어간다. 끝나면 제출본 PDF 는 `1_수집/배움/<과목>/제출/` 로 복사하고 지식은 2_지식 으로 승격하거나 지운다. 끝났는지는 `work.py` 가 제출·일정·멈춤으로 판정한다.

### 3.3 계층 로드
토큰 최적화의 핵심 원리는 **"넣은 걸 압축"보다 "애초에 안 넣기"** 다. 수많은 노트를 로드하지 않는다.
- **T0 (항상 로드)**: `CLAUDE.md`(29줄 · 3,083바이트)와 자동 메모리 `MEMORY.md`(56줄 · 8,296바이트, 상한 200줄·25KB). 규약과 사용자 정체성이다. 둘 다 제작자 볼트에서 잰 값이고 토큰 수는 재지 않았다.
- **T1 (세션 시작 주입)**: SessionStart 훅이 `recent.md`(9줄까지 · 줄당 150자)·`open-loops.md`(6KB 안)·일정 7일(최대 8줄)을 넣는다. 일정을 넣으면서 recent 를 10줄에서 9줄로 줄여 상쇄했다(ADR-017).
- **T2 (검색으로만 로드)**: 지식 노트·기록·`_ref`. **통독 금지** — 검색 top-k 나 주제 지도(`moc.py`)로 후보를 좁히고 필요한 범위만 읽는다. MOC 는 검색 색인에서 뺐다(11-02, §12.9).

CLAUDE.md 는 4절이다: §0 사용자(인터뷰로 채우는 개인 칸) · §1 세션 시작 · §2 읽기·쓰기 · §3 진화(규칙을 하나 더하면 하나를 뺀다, 200줄 이하). 11-02 코어 개혁이 낡은 사실과 모순을 정리하고 스킬 목록 줄을 뺐다. 제작자 볼트는 §0 에 «틀린 것은 거절» 규칙도 둔다(§9).

### 3.4 git·백업 — 2-repo 모델
- **볼트 = git repo.** 커밋은 Stop 훅이 턴마다 한다(Claude 변경분과 사용자 1_수집 변경분을 author 분리). SessionEnd 훅은 best-effort 백업이고 push 는 세션 시작과 종료에 한다.
- **push 제외**: `sensitive: true` 노트(pre-commit 이 unstage) · 파생·휘발분(`_index`·`_claude-memory`) · 원본(1_수집·0_작업 의 비 md 파일, 색인, 영상) · 금고 · 휴지통 `.trash/` · 플러그인 본체. 정본은 `.gitignore` 다. 원본을 빼는 까닭은 저장소가 원본 크기만큼 영구히 커지지 않게 하려는 것이고, 그래서 **원본 백업은 git 밖의 일**이다(2026-10-14).
- **2-repo 모델**: 배포 repo(모두 clone 하는 템플릿)와 개인 repo(각 사용자의 실제 진화 볼트). 설치한 볼트의 `origin` 은 개인 repo, `dist` 는 공개 배포 repo 다(`git remote -v`). setup-interview 가 개인 repo URL 을 받아 `origin` 을 돌리고 배포 repo 를 `dist` 로 보존한다. **섞이면 안 된다 — 배포판엔 개인 데이터가 0이어야 한다.**
- **배포는 `dist-sync` 가 한다.** `git pull` 은 쓰지 않는다. 배포판이 추적하는 파일 중 사용자가 매일 고치는 여섯(recent·open-loops·MOC·profile·CLAUDE.md·config.json)이 있어, pull 하면 충돌로 업데이트가 멈추기 때문이다. 파일을 코어·씨앗·CLAUDE.md·개인으로 가르고 개인 층은 읽지도 않는다(ADR-012). 사용자가 고친 코어는 배포판 이력의 판 해시 표로 가려 덮어쓰지 않고 합친다(ADR-030).

### 3.5 원본 형식 수용 — 원본이 원천, 정리노트 대신 색인 (2026-10-14)
PDF·docx·pptx·xlsx·hwp·html·영상 같은 **원본이 볼트의 정보원**이다. 예전 pdf-ingest 는 원본을 정제본·요지 통찰노트로 바꿔 넣었는데, 정리노트는 원본의 열화판이고(그림·표·쪽 배치가 빠진다) 원본과 따로 낡는다. 그래서 정리노트를 기본으로 만들지 않고 원본마다 **색인**을 붙인다.
- **원본** = `1_수집/<분류>/<파일>`(학교 자료는 `1_수집/배움/<과목>/`) — 내용 불변. 같은 sha256 은 하나만(사본을 들이지 않고 보고). 보고서 재료(사진·측정·코드·영상)는 1회용이라 원본 층에 들이지 않고 `0_작업` 으로 간다(ADR-028).
- **색인** = `1_수집/_색인/<원본 상대경로>.색인.md` — `3_시스템/ingest.py` 가 만든다. 위치 단위 헤딩(PDF 쪽·슬라이드·시트)마다 원본 링크(`[[원본#page=N]]`)를 달아 **찾고 원본의 그 자리로 가기 위한** 검색 표면이다(문장 품질보다 위치 정확도). 그림 쪽은 윈도우 내장 OCR(설치 0·오프라인)로 읽고, 그림 내용과 손글씨는 사용자가 단추를 누를 때만 `--vision` 으로 Claude 가 명사구 하나로 덧붙인다. 구독이 아니거나 한도에 막히면 멈춘다(ADR-016). 사람이 고치지 않는다 — 다시 만들 때 사라지고, 원본이 옮겨지면 해시로 다시 잇는다. 3_시스템 이 아니라 1_수집 아래 둔 까닭 = 3_시스템 은 옵시디언 검색·그래프에서 빠지는 폴더라서.
- **메모** = 원본 옆 같은 이름 md — 사람 전용이고 스크립트는 쓰지 않는다. **정리노트**는 사용자가 원할 때만 만들고 색인·원본 링크를 단다.
- **검색**: `search.py` 가 `1_수집/**/*.md`(색인·메모)를 함께 색인한다(청크 상한은 §12.9). 이후 질문 = 검색 → 색인의 그 쪽 → 필요하면 원본 그 쪽만 Read.
- 규칙 정본 → [[conventions#원본·색인]] · 결정 → ADR-013.

### 3.6 Brain Source — 원본을 보고 고치는 플러그인 (2026-10-22 코어 편입)
색인이 «찾기»라면 Brain Source 는 «보기·고치기»다. 외부뇌가 직접 만든 Obsidian 플러그인(Apache-2.0 · 소스는 볼트 밖 별도 저장소)이고 `.obsidian/plugins/brain-source/` 에 실려 있다.
- **보기**: PDF·docx·pptx·xlsx·hwp·csv·html·txt 를 옵시디언 탭에서 연다. 원본 아래에 같은 이름 메모 md 가 메모 칸으로 붙고, 색인·메모 md 를 열면 원본으로 가는 단추가 뜬다.
- **고치기**: 원본은 **보호(읽기 전용)** 로 열린다. 풀고 고치면 **고친 곳만 원본에 쓰고 나머지 바이트는 그대로**(xlsx·docx·pptx = XML 부분 패치 · hwp = 레코드 패치 · PDF 주석 = 증분 저장). 1_수집 «원본 불변» 은 시스템(Claude·스크립트)에 대한 규칙이고, 사람이 자기 원본을 고치는 창은 이것이다. 손글씨 판서의 낱말 상자(끌어 고르기, 11-02)는 `hwlayout.py` 가 위치를 준다.
- **보호**: `.obsidian/plugins/` 전체가 코어 게이트 경로다(2026-10-23, ADR-015). 플러그인 코드는 옵시디언 안에서 사람 권한으로 돌기 때문에, Claude 가 플러그인 파일을 쓰거나 옆에 새 플러그인을 심으려 하면 승인 창이 뜬다(§7). 읽기·실행은 막지 않는다.
- **시트·새로 만들기**: 엑셀식 `.sheet` 를 편집하고 xlsx 로 내보낸다(옛 Brain Sheet 를 대체). 탐색기 폴더 우클릭 «새 노트»에서 빈 Word·Excel·PowerPoint 와 txt·csv·html 을 만든다. Office 3종은 Office 가 만든 파일을 싣지 않고 최소 부품을 직접 쓰며, csv 는 UTF-8 BOM 이다(엑셀이 한글을 CP949 로 잘못 읽지 않게).
- **배포**: 번들 폴더는 27MB(`du` 27,604KB)이고 `THIRD_PARTY_NOTICES.md` 에 패키지 127개를 싣는다(표 행 수로 센 값, 카피레프트만 걸린 패키지가 묶이면 빌드가 멈춘다). 배포판에서는 `.gitattributes` 로 폴더 전체를 binary 로 둔다([[incident-2026-10-13-배포판-autocrlf-번들-줄바꿈변환]]). 업데이트는 `dist-sync` 의 `--apply-plugins` 다.

### 3.7 바탕 플러그인과 대화창
- **왜**: 2026-10-29 제작자가 «웬만하면 자체제작»을 정했고, 10-30 에는 대화창만으로는 부족하다고 판단했다. 그래서 대화창과 함께 볼트의 일(주제·받은함·행위·장부)을 한 화면에 모으는 바탕 플러그인을 만들었다.
- **무엇**: `brain-base`(소스는 볼트 밖 별도 저장소)는 오른쪽 곁창에서 설치된 `claude` 를 머리 없는 모드로 띄운다. 그래서 CLAUDE.md·훅·스킬·가드·기억이 데스크톱 앱과 같게 돌고, 분류기·훅이 «물어봄»이면 대화창에 승인 카드가 뜬다. 구독 로그인 그대로이고 API 키 환경 변수는 띄울 때 뺀다. 자체 탐색기(파일·주제), 주제 패널, 홈, 행위 문, 장부 보기도 같은 플러그인에 있다.
- **묻기 모드와 일 모드**: 새 대화는 묻기 모드다. 읽기 도구만 쓰고 첫 입력이 4,231토큰이다(제작자 볼트 실측, Opus low). 묻기 모드의 지침은 `3_시스템/vault-chat/상시.md`·`필요시.md` 다. 고치는 일은 머리 단추로 일 모드에 올려 같은 대화를 볼트 규약 전체로 이어 간다. 모델은 별칭으로만 부르고 실행 파일은 `claude_bin.py` 가 설치된 가장 새 판을 고른다.
- **화면 도구**(0.24, 11-03): 대화창의 Claude 가 탭을 열고 바꾸고 스크롤하고 나누고 닫는다. 파일 내용은 건드리지 않아 승인이 없다. 도구 하나·명령 글 한 줄로 만들어 첫 입력이 4,231에서 4,512토큰으로 281만 늘었다(두 번 잰 평균). 도구를 8개로 나누면 +896이다.
- **상자 고르기**(0.26~0.27, 11-03): 글자로 못 고르는 그림·수식을 입력 상자 단추 → 끌기로 골라 그림으로 붙인다. 파일을 다시 읽는 대신 보이는 화면을 뜨므로(옵시디언 창 캡처) PDF·docx·노트 어디든 같다. 토큰은 가로×세로÷750(573×171 약 +150 · 1206×1023 약 +1,640, 실측)이고 API 가 줄이는 한도(긴 변 1568 · 115만 화소) 안으로 줄여 보낸다. Alt+끌기 안은 편집기의 여러 커서와 겹쳐(실측 선택 2개) 단추 안을 골랐다. 글만 있으면 글자로 보내는데(0.27), 글자 토큰이 영어 0.33·한글 1.07/자(실측)라 작고 빽빽한 글은 그림이 더 싸다. 그래서 «글만 있다»(수식 기호·첨자·글자 밖 잉크 3% 초과가 없다)와 «글자가 더 싸다»가 둘 다일 때만 글자로 보내고, 수식·그림을 글자로 잘못 보내면 답이 틀리니 의심되면 그림으로 둔다. 글자층이 없으면 윈도 OCR 을 돌려 믿을 만할 때만 바꾼다.
- **상태**: 지금 판은 `.obsidian/plugins/brain-base/manifest.json` 에 있다. 화면 도구·튜토리얼·상자 고르기는 격리 시험만 통과했고 실제 볼트 화면에서 사람이 해 본 것은 아직 없다.

### 3.8 행위 층 — brain.py·fileops·장부·셸 가드
- **왜**: 삭제·이동·이름 바꾸기를 그때그때 지은 `rm`·`mv` 로 하면 흔적이 없고, 지운 것이 사라지고, 이름을 바꾸면 링크가 깨진다. 규칙 문구가 있어도 즉흥 행위가 10-14·10-29 에 재발했다. 막는 구조가 있어야 지켜진다(ADR-018).
- **fileops.py** 가 볼트 안 지우기·옮기기·이름 바꾸기·들이기·덮어쓰기를 하나로 맡는다. 행위는 `--why` 와 함께 장부 `3_시스템/ledger/ops.jsonl` 에 남고, 지운 것은 `.trash/<날짜>/` 에 30일 있다(영구 비우기 `purge` 는 사람만). 링크·캔버스·짝 메모가 따라 고쳐지고, 코드·설정·코어 문서의 옛 경로는 고치지 않고 알린다. 옵시디언이 켜져 있으면 이동은 공식 CLI `move` 에 맡겨 옵시디언이 링크를 고치게 한다(ADR-019).
- **brain.py** 는 외부뇌가 할 수 있는 일을 이름 붙은 행위로 부르는 실행기다. 행위는 `actions.json` 에 33개 있고 모듈이 더 선언한다. Claude 셸·터미널·예약 작업·옵시디언이 같은 행위를 같은 꼴로 부르고 `3_시스템/ledger/actions.jsonl` 에 남는다. 밖으로 보내거나 Claude 사용량이 드는 행위는 `--yes` 없이 돌지 않는다. `brain.py doctor` 가 건강 한 줄씩을 낸다.
- **셸 가드**: PreToolUse 게이트의 한 절(`core-gate.ps1` 2.5절 + `ops-guard.ps1`)이 셸의 지우기·옮기기 동사가 볼트 자리에 닿으면 막고 fileops 를 안내한다. 옵시디언 CLI 의 `eval` 은 막고, `fileops update|migrate --apply` 는 한 번 묻는다. 한계: 대본 파일 속 직접 삭제는 명령 글자에 안 보여 가드가 못 보며, CLAUDE.md §2 규칙이 덮는다.

### 3.9 역할 · 주제 등록부 · 구조 이전
- **왜**: 폴더를 옮길 때마다 코드·기억·스킬 속 경로가 따라오지 않았다. R6.2(10-30)가 코드에 박힌 경로 77곳을 예외 밖 0으로 만들었다. 제작자 볼트의 점검 대본 `_eval/hardpaths.py`(배포판에 없음)는 6파일 106곳을 예외 밖으로 센다(11-03 실측). 코드는 3곳이고 나머지는 시험 고정물과 이전 파일이다.
- **역할**: `3_시스템/roles.json`(역할 25개 · 묶음 4 · 노트 속성 표)이 정본이고 `roles.py` 가 읽는다. 지식 노트 자리는 묶음(`note_areas`·`moc_notes`·`knowledge_notes`·`content`)으로 묻는다. 폴더를 옮기면 fileops 로 옮기고 이 파일만 고친다.
- **주제 등록부** `2_지식/주제.md`: 과목·프로젝트의 정식 이름과 별칭이다. 주제 카드(`topic.py`)·받은함 분류·탐색기가 같은 이름을 쓴다(ADR-022). 파일마다 번호를 붙이는 식별번호 등록부는 만들지 않았다 — 이름·장부·역할이 같은 일을 하고 비용은 더 컸다(ADR-021).
- **구조 이전**: `restructure.py`(분류표 → 계획 → fileops 적용 → 점검)와 `3_시스템/migrations/` 가 R9(10-31)에 옛 체계(`notes`·`sessions`·`decisions`)를 배움·일·생활·분야와 기록으로 옮겼다. 사본 시험 → 백업 → 적용 순서였고 이전 단위로 되돌릴 수 있다(ADR-023). 사용자 볼트의 같은 이전은 업데이터가 이전 파일로 한다.

### 3.10 받은함 · 받는 문 · 따라가기 · 보존 일정표
- **받은함은 정거장이다.** `1_수집/_inbox` 는 쌓아 두는 곳이 아니다. `inbox.py` 가 항목마다 같은 내용·주제·하위 칸을 보고 제안하고 `--apply` 는 확신 높은 것만 옮겨 색인한다. Claude 가 건드린 항목이 턴 끝까지 남아 있으면 Stop 훅이 항목당 세션 한 번 되먹인다. 근거는 실측 2건이다(11-02 보고서 재료를 받은함 경로 그대로 읽고 남김, ADR-028).
- **받는 문**: 볼트 밖 파일을 복사가 아니라 옮겨서 받은함으로 들인다 — 탐색기 즐겨찾기·우클릭 첫 메뉴·`Ctrl+Alt+B`. 엔진은 `door.py` 하나이고 정리는 볼트가 켜져 있을 때만 한다(볼트 밖 후보는 `outside.py` 가 목록으로 보여 주고 고른 것만 받은함으로 옮긴다). 우클릭·단축키·즐겨찾기 등록에 쓰는 작은 실행 파일은 볼트 밖 빌더에서 만들어 배포판에 없고, 배포판에서는 행위 `door.put` 과 받은함 폴더에 직접 넣기로 같은 일을 한다. 11-03 제작이며 실제 탐색기 메뉴 클릭과 알림 단추 클릭은 미측정이다(ADR-031).
- **따라가기**: 사용자가 옵시디언 밖(윈도 탐색기)에서 옮기거나 지우는 일도 드물지 않다. `follow.py` 가 경로·크기·시각·파일번호·원본 sha256 의 «사진»을 비교해 옮김과 지움을 알아채고 장부·링크·색인·짝 메모를 맞춘다. 세션 시작 훅과 옵시디언을 켤 때 돈다(ADR-029).
- **보존 일정표** `2_지식/보존.md`: 칸마다(강의자료·웹 공지·작업 산출물·휴지통 …) 얼마나 두고 언제 지울지를 JSON 블록으로 정한다. 대본(`cleanup.py`·`work.py`)은 후보를 만들 뿐 지우지 않고, 승인된 것만 fileops 가 휴지통으로 보낸다. 자동으로 가는 것은 웹 수집 쪽 둘(웹 공지 마감 + 30일 · 웹 대기 칸 90일)뿐이다.

### 3.11 일정과 수집
- **일정**: `2_지식/일정/*.md` 의 열린 줄(`- [ ]`)이 원천이다. LMS 마감은 `schedule.py build` 가 만들고 손으로 적는 일정은 `내-일정.md` 에 둔다. Claude(세션 시작 7일 주입)·캘린더 플러그인·생성기가 같은 문법을 읽어야 폰 옵시디언 기본 편집으로도 되기 때문이다. 대가: 문법이 `schedule.py` 와 `session-start.ps1` 두 곳에 있어 바꿀 때 둘 다 고친다.
- **수집**: LMS(크롬 확장 `3_시스템/lms/` + `lms-auto.py`)와 웹 공지(`web-collect.py` + 조리법 `3_시스템/collect/*.json`)는 원본을 가공 없이 받아 `1_수집` 에 들이고 일정을 만든다. 철칙은 받아들이기만 무승인이고, 로그인은 사람이 하며, 밖으로 내보내기는 승인이다. 출처 전용 코드는 엔진에 0줄이고 차이는 조리법 데이터로 둔다. 두 수집기는 개인 기능이라 배포판 `3_시스템/` 에 없다(잰 값).

### 3.12 금고와 캘린더

## 4. 검색 — 측정으로 확정한 하이브리드

검색은 목적 ①(관련만 로드)·②(맥락 복원)의 핵심 엔진이다. **어떤 검색이 필요한지는 추측이 아니라 측정으로 정했다.**

### 4.1 측정 여정 (측정 전 아키텍처 금지)
1. **베이스라인**: 벡터 없이 Claude의 에이전틱 grep(MOC→grep→선별 Read)로 골든셋 hit@8 측정.
2. **함정 발견**: literal 골든셋(고유명사 공유)만으로는 grep이 100%. 그러나 이건 grep 홈그라운드만 잰 순환 측정이었다. **패러프레이즈 골든셋**(고유명사·헤딩어 제거한 의미 질의)을 추가하니 실사용에 가까운 그림이 나왔다.
3. **3자 측정 결과**:
   - literal 30문: lexical 93.3% / vector 83.3% / **hybrid 90.0%**
   - 패러프레이즈 12문: lexical 50% / vector 50% / **hybrid 58.3%** (각 arm이 서로 다른 6문을 맞춤 → RRF 합집합 7문 = 상보성 실증)
4. **결론 = 하이브리드 채택.** grep 단독·벡터 단독 모두 기각. 실사용 질의는 두루뭉술 → 벡터 필요, 그러나 grep 정밀도도 보존해야 한다.

### 4.2 as-built 구조 (`3_시스템/search.py`)
- **하이브리드 = lexical(grep) + vector RRF 융합** (Reciprocal Rank Fusion, k=60).
- **임베딩 모델 = `intfloat/multilingual-e5-small`** (384차원, CPU, ~470MB). 측정으로 채택. e5 규약대로 질의는 `query:`, 문서는 `passage:` 프리픽스.
- **하드코딩 금지**: 모델은 `config.json`의 `embed_model`에서 읽음. 티어 전환 = config 한 줄 + `--rebuild`(차원이 달라 재빌드 필수). 코드는 불변.
- **on-demand**: 데몬·포트·와처 없음. 인덱스는 `_index/`에 JSON 영속, hash 증분 재인덱싱.
- **청킹**: 헤딩 단위, max-pool. recency 가중은 제거(측정상 순노이즈), RRF가 융합.

> **왜 e5-small인가 (bge-m3 아니라)?** 설계 초기엔 GPU 티어(bge-m3, 1024차원)를 상정했다. 그러나 측정 결과 e5-small로 골든셋 목표를 통과했고, "측정 > 티어표" 원칙에 따라 최저가 구성을 채택했다. bge-m3는 폐기가 아니라 **강GPU 배포 사용자의 정규 상위 티어**로 [[#10. DEFERRED 창고|§10 DEFERRED]]에 보존.

## 5. 의미 그래프 (B1) — 플러그인 0

검색용으로 이미 계산한 벡터를 재활용해(추가 임베딩 0), 노트 사이 의미 이웃을 **위키링크로** 심는다. 그러면 **Obsidian 네이티브 그래프 뷰가 곧 의미 그래프**가 된다. 별도 시각화 플러그인 불요.

### 5.1 이방성 처리 — 평균 센터링 후 절대 임계 (2026-07-19 개정)
e5-small 임베딩은 **이방성**(anisotropy)이 있다. **raw** 벡터의 전 노트쌍 max-chunk 코사인이 0.80~1.00의 좁은 원뿔에 압착된다(최근접 이웃조차 0.92+). 그래서 raw 위의 절대 스칼라 임계는 원리적으로 작동하지 못한다 — 어떤 임계든 완전 그래프(헤어볼)이거나 과편화다.
- 실측(raw): 절대 thr=0.88 → 661엣지 헤어볼(precision 8.6%). 상호 kNN → 고립 양산.
- **1차 채택(빌드)** = per-node top-k(k=3) 상대 floor. 그러나 상대 floor는 **절벽형 노트만** 정화 — 진짜 이웃 없는 **평지형**(예: 시험공지·계획류)은 top-k가 노이즈로 강제충원(기말공지→영단어 등).
- **개정 채택 = 평균 센터링 후 절대 임계.** 전 청크벡터 글로벌 μ를 빼고 재정규화(All-but-the-Top 1단계)하면 원뿔이 펴져 진짜 이웃이 노이즈 위로 분리(이집트: 절벽 0.06→0.41). **raw서 불가했던 절대임계가 센터 후 유효.** 규칙 = top1 무조건 유지(고립방지 레일) + 2~k위는 `centered-cos ≥ neigh_tau(0.33)`. **neighbors 전용**(검색 vector_scores는 raw — 무영향).
- 실측(손라벨 골든 GOOD 14·SPUR 10): raw-floor 0.05 = GOOD 14/14·SPUR 9/10(평지형 1 잔존), **센터 0.33 = GOOD 14/14·SPUR 10/10·고립 0.** 수동 위키링크 recall 51→48/124(−3, 대부분 허브·본문 [[]]는 불변). 전문 = results-b1-neighbors.md. 소표본(<2노트)이면 센터링 스킵.

### 5.2 관리 블록 (writer)
`search.py --link-write`가 Claude 소유 노트에 접이식 콜아웃 블록을 심는다(reading·편집 양쪽에서 마커 안 보임). **SessionEnd 훅이 매 세션 자동 실행**(reindex 후 link-write)하므로 링크는 항상 최신 — 수동 호출도 가능.
```
> [!info]- 관련 노트 %%sl%%
> [[A]] · [[B]] · [[C]]
```
- **멱등**: 마커 `%%sl%%`로 기존 블록만 교체. 수동 링크·본문 불변(안전).
- **쓰기 권한**: Claude 소유(지식 노트 자리 전부·모듈 산출물·기록·`_ref`)만 자동 갱신. 1_수집 사용자 저작물은 안 씀.
- **피드백 루프 가드**: 관리 블록은 파생 데이터 → `strip_managed()`가 색인 유입 차단. 안 막으면 "노트가 이웃 이름 포함 → 재색인 → 그 이웃과 유사도↑" 자기강화. reindex 후 이웃 불변 실증.
- 파라미터(`neigh_k`·`neigh_dup`·`neigh_tau`)는 `config.json`의 `graph` 블록에서 읽음(setup-interview 슬롯).

> **정적 2D 의미지도는 채택하지 않았다.** t-SNE 산점도를 시험했으나 Obsidian 네이티브 그래프뷰(줌·필터·실시간·양방향)가 명백히 우월했다 — 의미그래프의 목적은 B1 위키링크 → 네이티브 그래프로 이미 완결되므로 별도 지도는 불요.

## 6. 네이티브 메모리 통제 — 옵션 R

Claude Code의 네이티브 자동 메모리(Claude가 스스로 쌓는 노트, `~/.claude/.../memory/`)는 외부뇌와 정면으로 겹친다. 둘 다 켜면 토큰 이중 로드 + 진실 원본 2개(모순).

**해법 = 옵션 R(리다이렉트).** `settings.local.json`에 한 줄:
```json
{ "autoMemoryDirectory": "C:\\Claude_Brain\\3_시스템\\_claude-memory" }
```
- 네이티브 자동학습을 **공짜로 유지**하되, 저장 위치를 **볼트 안**으로 돌린다 → 인간 가독·git·우리 검색 인덱스에 포함. 이중 시스템 소멸.
- 자동 로드 예산 = `MEMORY.md` 첫 200줄/25KB만. 토픽 파일은 on-demand.
- **배포 시 제외**: `_claude-memory`는 개인 레이어(빌더 사실)라 `.gitignore`로 배포 repo에서 뺀다. 로컬(리다이렉트 위치)엔 유지. 메모리는 재생성 가능하므로 git 백업 포기는 비치명.
- 리다이렉트 실패 시 폴백: `autoMemoryEnabled: false`(볼트 스킬이 전담).
- **배포 온보딩**: `settings.local.json`은 gitignore(머신 절대경로)라 배포판에 없다 → **setup-interview 슬롯0(설치 직후 선행)이 신규 사용자 머신에 이 리다이렉트를 설정**한다. 안 하면 네이티브 메모리가 볼트 밖 기본 위치에 남는다.

| idle-save.py | Stop(asyncRewake) | 무입력 50분 또는 5시간 사용률 80% 에 세이브포인트를 쓰게 깨움 | 유휴 65분 뒤 첫 요청의 86%(51/59)가 캐시를 통째 다시 썼다(09-24 실측). 알려진 결함: `/clear` 전 세션의 감시가 새 세션을 깨운다(11-03 재현) |
| session-end.ps1 | SessionEnd | 커밋 백업 + push + B1 링크 갱신(디태치) | 무거운 일을 훅 안에서 하면 타임아웃에 커밋 전에 죽었다(07-19) |
| statusline.py | statusLine | 사용률·캐시 만료를 `_index/usage/` 에 넘김 | idle-save 의 입력. 데스크톱 앱에서는 안 도는 것으로 보인다(10-03 실측) |

구현상 치명 실측 두 가지가 배포 안정성을 좌우한다:
- **pre-commit 위치**: `.git/hooks/`는 git 추적이 안 돼 clone 시 사라진다 → 추적 위치 `3_시스템/hooks/pre-commit` + 설치 시 `git config core.hooksPath 3_시스템/hooks`(README 절차).
- **PowerShell 인코딩 2층**: `.ps1`은 UTF-8 **BOM** 저장(PS 5.1이 cp949로 오독하는 것 방지) + 데이터 읽기는 `Get-Content -Encoding UTF8`. 검증은 반드시 `powershell`(5.1)로 — pwsh 7은 UTF-8 기본이라 버그를 못 잡는다. 파이썬 훅은 stdout 을 UTF-8 로 `reconfigure` 한다(로캘이 cp949 면 한글 JSON 이 깨져 훅이 통째로 무효).

지능 작업(세션 요약·recent 갱신)은 훅이 아니라 session-record 스킬이 한다. 훅은 결정론적 추출·저장·커밋·**검증(Stop)** 과 알림만 한다.

## 8. 스킬 7개와 모듈 2개

`.claude/skills/<이름>/SKILL.md` 가 스킬이고, 지금 목록의 진실 원본은 `3_시스템/_index/modules.json`(module-forge 의 `check` 가 만든다)이다. 스킬은 사용자 말에 모델이 부르는 절차이고, 기계로 되는 일은 대본(`record.py`·`weekly.py`)에 넘겼다.

**스킬 7**
- **setup-interview** — 신규 설치 개인최적화. 슬롯 0~10(11개)로 §0·profile·open-loops·모델 config 를 대화로 채운다. 슬롯 0(옵션 R 메모리 리다이렉트)을 설치 직후 먼저 건다. 코어 규약은 건드리지 않는다.
- **session-record** — 세션 기록을 확정한다. 먼저 수준을 판정한다(A 세션노트 · B recent 한 줄 · C 생략). recent·open-loops 는 즉석 코드가 아니라 `record.py` 로 고친다. 2026-08-16 에 옛 이름 `session-close` 에서 바꿨다(ADR-010).
- **pdf-ingest** — 원본을 `1_수집/<분류>/` 에 두고 `ingest.py` 로 색인한 뒤 검색 → 색인의 그 쪽 → 원본 그 쪽으로 읽는다(§3.5). 목적 ① 최대 지렛대(130k 토큰 → 수백)는 그대로다.
- **weekly-review** — 주간 점검. 측정은 `weekly.py --save` 한 번이고 스킬은 리포트를 읽고 판단만 한다.
- **deep-loop** — 한 논점을 N회 반복해 깊게 판다(2026-08-03). 조사 루프(자료 → 파생질문 → 재조사)와 실행 루프(측정 → 판정 → 수리)로 나뉘고 볼트에 저장하지 않는다(ADR-011).
- **canvas** — `.canvas` 제작. 4조건(항목≥5·축≥2·실제 노트·사람 배치 여지)을 통과할 때만 캔버스이고, 기계가 집합·엣지·크기·그룹을, 사람이 `x`/`y` 를 맡는다.
- **defuddle** — 웹 → 클린 마크다운. kepano/obsidian-skills(MIT) 차용(`.claude/skills/VENDOR.txt`).

**모듈 2** (`.claude/skills/<모듈명>/`, 네이티브 플러그인 형식) — 스킬과 달리 on/off 단위가 모듈 전체다. 켜고 끄기는 옵시디언 홈에서 사람이 누를 때만 한다(ADR-022). 불가침 3 = 코어 무수정·예약훅(Stop·SessionStart·SessionEnd) 금지·`1_수집/**` 하드블록. 산출물은 `2_지식/modules/<모듈명>/` 에 둔다.
- **dist-sync** (0.2.0) — `publish`(볼트 → 배포판)와 `update`(배포판 → 사용자 볼트). §3.4.
- **module-forge** (0.2.0) — `check`: basename 중복·`1_수집` 침범·예약훅·touches 겹침·deps 순환·surfaces 드리프트를 정적으로 잡는다.

> **11-02 에 쓸모없는 스킬 7개를 거뒀다.** 옛 스킬은 `search`·`inbox-sort`·module-forge 의 라우터와 `new` 등이다(ADR-026). 기준은 «사용 횟수 0»이 아니라 «그 일이 있었는가»였다. 스킬 `search` 는 호출 0회였지만 `search.py` 는 137회 불렸다(기록값) — 일은 있었고 스킬이 필요 없었다. 받은함 정리는 행위 `inbox.sort` 가 한다. obsidian-markdown 은 2026-07-28 에 거뒀다 — 발동하면 일반 Obsidian 스키마(`date`·`cssclasses`)를 가르쳐 볼트 스키마와 충돌했고, 실공백이던 블록참조는 `conventions.md` 의 «링크와 기록» 규약으로 흡수했다.

**출력 스타일** `lean`(`.claude/output-styles/lean.md`)은 도구 나레이션·장식·패딩을 걷되 **반박·불확실성 서술은 명시적 예외**다. 배포판 기본은 꺼짐이고 `settings.local.json` 의 `outputStyle` 로 켠다. 용도가 토큰 절감에서 출력 품질로 바뀐 경위는 ADR-008, 정보전달 규칙은 ADR-009에 있다.

## 9. 설계 원칙

이 시스템을 관통하는 규율. 여기서 벗어나는 변경은 재검토 대상이다.

- **사용자 > 제작자.** 이건 진짜 배포 제품이다("사용자=제작자"는 폐기된 가정). 그래서 §0·profile·모델은 하드코딩이 아니라 **소프트코딩**(인터뷰/config 주입). 제작자도 첫 사용자로서 배포 경로(인터뷰)를 밟는다.
- **측정 우선 — 측정 전 아키텍처 금지.** 설계 3라운드의 주 오류가 이것이었다. 벡터검색·임베딩 모델·의미그래프 임계 전부 골든셋/실측이 결정했다.
- **삭제는 지시가 있을 때만, 되돌릴 수 있게.** 옛 원칙은 «삭제 없음 — `status: archived` 마킹 + 검색 페널티»였다. 그런데 지움은 실제로 있었다(git 이력의 파일 삭제 139건, ADR-018 실측). 그래서 막는 대신 안전하게 했다. 노트는 사용자 지시가 있을 때만 fileops 로 지우고, 지운 것은 장부에 남고 30일 휴지통에서 되살릴 수 있다. 끝났지만 남길 것은 여전히 `status: archived`(검색 ×0.5)다. 원래의 자동 만료 파이프라인은 그 자체 결함을 낳아 폐기했고, 후보 목록 + 휴지통 꼴로만 일부 돌아왔다(§10).
- **DEFERRED 창고.** *"잘려나간 설계는 사라지지 않는다 — 문서로 남고, 필요가 실증되면 그때 꺼낸다."* ([[#10. DEFERRED 창고|§10]])
- **요약 ≠ 원문 대체.** 요약은 포인터+gist만. 원문은 보존.
- **강제는 결정론적 측정으로.** 1인 시스템에서 관료적 거버넌스 절차는 자연 작동하지 않음이 실증됐다(과대 마감 3회). 옛 서술은 «골든셋 = 유일 거버넌스»였지만 지금은 측정이 여럿이다: 골든셋 hit@8(합격선 ≥ 80%), 코어 게이트 회귀 111케이스, 어긋남 검사 `drift.py`, 주간 `weekly.py`. 골든셋의 지금 값은 §12.11.
- **_ref 생존 인프라.** 버그·이상 시 `3_시스템/_ref/`의 과거 진단(incident)을 **먼저 검색** → 해결 후 incident로 기록. 쓰기만 있고 읽기 경로가 없으면 죽은 폴더가 된다는 구 시스템 교훈 때문이다. **범위 = 외부뇌 시스템 자체의 진단 전용.** **프로젝트의 incident은 그 프로젝트 폴더**(예 `2_지식/일/<프로젝트>/_ref/`)에 둔다.
- **틀린 것은 거절한다.** 사용자 말·자료·도구 결과·이전 결론 모두 실행 전에 사실·근거·목표 부합을 먼저 판단하고, 틀렸으면 «아니다»와 까닭, 맞는 대안을 말한다(제작자 볼트의 `CLAUDE.md` §0).
- **기본은 자체 제작, 외부는 예외.** 자체 제작이 비합리적일 때만 외부를 쓰고 까닭을 밝혀 묻는다(2026-10-29).
- **자리는 역할 이름으로 묻고, 행위는 한 실행자가 장부에 남긴다**(§3.8·§3.9). **받은함은 정거장이다** — 확인했으면 그 자리에서 비운다(§3.10). **상시로 읽히는 글은 상한과 어긋남 검사로 지킨다**(§3.13).

## 11. 프론트매터 스키마

노트의 기계 스펙. 규약 글은 `3_시스템/conventions.md`, 표의 정본은 `3_시스템/roles.json` 의 `props` 다. 옵시디언의 새 노트 표(brain-base)와 `props-sync.py` 가 같은 표를 읽는다(ADR-027). 값을 모르면 키만 쓰고 값은 비운다.
- **2_지식 표**: `title` · `created` · `updated` · `tags` · `주제` · `aliases` · `links` · `status` · `source`. **0_작업 표**: `title` · `created` · `updated` · `tags` · `주제` · `마감` · `단계`(수집·초안·제출·끝) · `의도` · `aliases` · `source`.
- 필드명은 `created`다 — `date`가 아니다. 일반 Obsidian 스키마의 `date`·`cssclasses` 와 충돌하며, 이것이 §8에서 obsidian-markdown 스킬을 거둔 사유 중 하나다.
- **`created` 면제 = 상시 갱신 핵심 파일**(`MOC`·`recent`·`open-loops`·`profile`·설계노트·사용자설명서). 생성일이 뜻을 갖지 않고 개정 이력은 git이 담당한다.
- **`updated` 는 손으로 고치지 않는다.** 커밋 때 `props-sync.py` 가 파일 수정 날짜로 적는다. 손으로 적은 날짜는 믿을 수 없었다(ADR-020).
- **`links` 는 따옴표 배열**이다(`["[[노트]]"]`). 따옴표가 없으면 YAML 오류이고 pre-commit·Stop 훅이 막는다.
- `status`: active · archived (기본 active) — 검색이 읽는 필드는 이것 하나다(archived ×0.5). `source`: user · claude · 수집(옛 값은 고치지 않고 읽을 때 새 값으로 본다).
- 표 뒤에 필요할 때만 더한다: `type`(semantic · episodic · procedural · decision · moc · incident, 선택이고 없으면 semantic) · `confidence`(verified · hypothesized) · `sensitive: true`(push 제외) · `author`(수집물 게시자). **6종 밖의 `type` 값을 만들지 않는다** — 2026-08-17 전수에서 스키마 밖 10건이 모두 기존 6종으로 표현 가능했다(판단을 미룬 것이었다).
- 옛 `importance` 는 2026-10-30 에 폐지했다. 코드가 읽는 곳이 없었다.

## 12. 구현 명세 (재구축용)

> **이 절의 목적.** 볼트에 이상이 생겨 고치거나 기능을 늘릴 때, 각 구성요소가 «왜 그렇게 생겼고 어디서 깨지는가»를 찾는 절이다. 파일 내용을 옮겨 적지 않는다 — 옮겨 적으면 다시 낡는다(이 절의 옛 판이 그랬다). 내용은 아래에 적은 진실 원본 경로의 실물에 있고, 여기에는 까닭과 함정만 남긴다. 스펙과 코드가 어긋나면 **코드가 진실 원본**이다.

### 12.1 재구축 길 — 배포판 clone + setup-interview
설계에서 처음부터 짓지 않는다. 지금 시스템을 다시 세우는 길은 배포판이고, 설치 절차의 진실 원본은 배포판 `README.md` 다.
1. 배포판 repo 를 태그로 clone 하고 곧바로 `git switch -c main` 을 한다. 태그 clone 은 detached HEAD 라서 이 단계가 없으면 세션 커밋이 고아가 되고 push 가 영구 실패한다.
2. `git config core.hooksPath 3_시스템/hooks` 를 한다. 안 하면 pre-commit(secret-scan)이 돌지 않는다.
3. 파이썬 의존성을 깔고 `py -3 3_시스템/search.py --rebuild` 로 첫 인덱스를 만든다. 모델(~470MB) 내려받기와 임베딩이 훅 타임아웃을 넘길 수 있어 수동이다.
4. 옵시디언에서 폴더를 열고 «제한 모드 끄기»로 동봉 플러그인을 켠다. `claude` 를 띄워 트러스트를 수락하면 첫 세션에 «개인화 미완료»가 뜨고, `setup-interview` 가 §0·profile·모델 config·개인 repo 연결을 채운다.

이미 설치한 볼트는 README 의 «업데이트» 절차(`dist-sync:update`)로 올린다.

### 12.2 폴더 트리
정본은 실물과 `3_시스템/roles.json` 이다(`py -3 3_시스템/roles.py list`). 빈 폴더는 `.gitkeep` 으로 추적하고 영역 폴더는 처음 쓰일 때 만든다. 함정: 코드에 폴더 이름을 글자로 박으면 다음 이전에서 조용히 어긋난다. `drift.py` 가 글 속 옛 이름을 잰다.

### 12.3 .gitignore · .gitattributes
정본은 볼트 루트의 두 파일이다. 볼트와 배포판의 `.gitignore` 는 다르다. 배포판은 자체 플러그인 3개의 본체를 추적하고 볼트는 `.obsidian/plugins/` 전체를 제외한다. 함정:
- 원본(비 md)·영상·금고·휴지통·`_index` 를 빼는 까닭은 저장소가 원본 크기만큼 영구히 커지지 않게 하려는 것이다. 그래서 원본 백업은 git 밖의 일이다.
- 번들 플러그인은 `.gitattributes` 로 binary 고정한다. 받는 쪽 autocrlf 가 번들 줄바꿈을 바꾼 사고가 있었다. md·py·ps1 은 LF 고정이다. B1 writer 가 노트를 LF 로 다시 쓸 때 CRLF 이력이면 줄 전체가 바뀐다([[incident-2026-07-04-writer-crlf-eol-churn]]).

### 12.4 CLAUDE.md
정본은 `CLAUDE.md` 실물이다(구조는 §3.3). 함정:
- 규칙을 더하면 하나를 뺀다(상한 200줄). 기본 로드가 다시 비대해지는 것이 뿌리 ② 의 재발이다.
- §0 의 `{{슬롯}}` 이 남아 있으면 SessionStart 훅이 «개인화 미완료»를 띄우고 자동 push 를 막는다. 개인화 전에는 `origin` 이 공개 배포 repo 일 수 있다.
- 낡은 사실은 짧은 문체로도 답을 틀리게 한다. 고칠 때는 문체보다 사실·모순을 먼저 본다(ADR-025). 코어 파일이라 고칠 때 게이트 승인이 뜬다(§7).

### 12.5 훅 등록 (.claude/settings.json)
정본은 `.claude/settings.json` 이다(이벤트 7개의 명령 10개 + statusLine). 경로는 `$CLAUDE_PROJECT_DIR` 로 쓰고 머신 절대경로는 넣지 않는다. 머신별 값은 `settings.local.json`(gitignore)에 둔다: `autoMemoryDirectory`·`outputStyle`·`enabledPlugins`·permissions. 함정:
- **Stop 의 항목은 별도 그룹으로 둔다.** 같은 그룹이면 stdout 이 섞여 `stop-check` 의 `{"decision":"block"}` 파싱이 깨진다. 스텁 갱신을 `stop-check` 안에서 `Start-Process` 로 디태치하면 훅 왕복이 810ms → 1,379ms 로 늘었다(프로세스 생성 비용, [[incident-2026-08-08-StartProcess-디태치-569ms]]).
- **`permissions.ask` 게이트는 두지 않는다**(2026-08-17 철수). `ask` 규칙은 훅이 `allow` 를 내도 프롬프트를 띄워(공식 문서·실환경 재현) 통과 토큰이 작동하지 않는다. 게이트를 훅 단일층으로 모았고, 훅 사망은 `GATE-BROKEN` 로그와 weekly 로 잡는다.
- `permissions` 를 쓸 때의 문법 함정 셋: ① `Write(path)` 경로 규칙은 무시된다 — `Edit(path)` 만 모든 편집 도구를 커버한다. ② `/path` 는 설정 소스 기준 앵커라 유저 전역 설정에 두면 볼트가 전혀 보호되지 않는다(2026-07-30 실측 사고). ③ `ask` > `allow` 라 `--allowedTools` 로 열어도 막힌다.

### 12.6 훅 스크립트 — 까닭과 함정 (결정론층, LLM 호출 없음)
정본은 `3_시스템/hooks/` 의 파일과 `session-stub.py`·`mdtable.py` 다(훅 표와 인코딩 함정은 §7). 다시 지을 때 틀리기 쉬운 곳만 적는다.
- **pre-commit**: 파일 목록을 `git -c core.quotepath=false` 로 받는다. 안 그러면 한글 경로가 8진수로 인용돼 `[ -f ]` 가 실패하고 볼트 전체 검사가 조용히 건너뛰어진다. secret 패턴(`sk-`·`ghp_`·`AKIA`·PEM)은 단어경계와 16자 이상을 건다(CSS 클래스 `task-` 가 걸린 적이 있다, [[incident-2026-07-03-스펙-실측-괴리]]). sensitive 검사는 `ACMR` 로 이름 바꾸기를 포함한다 — 이름만 바꾼 민감 노트가 검사를 건너뛰던 구멍이 있었다. 2_지식 의 frontmatter 위반은 차단이고 1_수집 은 경고다. MOC 등재는 여기서 안 본다 — 커밋이 좌초하므로 Stop 훅 몫이다.
- **stop-check.ps1**: 위반이면 stdout 에 `{"decision":"block","reason":…}` + exit 0 을 낸다(공식 계약). `stop_hook_active` 는 보장되지 않아 무한루프 차단은 파일 서킷브레이커(`_index/.stopcheck-guard`)가 맡는다. 같은 위반을 2회 막은 뒤 풀고 `hooks.log` 에 남긴다 — 조용히 넘기지 않는다([[2026-07-11-규약단계-침묵생략]]). 대상은 `moc_notes` 묶음을 재귀로 훑되 `_` 로 시작하는 하위 폴더는 뺀다. 검사 항목은 프론트매터 · MOC 등재 · links 따옴표 · 파일명 전역 고유(2_지식·`_ref` 에서 `[[name]]` 모호 방지) · 블록수식 연속(`$$…$$` 가 빈 줄 없이 이어지면 수식이 날것으로 노출)이다. 위반 0이면 그 자리에서 커밋한다 — 종료가 PC 셧다운이면 SessionEnd 가 죽기 때문이다([[incident-2026-07-19-SessionEnd-커밋정지]]). Stop 의 stdout 은 block JSON 만 허용하므로 git 출력을 모두 억제한다. 10분 넘은 빈 `index.lock` 은 도는 git 이 없을 때 옮겨 격리한다(죽은 잠금으로 자동 커밋이 며칠 멈춘 일 3회, [[incident-2026-08-02-git-index-lock-62시간-자동커밋사망]]).
- **core-gate.ps1 + core-gate-decide.ps1**: 파일을 둘로 나눈다. PowerShell 은 실행하지 않는 코드도 파싱 비용을 치러서, 판정부를 한 파일에 두자 코어와 무관한 모든 도구 호출이 +24.8ms 를 냈다(08-17 실측). 검사 대상은 도구별로 가른다(파일 도구는 `file_path`, 셸 도구는 `command`). raw 전체를 보면 본문이 `CLAUDE.md` 를 언급하기만 해도 모든 편집에 승인이 뜬다(07-30 실측). 볼트 밖은 코어가 아니며, `C:/Claude_Brain_dist` 가 `C:/Claude_Brain` 으로 시작하는 접두 함정은 슬래시를 붙여 가른다. fail-open 이되 조용하지 않게: 판정부가 없으면 exit 0 과 함께 `GATE-BROKEN` 을 `_index/core-gate.log` 에 남긴다.
- **통과 토큰** `_index/.core-token`(`expires`·`scope`·`bind`·`bound`·`reason`)은 무인 세션이 쓸 유일한 신뢰 신호다. 만료는 문자열이 아니라 실제 시각으로 비교한다(문자열 비교는 `2026-8-18` 같은 형식 불량을 무제한 토큰으로 읽는다). 게이트 자신은 어떤 토큰으로도 못 고치고, 토큰은 차단만 끈다(준수사항 7절은 `allow` 에도 나간다).
- **회귀 하네스** `3_시스템/_eval/gate-verify.ps1` + `gate-cases.tsv`(111케이스, 판정 NOFIRE·ASK·ALLOW·DENY): 케이스의 볼트 경로는 `<VB>`·`<VS>` 플레이스홀더로 쓴다. 경로를 박으면 다른 위치의 볼트에서 전 케이스가 «볼트 밖»으로 통과해 하네스가 조용히 무력화된다. 준수사항 전문은 [[코어수정-준수사항-체크리스트]].
- **session 훅들**: 색인 증분은 디태치하고(동기였을 때 시작이 중앙값 23초, [[incident-2026-07-27-SessionStart-동기reindex-23초-블로킹]]) push 는 동기로 둔다(1.5초로 짧고 동시 git 은 `index.lock` 경합 위험). SessionEnd 는 커밋을 먼저 하고 무거운 일을 맨 끝에 디태치한다. 훅의 plain stdout 은 사용자 화면에 안 보이므로 기록 미완료 알림은 `session-notice.py` 가 `systemMessage`(데스크톱은 첫 응답에 한 줄로 알리라는 컨텍스트)로 낸다. 압축·재개 때는 내지 않는다.
- **session-stub.py**: 트랜스크립트를 상태 JSON 과 바이트 offset 으로 증분 파싱한다(40MB 전량 197ms → 12ms). 기록 미완료 판정은 `finally` 에서 하고, 스텁 본문이 아니라 state json 의 구조화 이벤트만 본다(본문의 응답 헤딩이 자기 언급으로 오탐한다). stdout 에는 쓰지 않는다(Stop 의 `additionalContext` 는 빈 턴을 만든다). 결과는 `_index/.pending-sessions.txt` 에 원자 교체로 쓰고 0건이면 지운다.
- **나머지**: `mdtable.py hook` 은 넘친 칸을 합치지 않고 줄 번호만 알린다(기계가 가를 수 없고, 첫 가동에서 합쳤다가 30곳이 밀렸다). `loop-pin.py` 의 재주입도 system-reminder 채널이라 순응 의존이 남는다. `idle-save.py` 는 앱이 유휴 세션을 내렸다 올리면 함께 죽어 못 막는다(재기동 뒤 첫 요청은 60분 안이어도 90%(28/31)가 전량 재작성, 09-24 실측).

### 12.7 config.json
```json
{ "embed_model": "intfloat/multilingual-e5-small",
  "graph": { "neigh_k": 3, "neigh_dup": 0.999, "neigh_tau": 0.33 } }
```
`embed_model` = 검색 모델(하드코딩 금지, 여기서만 읽음). `graph` = B1 이웃 파라미터(setup-interview 슬롯).
주의: 키 이름은 **`neigh_tau`**다. 2026-07-19 평균 센터링 개정(§5.1) 전의 `neigh_floor`(상대 floor 0.08)는 `search.py`에 더 이상 없다 — `graph_cfg()`가 읽는 키는 `neigh_k`·`neigh_dup`·`neigh_tau` 셋뿐이라 구 키로 쓰면 조용히 기본값으로 떨어진다.

### 12.8 conventions.md
정본은 `3_시스템/conventions.md`(77줄)다. 함정:
- Stop 훅이 강제하는 항목이 여기 명문화돼 있다: 파일 이름은 2_지식·`_ref` 전체에서 하나뿐이어야 하고(위키링크가 이름으로 찾는다), `moc_notes` 묶음은 프론트매터와 MOC 등재가 필요하며, `modules/` 는 프론트매터만 필요하다.
- 대본·스킬·dist-sync 가 절 이름을 참조한다. 절 이름을 바꾸지 않는다(ADR-025 유지 항목).
- 링크 입도 규약(`[[노트]]` / `[[노트#헤딩]]` / `[[노트#^blockid]]`)은 «요약 ≠ 원문 대체»의 실행 수단이다.

### 12.9 search.py — 하이브리드 검색 + B1 (핵심 재구축 대상)
정본은 `3_시스템/search.py` 다. 상단 임포트는 stdlib 만이고 `sentence_transformers`·`torch` 는 지연 임포트한다. stdout/stderr 는 UTF-8 로 `reconfigure` 한다(콘솔 cp949 에서 `—` 출력이 크래시, [[incident-2026-07-04-search-stdout-cp949]]). CLI 는 `--reindex`·`--rebuild`·`--q "질의" --k 8 --mode lexical|vector|hybrid`·`--neighbors`·`--eval`·`--link-dryrun`/`--link-write` 다.
- **인덱스** `_index/embeddings.json`: 경로별 {hash, mtime, status, gist, vecs} 와 `_model` 각인. config 의 모델이 각인과 다르면 `--reindex` 도 전체를 다시 빌드한다(차원 혼합 가드). 대상은 `2_지식/**`(MOC 제외 — 노트 설명 모음이라 노트 자신과 겹쳐 흔한 낱말로 올라온다, 11-02) · `3_시스템/_ref/**` · `_claude-memory/**` · `1_수집/**/*.md`(`_inbox/_promoted/` 제외) · `_index/pdf-cache/**` 다.
- **청킹**: 헤딩 경계, 40줄 넘는 섹션은 창 분할, 노트당 120청크(원본 색인은 2,000 — 쪽당 1청크라 120이면 긴 PDF 뒷부분이 빠진다). 노트 점수는 max-chunk cosine(통짜 희석 방지). 본문 없는 제목-only 섹션은 다음 섹션에 접두 병합한다 — 내용 없는 벡터가 이방성 원뿔에서 무관한 노트에 max 를 세우는 허위 이웃을 막는다([[incident-2026-07-19-빈약청크-허위이웃]]).
- **융합**: 어휘 arm(조사 접미를 뗀 질의 토큰의 `매칭수*10 + log1p(빈도)`)과 벡터 arm(e5 는 `query:`·`passage:` 접두, archived ×0.5, recency 가중 0)을 RRF k=60 으로 합친다. 모델 티어는 config 한 줄 + `--rebuild` 다: 저 = e5-small(384, CPU, 기본) · 중 = e5-base(768) · 고 = bge-m3(1024, GPU).
- **B1**: 이웃은 평균 센터링 후 top-k(§5.1)이고 top1 은 무조건 두고 2~k위는 `neigh_tau` 이상만 둔다. 검색의 벡터 점수는 센터링하지 않는다. writer 범위는 `roles.json` 의 `note_areas`·`modules`·`sessions` 와 `3_시스템/_ref`(Claude 소유만)이고, 링크 대상에서 pdf-cache·기억·원본 색인·시스템 문서를 뺀다. 블록은 접이식 콜아웃 `%%sl%%` 마커로 멱등 교체하며, `strip_managed` 가 색인 유입을 막아 자기강화를 끊는다.

### 12.10 스킬
정본은 각 `.claude/skills/<이름>/SKILL.md` 다(목록은 §8). 함정:
- 무인 실행에서 승인 프롬프트 대기는 조용한 사망이다(첫 `Write` 승인 대기 3시간 54분 뒤 abort, [[incident-2026-07-27-weekly자동실행-권한대기-사망]]). 승인이 뜰 스텝은 «미실행»으로 보고하고 넘어간다.
- 스킬 파일은 T2 라서 부르지 않으면 읽히지 않는다. 꼭 읽혀야 하는 규약은 훅으로 다시 넣는다(`loop-pin.py`). 재고 자르는 기계 일은 즉석 코드가 아니라 대본에 둔다(`record.py`·`weekly.py`).

### 12.11 골든셋 + 측정
골든셋은 각 볼트가 자기 코퍼스로 만드는 `3_시스템/_eval/golden.jsonl`(제작자 볼트 literal 30)과 `golden-paraphrase.jsonl`(패러프레이즈 12)이다. 각 줄 `{"q":"한국어 질의","a":"정답 노트 상대경로"}` 다. `search.py --eval <파일> --k 8` 이 lexical·vector·hybrid 3자 hit@8 을 내고, 합격선은 ≥ 80% 이며 weekly 가 재측정해 낙폭을 잡는다.

- 11-02 주간 재측정(기록값, 이번에 다시 돌리지 않음): literal 30 은 세 arm 모두 30/30, 패러프레이즈 12 의 hybrid 는 5/12(41.7%)다. 주간 리포트는 10-25 와 같다며 낙폭이 없다고 적었다. 빌드 때 7/12 에서 내려간 까닭은 확인 못 함.
- 배포에는 골든이 들어가지 않는다. 사용자가 자기 코퍼스로 쓴다(절차 `_eval/measure.md`). 배분은 지식 질의 + 세션 회상 + `_ref` 형 + PDF 내용형을 권한다.
