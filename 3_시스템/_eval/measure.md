# 골든셋 측정 절차 — hit@8

검색 성능을 골든셋으로 측정·회귀한다. 지표 = **hit@8** = (정답 노트가 top-8 후보에 포함된 질의 수) / 전체. 합격 = **≥ 80%**.

## 1. 골든셋 작성
`_eval/*.jsonl`, 각 줄 = `{"q":"한국어 질의","a":"정답 노트 상대경로"}`. **골든은 배포에 없음 — 각 사용자가 자기 볼트로 작성**한다.
- **literal형**: 노트의 고유명사·헤딩어를 그대로 쓴 질의(grep/lexical 강점 구간).
- **패러프레이즈형**: 고유명사·헤딩어를 뺀 의미 질의(벡터/하이브리드 검증, **실사용 근사**).
- 배분 권장: 지식질의 · 세션회상형 · _ref형("전에 이 버그 어떻게 풀었지") · PDF내용형.

> ⚠ **함정: literal만 재면 순환측정.** literal 질의는 grep 홈그라운드(고유명사 공유)라 grep이 거의 100% — "검색이 좋다"가 아니라 "질의가 grep에 유리"였을 뿐. **패러프레이즈 골든을 반드시 병행**해야 각 arm의 강점과 하이브리드의 상보성이 드러난다. (이 함정을 놓쳐 벡터 불요로 오판할 뻔한 게 빌드 중 실측됨 — `results-hybrid.md`.)

## 2. 측정
```
py -3 3_시스템/search.py --eval <골든파일> --k 8
```
→ **lexical / vector / hybrid 3자 hit@8** 자동 출력 + miss 목록(정답의 실제 순위).

## 3. 판정
- 패러프레이즈 골든에서 **하이브리드가 각 arm 단독을 능가**하면 하이브리드 유지(현 채택 구성).
- hit@8 < 80%면 임베딩 티어 상향(`config.json` `embed_model` 교체 + `search.py --rebuild`) 후 재측정.

## 4. 회귀 (weekly)
`weekly-review`가 골든 샘플을 재측정(3자) → 하이브리드 낙폭 시 보고. 재측정 트리거: 코퍼스 급증(수백 노트↑) · 이전 대비 하락 · 임베딩 모델 교체.

## 5. 패러프레이즈 셋 v2 (11-05 · 결과를 보기 전에 고정)
- 옛 12문항(10-25 이전 · 5/12 불변 · «문항 갱신 12회째 미실행»)을 버리고 새로 뽑았다. 고르는 규칙: 시드 `20261105` 로 무작위 · 색인에 든 노트 · `sensitive`·`archived`·옛 골든 정답 제외 · 지식 3 · 세션 기록 3 · `_ref` 진단 3 · 원본 색인 3. 질문은 노트 제목·헤딩 낱말을 피해 의미로 썼고, 쓴 뒤 검색 결과를 보지 않았다. 옛 문항은 git 이력에 있다.
- **판정 규칙(측정 전 고정)**: 기준선 = 첫 측정의 hybrid hit@8. 이후 weekly 가 같은 셋을 재서 **기준선보다 2문항 이상 내려가면 보고**한다. 합격선은 이 문서 머리말의 ≥ 80%(12문항 중 10) — 첫 측정이 미달이어도 문항을 바꾸지 않는다(문항은 코퍼스가 바뀌어 정답 노트가 사라질 때만 그 문항만 갈아 기준선을 다시 적는다).
- 검색 코드·`search.py` 는 이 일에서 건드리지 않는다. 측정 = `py -3 3_시스템/search.py --eval 3_시스템/_eval/golden-paraphrase.jsonl --k 8`. `weekly.py` 는 literal 셋(`golden.jsonl`)만 재므로 이 셋은 손으로 돌린다(자동화는 다음 일).
- **첫 측정(11-05 · 기준선)**: lexical 9/12(75.0%) · vector 9/12(75.0%) · **hybrid 10/12(83.3%) = 합격선 통과**. hybrid 가 각 단독보다 높다(§3 충족). 놓친 hybrid 2건 = 코어개혁 세션 기록(순위 11) · 전자기학 과제 안내 색인(순위 780 · 영어 PDF 색인이라 한국어 질의와 어긋남). 옛 셋 5/12 는 같은 코퍼스에서 낮게 나온 값이라 «검색이 나쁘다»가 아니라 «문항이 낡았다/어려웠다»에 가깝다(두 셋은 문항이 달라 직접 비교는 못 함).
