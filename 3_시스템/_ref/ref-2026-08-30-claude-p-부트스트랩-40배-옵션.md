# `claude -p` 회당 85,953 → 2,156 — 원인은 경로가 아니라 기본 옵션

**한 줄**: 하위 세션 호출이 비싼 원인이 `claude -p` 의 성질이라고 7일간 믿었는데,
실측해 보니 **옵션을 하나도 안 준 결과**였다. 회당 원시 **85,953 → 2,156(39.9배)**.
그 오판 위에서 *"모드 B 에는 `ANTHROPIC_API_KEY` 가 필요하다"* 는 사망 판정이 서 있었다.

## 증상

제작자 볼트의 화면 관측 프로젝트가 관측자·채점자를 전부 `claude -p` 하위 세션으로 부른다.
회계 상수는 `CLI_CALL_OVERHEAD=45,000 × CLI_TURNS=2 = 90,000/호출` 이었고,
그 값이 모든 비용 판단을 지배했다.

    오버헤드 비중  모드 A 71% · 모드 B **97%** · 명세 §7 베이스라인 86.6%
    베이스라인 1,560만 토큰 중 **1,350만이 부트스트랩**, 이미지는 210만뿐

즉 **재는 것보다 세션을 띄우는 데 6.4배를 쓰고 있었다.**

## 원인 — 요인 분해 실측

세션 로그(`~/.claude/projects/<슬러그>/*.jsonl`)의 `usage` 를 **`requestId` 로
중복제거**해 합산했다(한 API 요청이 assistant 레코드 여러 개로 쪼개지고 각 레코드가
같은 usage 를 복제한다). 같은 프롬프트·같은 모델·같은 이미지 1장, 정상 상태.

| 조건 | 왕복 | 원시 | 비고 |
|---|---:|---:|---|
| **H** `-p … --allowedTools Read` | 2 | **85,953** | 현행 |
| C `+ --safe-mode` | 2 | 36,953 | −11% |
| D `--system-prompt` 대체 | 2 | 32,298 | −22% |
| **E** `--tools ""` | 2 | **9,210** | **−78%** |
| F `--exclude-dynamic-system-prompt-sections` | 2 | 41,118 | −1% |
| G `--tools Read --system-prompt` | 2 | 26,342 | |
| K G `+ --safe-mode` | 2 | 5,328 | |
| **L** G `+ --strict-mcp-config` | 2 | **5,296** | K 와 같다 |
| I G + 둘 다 | 2 | 5,320 | K·L 과 같다 |
| **J** `--input-format stream-json` + 이미지 직접 첨부 | **1** | **2,156** | |
| J 배치 14장 | 1 | 25,298 | 장당 1,807 = **선형** |

**주범 순서 — 내장 도구 정의 78% > 기본 시스템 프롬프트 22% > MCP 도구 정의 > Read 왕복.**

### 함정 넷

**⑴ `--allowedTools` 는 비용을 안 줄인다.**
이름이 비슷해 같은 것으로 읽히는데 **완전히 다르다.**

    --allowedTools Read    허용 목록. 도구 정의는 **전부** 실리고 사용만 제한한다.
    --tools Read           사용 가능한 도구 **집합**. 정의 자체가 하나로 준다.

우리는 줄곧 앞엣것을 쓰고 있었다. 안전 울타리로도 부실하고(별도 확인) 비용도 안 줄인다.

**⑵ `-p "<프롬프트>"` 는 이미지를 메시지에 못 붙인다.**
공식 문서([Streaming Input](https://code.claude.com/docs/en/agent-sdk/streaming-vs-single-mode))가
명시한다 — *"Single Message Input mode does **not** support: **Direct image attachments
in messages**"*. 그래서 이미지를 `Read` 도구로 읽어야 하고, **그것이 왕복 2회 =
부트스트랩 2배**를 만든다. `--input-format stream-json` 이 streaming input mode 이고
`content` 배열에 `{"type":"image","source":{"type":"base64",…}}` 를 직접 넣을 수 있다.

**⑶ `--safe-mode` 와 `--strict-mcp-config` 는 같은 것을 껐다.**
K·L·I 가 전부 5.3K 로 동일하다 — 둘 다 **MCP 서버 도구 정의**를 없앤다.
**좁은 쪽(`--strict-mcp-config`)만 쓰면 된다.** `--safe-mode` 는 CLAUDE.md·스킬·훅까지
끄는 넓은 플래그이고 문서가 *"문제 해결용"* 이라 부른다 — 품질 영향이 미검이라
안 쓰는 편이 낫고, **안 써도 같은 절감이 나오므로 그 미결 자체가 사라진다.**

**⑷ 단발 측정은 캐시 상태에 오염된다.**
프롬프트를 바꾼 첫 호출은 캐시를 통째로 다시 쓴다(`cache_creation` 큼 · `cache_read` 0).
그래서 **표준환산(캐시읽기 0.1배)으로 재면 새 조건이 오히려 비싸 보인다.**
정상 상태(같은 프롬프트 2회차 이후)를 봐야 한다.

    G 1회차  wr      0  rd 26,197 | 원시 26,342  표준 2,764
    G 2회차  wr      0  rd 26,197 | 원시 26,355  표준 2,777   ← 안정
    G 3회차  wr  2,256  rd 23,951 | 원시 26,379  표준 5,387   ← TTL 경계
    H 현행                        | 원시 85,953  표준 24,369

**어느 셈법으로도 최소 옵션이 이긴다**(원시 3.3배 · 표준 8.8배). 결론이 셈법에
의존하지 않는 것이 이 실측의 강점이다.

## 수리

```
claude -p --input-format stream-json --output-format stream-json --verbose
          --model <m>
          --tools ""                    # 도구 정의 제거 (부트스트랩 78%)
          --system-prompt "<짧은 역할>"   # 기본 프롬프트 대체 (22%)
          --strict-mcp-config           # MCP 정의 제거
  stdin:  {"type":"user","message":{"role":"user","content":[
            {"type":"text","text":"<규칙 + 항목 목록>"},
            {"type":"image","source":{"type":"base64","media_type":"image/png",
                                      "data":"<b64>"}}]}}
```

구현 → 그 프로젝트의 `observer.py` `ClaudeStreamObserver`(배포판 미포함).
근거 주석 → 같은 저장소 `eye/config.py` (`STREAM_SYSTEM_PROMPT` 위).

⚠ **기존 경로를 지우지 않았다.** 앞선 단계의 모든 측정이 옛 경로에서 나왔고, 대조 없이
갈아타면 이전 값과 비교 가능성이 끊긴다.

## 부수 소득 셋

**⑴ 회계가 추정에서 실측으로 바뀐다.**
`--output-format stream-json` 의 `result` 줄에 진짜 `usage` 와 `modelUsage` 가 실려 온다.
상수 두 개로 추정할 이유가 없어진다.

**⑵ 회계가 못 보던 항이 드러난다.**
`modelUsage` 에 **`claude-haiku-4-5` 가 호출당 1,027~3,146 입력토큰** 찍힌다
(`post_turn_summary` 생성으로 보인다). **호출당 usage 만 보는 회계는 이 항을 구조적으로
못 본다.** 무엇에 쓰이는지·끌 수 있는지는 미확인.

**⑶ 사용률 경고가 스트림에 실려 온다.**
`{"type":"rate_limit_event","rate_limit_info":{"status":"allowed_warning",
"utilization":0.78,…}}`. 삼키지 말고 찍어야 한다.
⚠ **단 `Gist.error` 같은 "사건 오류" 필드에 넣으면 안 된다** — 그 프로젝트에서 넣었더니
`trusted` 판정이 죽어 **되먹임 컨텍스트가 통째로 끊겼고 채점기의 오류 건수도 부풀었다.**
**경고는 사건이 아니라 환경 상태다.**

## 파급

    모드 A (20분)      126,601  ->  약 31,000     4.1배
    모드 B (20분)    1,204,169  ->  약 50,000    **24배**
    명세 §7 베이스라인 15,597,600 -> 약 2,160,000  7.2배

그리고 명세가 적어 둔 판정이 무효가 된다 —
*"`claude -p` 경로에서는 모드 B 가 사실상 불가능하다. 모드 B(=1장 완성)를 위해서는
`ANTHROPIC_API_KEY` 가 필요하다."* 그 근거가 *"§3.4 배치 = 필수(회당 오버헤드 98K)"*
였다. **회당 2,156 이면 배치가 필수가 아니고, 배치가 없으면 명세가 지목한 발화 지연
충돌도 사라진다. 키 없이 성립한다.**

## 교훈

**비용이 막는다고 결론 내리기 전에 그 도구의 `--help` 를 끝까지 읽고 옵션을 하나씩
갈라 재라.** 요인 분해 없이 *"이 경로는 비싸다"* 로 닫으면, 실제로는 **기본값이 비쌌던
것을 경로 탓으로 돌리게 된다.** 이 프로젝트는 그 오판 위에서 사망 판정 하나를 일주일
내내 들고 있었고, 그 판정이 앞선 단계들의 비용 판단 전부를 규정했다.

⚠ 그리고 **같은 계열의 이전 교훈이 이미 있었다** — *"모델이 없으면 못 한다고 결론
내리기 전에 OS 가 이미 주는 것을 먼저 재라"*(윈도우 내장 OCR). **이번 것은 그 하네스
판본이다.**

## 재현

```bash
# A/B — 세션 로그의 usage 를 requestId 중복제거해 읽는다

claude -p "<같은 프롬프트>" --model sonnet --tools "" \
        --system-prompt "<짧게>" --strict-mcp-config
# 그 뒤 ~/.claude/projects/<슬러그>/*.jsonl 두 개를 mtime 순으로 읽어
#   input_tokens + cache_creation + cache_read + output_tokens 를 합산
# ⚠ 정상 상태를 보려면 같은 조건을 2회 이상 돌린 뒤 2회차를 본다
```
