# 작업 자동 비움이 제출 하나로 폴더를 통째로 휴지통에

## 증상
사용자 11-15 «어제 부탁한 최종 프로젝트 역할분담 문서 어디 있어?» — 작업 폴더 `0_작업/배움/<과목>/최종프로젝트/` 가 없음. 04:09 `script:work` 묶음이 13개를 휴지통으로 보내고 폴더를 지웠다. 역할분담 문서 둘(파트 A·B)이 «초안·다른 판(보낸 판이 보관됨)», 예시 html 셋이 «작업 노트·파일»로 갔다. `fileops restore` 로 다섯을 되살림(해시 = 장부와 같음).

## 근본원인 (제작자 볼트 실측)
- **제출 하나 = 작업 끝**: 제안서 PDF 를 LMS 에 낸 뒤(01:27) LMS 수집이 «내 제출»을 받았고(01:50), 04:09 볼트를 켤 때 `work.py sweep` 이 `by_lms` «보냄»(SURE)으로 보고 승인 없이 비웠다. 폴더는 제안서 → 발표·최종 보고서로 이어지는 여러 단계 작업이었다.
- **아직 하는 중인 증거를 안 봄**: 판정기가 읽는 일정에 한 달 뒤 «마지막 발표·시연 + 마지막 보고서»(남음)가 있었고, 파트 A·B 는 제출 8분 뒤에 만든 파일이었고, 마지막 수정은 0일 전이었다.
- **자동 쪽이 더 거침**: 보냄 갈래의 남은 칸은 보낸 파일과 이름이 닮았는지 보지 않고 문서 = «초안·다른 판», 나머지 = «작업 노트·파일»로 휴지통. 끝냄 갈래는 «다시 못 만드는 것은 남긴다». 전날 정리 계획(마감 지남 · html = 승격)과 04:09 실제 비움이 다르게 나온 까닭.
- 곁: 일정에 적힌 제안서 마감 날짜가 LMS 마감과 달라, 전날 «마감 지남» 판정이 그 날짜에서 나왔다.

## 해결
사용자 11-15 승인:
1. 끝남 근거(사람 표시 빼고)가 있어도 `still_going` 증거가 있으면 «진행» — 같은 낱말의 앞으로 일정 «남음» · LMS 제출 시각 뒤에 고친 파일(보낸 파일의 판·`작업.md` 빼고 · 시계 차 60초).
2. 보냄 갈래의 «초안·다른 판»은 `related()`(보낸 파일과 정규화 이름 앞머리가 길게 같음 · 확장자 무관)만. 이름이 다른 것은 지식으로 승격하고, 그런 파일이 있으면(`held`) sweep 이 비우지 않는다 → `work.py plan` 후보 · 승인 뒤 `--apply`.
- `topic.status` 에 `limit` 인자(기본 그대로) — 앞으로 일정 줄을 12줄 상한 없이 보려고.

격리 시험(모듈을 경로로 읽어 시험 볼트 · sweep 안 부름): 사고 재현 = 원래 판은 9개 모두 휴지통(04:09 와 같음) · 고친 판 = 진행(두 증거 다) · 증거를 끈 고침 2 단독 = 초안 둘만 휴지통, 파트 A·B·html = 승격·held · 지난 자동 비움 둘 중 하나는 그대로 자동 비움, 하나는 분석 대본 산출물 `results.json`(이름 다름)이 held → 후보로 남음(전에는 자동으로 지움) · 제작자 볼트 작업 28개 중 판정이 바뀐 것 = 이 작업 하나(마감 지남 → 진행).

## 재발방지
- 제출·병합·마감 같은 기록 근거는 «그 결과물이 끝났다»이지 «작업이 끝났다»가 아니다 — 자동으로 지우는 쪽에는 반대 증거 검사를 둔다.
- 이름으로 «판»을 가를 수 없는 파일은 자동으로 지우지 않는다(옮기거나 묻는다).
- 손해(잼): 이름이 넓은 작업(예: «보고서»)은 앞으로 일정이 있는 동안 진행으로 남는다 · 대본 산출물(`results.json` 등)이 있는 보냄 작업은 승인을 한 번 거친다. 그때는 홈·탐색기 «끝냄».
