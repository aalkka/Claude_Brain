# 오전 내내 클로드 멈춤(제작자 PC · 11-20 06:43~13:00)

## 증상
사용자 «컴퓨터가 꺼지고 클로드가 로그아웃되는 사태 발생. 그래서 저녁동안 클로드가 돌지 못함». 13:00 에 와 보니 PC 가 꺼진 듯했고 Claude 앱은 다시 로그인하라고 했다.

## 잰 사실(11-20 13시 · 조사 세션)
- 재부팅·종료·로그오프 기록 없음(System 6005/6006/6008/1074 · Winlogon 7001/7002 0건). 전원 = 00:25 부터 계속 AC.
- 잠듦·깸(Kernel-Power 42/107 · Power-Troubleshooter 1):

| 잠듦 | 까닭 | 깸 | 깨운 것 | 깬 뒤 다시 잠까지 |
|---|---|---|---|---|
| 06:43:30 최대 절전 | Application API(다른 세션의 «깨우기 시험(최대 절전)») | 06:46:16 | 그 시험 작업 타이머 | 2분 27초 |
| 06:48:43 | System Idle | 06:54:51 | 수집 출처 A | 26분(수집하는 동안 붙듦) |
| 07:20:50 | System Idle | 11:59:57 | 수집 출처 B | 2분 18초 |
| 12:02:15 | System Idle | 13:00:44 | 사용자 | — |
- 무인 절전 제한 `powercfg /qh SCHEME_CURRENT SUB_SLEEP UNATTENDSLEEP` = **0x78 = 120초**(AC·DC). AC 유휴 절전은 «안 함»이다. 타이머로 저절로 깬 PC(무인 깨어남)는 사람 입력도 «시스템 필요» 요청도 없으면 윈도가 이 시간 뒤 다시 재운다 — 위 «2분 18~27초»가 그것이다. 잠든 꼴이 최대 절전이었으니 다시 최대 절전으로 갔다.
- 실행 상태 `CallNtPowerInformation(SystemExecutionState)` = 0x0 — 평소 «시스템 필요»를 쥔 상주 프로세스가 없다. 수집 «PC 깨우기»는 받는 동안만 쥐고 놓는다.
- 폰 서버(모바일 연결 모듈)는 깬 틈에만 답했다 — 폰 환경이 오전 내내 끊김.
- **«로그아웃»은 데스크톱 앱 로그인 만료다(절전과 별개)**: `%LOCALAPPDATA%\Claude\Logs\main.log` 07:11:20 «OAuth token refresh failed (invalid_grant)» → «the server says this sign-in is too old (session_stale_relogin), so the person must sign in again» → «Code-tab token renewal (timer) failed». `remote-control.log` 07:12:24 «state off → auth_stale». 13:01 사용자가 다시 로그인 → 13:02 풀림 · `~/.claude/.credentials.json` 갱신. 남은 기록에서 앞 로그인은 약 28일 전 하나. 서버가 정한 로그인 수명(값은 모름 · 추정)이라 PC 가 깨어 있었어도 07:11 에 풀렸다.

## 근본 원인
1. **사람 없을 때 실제로 재우는 시험을 허락했다.** 다른 세션의 «깨우기 시험(최대 절전)»이 06:43 에 PC 를 최대 절전으로 보냈다. 시험 자체는 3분 뒤 깨웠지만 거기서 사슬이 시작됐다.
2. **AC 에서 «깨어 있음»을 쥐는 상주가 없었다.** «PC 는 끄지 않고 깨어 있어 폰 환경 유지»를 «AC 유휴 절전 = 안 함» 한 설정에만 맡겼다. 그 설정은 사람이 쓰다 둔 PC 의 유휴만 막고, 한 번 잠든 PC 가 무인으로 깬 뒤의 2분 재잠(UNATTENDSLEEP)은 못 막는다. 수집 «PC 깨우기»는 받는 동안만 붙들어 사슬을 끊지 못했다.
3. **로그인 만료를 아무도 알리지 않았다.** 앱은 07:11 에 알았지만 사람에게 가는 알림이 없다 — 사용자가 13:00 에 와서야 봤다.

## 해결
- 자체 절전 모듈(`self_sleep`)에 칸 둘:
  - `power.awake_ac` «전원 연결 때 깨어 있음»(기본 켬) — 감시 창 스레드가 `SetThreadExecutionState(ES_SYSTEM_REQUIRED|ES_CONTINUOUS)`를 쥠. 화면은 꺼짐. 배터리면 놓음. 사람이 고른 절전·SetSuspendState 는 막지 않음.
  - `power.resume_awake` «저절로 깬 뒤 깨어 있음»(기본 켬) — `PBT_APMRESUMEAUTOMATIC` 를 받으면 바로 다시 쥐고, 사람이 만지면 보통 규칙. 잠듦은 `suspend` 로 기록(원치 않은 잠 진단).
  - 시험 42/42(다른 프로세스에서 0x1 로 보이고 끝나면 전과 같음) · 감시 길 실측: 감시가 도는 동안 0x1 · 끝나면 0x0.
- **안 잰 것**: 실제로 재운 뒤 타이머로 깨서 2분 뒤 다시 안 자는지 — PC 가 꺼지므로 사람이 자리에 있을 때만 잰다.
- 로그인 만료 알림: `3_시스템/claude_login.py` 가 앱 `main.log`(session_stale_relogin)·`remote-control.log`(→ auth_stale)를 읽어 풀림·되찾음을 가름 → 건강 줄 «Claude 로그인»(drift.mem_rows) · 모바일 연결 모듈이 있으면 폰에도 그 풀림에 한 번. 시험 `3_시스템/_eval/claude_login_check.py`. 서버가 정한 수명이라 막을 수는 없고 빨리 알 수만 있다.

## 재발 방지
- 실제로 재우는 시험(절전·최대 절전·깨우기)은 사람이 자리에 있을 때만. 무인 시간에 허락하지 않는다.
- «깨어 있음»은 설정 한 줄이 아니라 쥐는 상주로 보장한다. 확인 = `self_sleep.py status` 의 `system_required_held`.
- 무인 측정·가동 기록은 Kernel-Power 42 «System Idle» 를 먼저 본다 — AC 인데 이 까닭이 나오면 무인 재잠이다.
