# 자동 모드 서버 판정이 무응답을 내며 무인 진행을 멈췄다

## 증상
- Bash·PowerShell·Edit·Write 가 실행 전에 거부된다. 문구:
  `The server-side auto mode classifier gave no verdict (error), so auto mode cannot determine the safety of <tool>.`
- 명령 내용이 거부된 것이 아니라 판정 서비스가 판정 대신 오류를 낸 것이다. Read·Grep·Glob 은 판정이 필요 없어 계속 된다.
- 하네스 규칙: 10 응답 연속 무판정이면 턴이 끝난다(문서 `errors#the-server-returned-no-safety-verdict`). 사용자가 메시지를 보내면 계수가 0으로 돌아간다.
- 피해: 09-30 03:19 묶음에서 세션 B 가 8회째에 스스로 멈춤 → 무인 진행 약 6시간 공백. 예약된 측정 작업이 실행되지 못했다.

## 실측 (세션 기록 40개 · 판정 필요 호출 4,606건 · 스크립트는 세션 scratchpad `clf*.py`)
- 7월 ~ 09-29 17:30 KST: 약 4,400건 무실패.
- 09-29 17:30 부터 4 묶음 28건. 각 묶음 = 5~8건 연속 · 1~3분 안.

| 묶음(KST) | 세션 | 연속 실패 | 복구까지 |
|---|---|---|---|
| 09-29 17:30 | 세션 A | 7 (Edit) | 3.5분 |
| 09-29 23:55 | 세션 B | 7 | 19분 |
| 09-30 01:50 | 세션 B | 5 | 15분 |
| 09-30 03:19 | 세션 B | 8 | 세션이 멈춤 |

- 무관한 것: 입력 크기(0~8K자 전 구간 0.4~0.9%) · 도구 종류 · 맥락 크기(실패 중앙 24만 < 성공 중앙 34만 토큰).
- 버전: 09-28까지 2.1.280, 09-29부터 2.1.284. 같은 2.1.284 의 09-29 오전 세션 C 216건은 무실패 → 버전만으로 설명 안 된다.

## 원인 판단
- 서버 측 판정(server-side classifier review — 모델 요청 안에서 서버가 행동을 판정)의 일시 장애. 우리 입력 탓이 아니다 [실측 근거].
- 모름: 서버 판정이 09-29부터 이 세션들에 켜졌는지, 그 전에는 Claude Code 자체 판정 요청 경로였는지. 오류 문구의 «server-side» 가 09-29부터만 나타나는 것은 정황일 뿐이다.

## 우리 쪽 결함
- 이전 세션이 6~8회에서 «10회면 강제 종료» 를 이유로 스스로 멈췄다. 10회에 멈춰도 결과(턴 종료)는 같고, 복구 기회만 버렸다.
- 재시도 간격 10~40초 ≪ 실측 복구 3.5~19분. 같은 명령을 빠르게 다시 치는 것은 계수만 소모한다.

## 대처 후보 (사용자 09-30 «기록만» — 미적용)
1. **`CLAUDE_CODE_AUTO_MODE_SERVER=0`** — `~/.claude/settings.json` 의 `env`. 자동 모드·안전 검사는 유지하고 판정만 Claude Code 자체 요청으로 돌린다(문서의 공식 대처 · v2.1.281+ 가 읽음). 새 세션부터.
   - 문제점: 서버 판정은 무료, 자체 요청은 Enterprise·API 계정만 과금(Max 는 대상 아님 · 문서). 5시간 한도 소모 여부는 문서에 없음(미확인). 동작마다 왕복 1회 추가 → 지연 증가 가능. 자체 경로도 실패할 수 있음.
2. 보조: 볼트 밖 작업 저장소를 `additionalDirectories` 에 → 그 안 편집은 판정 없이 통과(문서 결정 순서 2단계). 대신 그 편집은 검사 없음.
3. 편집 자동 수락(acceptEdits) — **부적합**. 작업 디렉터리 밖 편집·읽기 전용 아닌 Bash 전부 확인 창 → 무인 진행이 첫 명령에서 멈춘다.
4. 권한 무시(bypassPermissions) — **비권장**. 안전 검사 전체가 꺼짐 · 문서는 컨테이너/VM 한정 · 세션 도중 전환 불가.

## 코어게이트 × 권한 모드 (사용자 질문 · 문서 기준 · 두 모드 실측 0건)
| 게이트 판정 | 편집 자동 수락 | 권한 무시 |
|---|---|---|
| deny(토큰 범위 밖) | 유지 | 유지 |
| 토큰 allow + 준수사항 주입 | 유지 | 유지 |
| ask(토큰 없음 · 대화형 코어 편집 기본) | 유지(추정) | 꺼질 가능성 큼(추정) — 우회 모드 예외 목록에 «명시적 ask 규칙» 만 있고 훅 ask 는 없다 |

- `core-gate.log` 의 모드 기록은 `[auto]`·`[default]` 뿐이다.
- 우회 모드에서도 남는 1층 `permissions.ask` 는 코어 게이트 개정 4(08-17)에서 철수했다 — 토큰 통과의 전제. 되살리면 무인 토큰 경로가 깨진다.

## 운영 규칙 (적용함)
- 무판정 거부가 나면 스스로 조기 종료하지 않는다. 판정이 필요 없는 읽기 작업(Read·Grep·Glob)으로 넘어가 할 일을 하고, 간격을 두고 한 번씩 재시도한다. 같은 명령 연타 금지.
- 서버 판정 세션에서는 읽기 전용 Bash 도 판정을 기다린다(문서) — 대기용 `sleep` 도 막힌다.

## 재발 (09-30 오후 · 다른 작업 세션)
- Bash 4회 연속 «no verdict (error)» — 사이에 읽기 작업·파일 읽기로 간격을 둠. 읽기(Read·Grep)와 스크래치 폴더 쓰기(Write)는 통과 → 작업물(#3 정답 구간)을 스크래치에 먼저 보존.
- 사용자에게 대처 1 적용 승인 요청 → 사용자 «재시도» → 곧바로 통과(복구). **대처 1 은 여전히 미적용.**
- 교훈: 막히면 판정이 필요 없는 도구(Read·Write)로 **진행 중 산출물을 먼저 보존**한 뒤 묻는다.
- 같은 날 밤 두 번째 재발: Bash 2회 · Write 1회 연속 무응답(쓰기 도구도 막힘 · 스크래치 폴더 Write 는 통과) → 절차 문서를 스크래치에 보존 · 읽기 작업 뒤 재시도로 복구(수 분).
