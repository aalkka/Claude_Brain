# 데스크탑에서 기록 알림이 두 경로 모두 막혀 있었다

## 증상
사용자: «세션 스텁 메시지가 세션 시작 때 안 뜸. CLI 에서만 뜸.» 09-12 에 `session-notice.py`(SessionStart `systemMessage`)로 한 번 고쳤는데 데스크탑에서는 그대로였다.

## 원인 — 두 경로가 동시에 막혔다
1. **화면 경로**: 데스크탑 앱은 Agent SDK 로 Claude Code 를 띄운다(`CLAUDE_CODE_ENTRYPOINT=claude-desktop` · SDK 0.3.280). 훅 문서: `systemMessage` 는 SDK 에서 `SDKInformationalMessage` 로 따로 빠진다. 트랜스크립트에는 `hook_system_message` 로 **기록됐지만** 앱이 그리지 않았다(사용자 판정).
2. **Claude 경로**: 같은 목록이 컨텍스트로도 주입되는데, 그 원문에 «**사용자 화면에는 session-notice.py 가 systemMessage 로 이미 띄웠다**»가 박혀 있었다(`session-stub.py` 가 쓰는 `.pending-sessions.txt`). 모델에게 «전하지 마라»로 읽힌다 — 09-24 이 세션에서도 전하지 않았다.

CLI 에서는 1이 살아 있어 문제가 안 보였다. 09-12 수리는 CLI 에서만 검증됐다.

## 수리
- `session-notice.py`: 데스크탑(`CLAUDE_CODE_ENTRYPOINT == "claude-desktop"`)이면 `systemMessage` 대신 SessionStart `additionalContext` 로 **«첫 응답 맨 앞에 이 줄을 옮겨 적어라»** 지시를 낸다. CLI 는 기존 그대로.
- `session-stub.py`: «이미 띄웠다» 문구를 «화면 알림은 session-notice 담당 — CLI 는 systemMessage, 데스크탑은 첫 응답 전달 지시»로 교체.
- 모의 실행: 두 모드 JSON 유효 · 분기 확인. ⚠ **훅 프로세스가 `CLAUDE_CODE_ENTRYPOINT` 를 물려받는지는 새 데스크탑 세션에서만 확인된다**(Bash 도구 환경에는 있다). 안 물려받으면 기존 동작(systemMessage)으로 떨어진다 — 악화는 없다.

## 재발방지
- **표시 경로를 고칠 때는 CLI·데스크탑 둘 다에서 사람 판정을 받는다.** 트랜스크립트에 기록됐다는 것은 화면에 보였다는 증거가 아니다.
- 모델에게 주입하는 문구에 **다른 채널의 성공을 단정하지 않는다**(«이미 띄웠다»). 그 단정이 순응 경로를 끈다.
- 세션 중 바꾼 훅·상태줄 설정은 **그 세션에 반영되지 않는다**(09-24 실측: settings.local.json 에 넣은 PostToolUse 기록 훅이 발화 0) — 표시 수리는 새 세션에서만 검증된다.

## 후속 (2026-10-03 · 사용자 «대답할 타이밍이 안 나옴 · 세션 코드만으론 기록할지 못 정함»)
- 본문 맨 앞 한 줄 방식은 **보이기는 했으나**(10-03 이 세션 첫 응답에 주입 확인) 다른 작업에 묻혀 답할 틈이 없었다.
- 수리: `session-notice.py` 데스크탑 지시 = 첫 응답에서 **AskUserQuestion 질문창**(세션마다 질문 하나 · 세션노트 / recent 한 줄 / 넘어가기 / 이번엔 보류) · 무인 진행·도구 없음이면 예전 한 줄로. `session-stub.py` = 미기록 목록에 «제목» 추가(트랜스크립트 마지막 `custom-title` · 없으면 첫 발화 40자 · 실측 40세션 중 5개가 제목 없음).
- 검증: 격리 복사본에서 생산자→표시기 두 모드 · 옛 형식(제목 없음) 호환 · PS 5.1 JSON 유효. 같은 세션에서 질문창으로 3건 처리(사용자 승인). **새 세션 첫 응답에서 창이 뜨는지는 아직 미확인.**
- 같은 날 점검에서 찾은 감지 공백: 기록을 Bash 로 쓴 세션(14일 2건)을 미기록으로 오탐 · 사후 세션노트가 감지를 풀지 않음 → open-loops.
- **감지 수리(같은 날 · 사용자 승인)**: `session-stub.py` 가 셸 명령 속 recent·open-loops·sessions 쓰기(쓰기 표지 동반만)와 세션노트 프론트매터 `session: <id>` 를 기록으로 인정. 30일 164세션 재판정 = 8세션 미기록→기록(전부 실제 쓰기) · 반대 방향 0 · 옛 감지의 미기록 18건 중 8건이 오탐이었다.
- **세이브포인트 근본 원인(같은 날)**: `idle-save.py` 가 파일 크기·시각으로 «새 활동» 을 재는데, 앱이 턴 끝 4~17초 뒤 `stop_hook_summary`·`custom-title` 등 메타 줄을 덧붙여 감시가 첫 확인(30초)에서 늘 빠졌다(유휴 50분+ 3건 모두 이 줄 · 저장 0 · 발동 표지 0). 수리 = user/assistant 줄 시각으로 판정 + hooks.log 계측(`watch`·`exit activity`·`fire`). 격리 재현: 옛 = 메타 줄만에 2초 탈락 · 새 = 기한에 깨움 · 진짜 입력엔 빠짐. **실사용 첫 발동은 미확인.**
