# hasattr 로 감싼 없는 메서드 — 조용한 무동작

**한 줄**: 방어적으로 쓴 `hasattr` 가 오타를 숨겨, 고리가 한 번도 안 돌고
**측정값이 조용히 일부 누락됐다.** 예외도 경고도 없었다.

## 증상

`measure/gate_replay.py`(게이트 재현 자)가 601프레임 입력에 대해
**598건만** 재현했다. 3건 차이는 `LookaheadGate` 의 창 크기(w=3)와 같아
"버퍼 지연이니 당연하다"고 읽혔고, **그 단계 세션노트에 그대로 실렸다**
(*"재현 598건"*).

그리고 원본과의 대조에서 `minor` 가 568 대 **565** 로 어긋났는데, 그것을
전부 효연 사본(`idle_ms` 미저장) 탓으로 돌렸다.

## 근본 원인

```python
while True:
    v = g.flush() if hasattr(g, "flush") else None    # flush 는 없다
    if v is None:
        break
```

`LookaheadGate` 에 있는 메서드는 **`drain()`** 이고 `flush` 는 존재하지 않는다.
`hasattr(g, "flush")` 가 항상 False 이므로 `v` 는 즉시 None 이 되고 **고리가
한 번도 돌지 않는다.** 스트림 끝의 잔여 프레임이 통째로 버려졌다.

⛔ **`hasattr` 를 쓴 의도가 정확히 이 결함을 만들었다** — "이 메서드가 없을
수도 있으니 방어하자"가 **오타를 정상 경로로 바꿨다.** `g.flush()` 를 그냥
불렀으면 `AttributeError` 로 즉시 드러났을 것이다.

## 해결

```python
for v in g.drain():
    take(v)
```

수리 뒤 재현이 601건이 되고 `minor` 가 **568 로 원본과 일치**했다. 남은
어긋남(look 22 대 25 · major 10 대 7)은 효연 사본 미저장 몫으로 좁혀졌다.

## 재발 방지

1. **`hasattr` 로 자기 코드의 메서드를 방어하지 마라.** 진짜 선택적 인터페이스
   (외부 객체·플러그인)에만 쓴다. 같은 저장소 안의 클래스는 그냥 부른다.
2. **"당연히 그럴 것"으로 설명되는 차이를 검산하라.** 598 대 601 은 창 크기와
   우연히 일치해 그럴듯했다. **그럴듯한 설명이 검증을 대신하면 안 된다.**
3. **재현 자에는 입력 수와 출력 수의 항등식을 넣어라.** `len(rows) == len(t)` 가
   아니면 경고. 이 한 줄이면 그 단계에서 잡혔다.

## 계보

이 프로젝트의 **자 26차 수리**다. 같은 계열의 앞선 것 —
재생 하네스 3중 계측 오염 사고(계측이 계측을 오염),
자 25차(크롭에 쓴 존과 기록한 존이 달랐다).

**공통점**: 셋 다 **측정 도구가 조용히 틀렸고, 그 값이 결론으로 실렸다.**
