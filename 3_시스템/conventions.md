# 자리
자리는 역할로 묻는다. 코드와 스킬에 경로를 글자로 박지 않고 `py -3 3_시스템/roles.py list`로 확인한다. 특정 노트는 이름 위키링크로 가리킨다.

- 작업 중인 것: `0_작업/<영역>/<주제>/<작업>`. 초안·docx·보고서 재료를 두고, 끝나면 승격(결과물은 원본 층 `보냄/`으로 · 앎은 `2_지식`으로)하거나 지운다. md 가 아닌 파일은 git 에 안 들어간다.
- 받은 원본: `1_수집/`(학교 자료 = `1_수집/배움/<과목>/`, 처음 받는 곳 = `1_수집/받은함`).
- 지식 노트: `2_지식/<영역>/<주제>/`. 영역은 배움·일·생활·분야다. 주제 목록은 `2_지식/주제.md`.
- 세션 기록: `2_지식/기록/`. 결정(ADR): `2_지식/일/외부뇌/결정/`. 모듈 산출물: `2_지식/modules/<모듈명>/`(설계노트는 지식 노트로).
- 진단: 외부뇌 시스템 자체는 `3_시스템/_ref/`, 프로젝트 것은 그 프로젝트 폴더의 `_ref/`.
- 파생물은 `3_시스템/_index/`: `cache/`(다시 만들면 그만) · `work/`(다시 만드는 데 비용이 듦) · `<모듈명>/` · 로그 `*.log`. 기존 `embeddings.json`·`hooks.log`·`pdf-cache/`는 경로가 코드에 박혀 있어 옮기지 않는다. 볼트 밖 파일의 경로는 기록하지 않는다. 옮겨지면 혼란만 남으니 필요할 때 다시 요청한다.
- 모듈 설명서 사본은 `3_시스템/설명서/_index/`: 원본은 모듈 폴더에 있고, 켜진 모듈 것만 `brain.py` 가 만들고 치운다. 고치려면 원본을 고친다.
- MOC·recent·open-loops·설계노트·사용자설명서는 옮기지 않는다.

# 프론트매터 스키마
층마다 표가 하나다. 값을 모르면 키만 쓰고 값은 비운다. 표의 원본은 `3_시스템/roles.json` `props`이고 옵시디언 새 노트 표와 같다.
```yaml
# 2_지식
title: 제목
created: 2026-11-02     # date 가 아니라 created
updated: 2026-11-02
tags: []
주제: 과목이름       # 주제 등록부 이름. 비우면 자리로 추정
aliases: []
links: ["[[노트]]", "[[다른노트#^id]]"]   # 위키링크는 따옴표 배열. 따옴표가 없으면 YAML 오류이고 훅이 막는다
status: active          # active | archived
source: claude          # user | claude | 수집

# 0_작업 (links·status 없음)
title: 제목
created: 2026-11-02
updated: 2026-11-02
tags: []
주제: 과목이름
마감:                   # YYYY-MM-DD[ HH:MM]
단계:                   # 수집·초안·제출·끝
의도:
aliases: []
source: claude
```
- 새 노트와 `created`가 2026-10-30 이후인 노트에 빠진 키는 커밋 때 `props-sync.py`가 채우고 표 순서로 놓는다. 그 전 노트와 속성 없는 md는 손대지 않는다.
- `updated`는 커밋 때 `props-sync.py`가 파일 수정 날짜로 적으니 값을 손으로 고치지 않는다.
- `created` 면제: MOC·recent·open-loops·profile·설계노트·사용자설명서.
- 필요할 때 표 뒤에 더한다: `type`(semantic·episodic·procedural·decision·moc·incident, 없으면 semantic) · `confidence`(verified·hypothesized, 합성·수집물은 hypothesized) · `sensitive: true`(push 제외) · `author`(수집물 게시자).
- `작업.md`: 0_작업 표 + work.py 가 읽는 `보냄`·`결과물`·`저장소`·`가지`. `단계: 끝` = 끝난 작업.

# 파일 이름과 MOC
- 파일 이름은 2_지식·`_ref` 전체에서 하나뿐이어야 한다. 위키링크가 이름으로 찾기 때문이고, 겹치면 훅이 턴을 막는다.
- `moc_notes` 묶음 자리의 노트는 프론트매터와 MOC 등재가 필요하고 훅이 검사한다. `_`로 시작하는 하위 폴더는 대상이 아니고, `modules/`는 프론트매터만 필요하다(모듈은 설계노트 한 줄로 대표).
- MOC 꼴: 영역 `##` · 주제 `###` · 한 줄 150자 이하(설명은 노트에). 찾기 색인에서 빠져 있다. 넘는 줄은 `moc.py check`로 찾는다.

# 링크와 기록
- 기본은 `[[노트명]]`. 긴 글의 한 대목을 가리킬 때는 읽는 쪽이 통독하지 않도록 `[[노트명#헤딩]]`이나 `[[노트명#^id]]`로 쓴다. 블록 id 는 대상 블록 끝줄 바로 다음 줄에 빈 줄 없이 `^id`(영숫자·하이픈)로 둔다.
- 논점이 끝나면 제목 바로 아래에 `> [!done] 종결 — <결론> (<날짜>)`를 둔다. 부분만 읽는 쪽이 옛 서술을 지금 판단으로 오해하지 않게 하기 위해서다. 옛 서술은 지우지 않고 `(→ 최상단 종결 배너 참조. 이 서술은 <날짜> 시점이다)`만 덧붙인다.
- incident: 프론트매터(`type: incident`) + `## 증상` · `## 근본원인` · `## 해결` · `## 재발방지`.

# 원본·색인
원본 형식 파일(pdf·docx·pptx·xlsx·hwp·html·영상)이 볼트의 정보원이다. 정리 노트를 따로 만들지 않아도 되도록 원본마다 색인을 붙인다.
- 원본: `1_수집/<분류>/<파일>`. 내용을 고치지 않는다. 분류는 Claude 가 옮기되 과목이 파일 이름·내용에서 분명할 때만 하고, 애매하면 `받은함`에 두고 묻는다. 복사하지 않고, 같은 sha256 이 있으면 들이지 않고 알린다.
- 색인: `1_수집/_색인/<원본 상대경로>.색인.md`. `3_시스템/ingest.py`가 만들고 다시 만들 때 덮으니 손으로 고치지 않는다. git 에 안 들어간다. 원본이 옮겨지면 해시로 다시 잇고, 원본이 없어진 색인은 고아로 알린다.
- 메모: 원본 옆 `<원본 이름>.md`(같은 이름이 둘이면 `<이름> (<확장자>).md`). 사람의 글이다. 사용자가 요청할 때만 쓰고 대본은 쓰지 않는다.
- 제출본: 제출이 확정되면 PDF 만 `1_수집/배움/<과목>/제출/`로 복사한다. docx 와 재료는 `0_작업`에 둔다.
- 받은함: `py -3 3_시스템/inbox.py`가 제안하고 `--apply`(행위 «받은함 정리»)가 확실한 것만 한다. 폴더는 통째로 옮기지 않고 안을 본다. 문서는 `<과목>/<칸>`으로 옮겨 색인한다. 재료(사진·측정·코드·영상)는 1회용이라 원본 층에 들이지 않고 작업 자리로 옮기고, 끝난 작업이 쓴 것이면 휴지통으로 보낸다. 같은 sha256 은 휴지통으로, 빈 폴더는 치운다. 받은함은 정거장이라 Claude 가 확인했으면 그 자리에서 비우고, 휴지통도 Claude 가 한다. 받은함의 재료로 작업을 시작하면 먼저 작업 폴더로 옮겨 쓴다.
- 받은함 승격: 사용자가 적은 아이디어 노트에만 쓴다. 아이디어가 Claude 에게 전달되어 가공되면 가공본을 지식 폴더에 쓰고 받은함의 노트는 지운다. 가공본에는 아이디어 노트의 원문이 들어가야 한다(요약 금지). 이 전체를 승격이라 한다. 원문이 다 들어갔는지 대조가 안 되면 받은함에 둔다. 할 일이면 open-loops 에 gist+링크를 적는다.
- git: 원본(비 md)은 올리지 않고 백업도 없다. 영상·무손실 오디오는 볼트 전역에서 제외한다.

# 볼트 행위 — fileops
볼트 안 지우기·옮기기·이름 바꾸기·들이기·덮어쓰기는 `py -3 3_시스템/fileops.py`로 한다. 셸의 rm·mv 등은 훅이 막는다. 볼트 내용을 옮기는 대본은 `import fileops`를 쓴다(`--by script:<이름>`).
- 명령: `mv <원래> <새 자리>` · `rm <경로>` · `restore <id>` · `undo <묶음 id>` · `cp <밖> <안>` · `replace <새 파일> <자리>` · `mkdir` · `archive` · `plan <json>` · `log` · `where <이름>` · `trash` · `who <경로>`(쥔 프로그램). 모두 `--why "까닭"`을 붙이고, 맨 앞 `--dry`로 미리 본다. 경로는 볼트 뿌리 기준이다.
- 옮기기·지우기는 이름 바꾸기 한 번이라 파일이 잠겨 있으면 아무것도 바뀌지 않은 채 실패하고 쥔 프로그램을 알린다.
- 원본 지우기·덮어쓰기는 지시가 있을 때 `--user-asked`로 한다. 30개 넘는 폴더를 지우면 `--count N`이 필요하다. 코어·`.obsidian`·장부·금고는 다루지 않는다.
- 장부 `3_시스템/ledger/ops.jsonl`에 남고, 지운 것은 `.trash/<날짜>/`로 간다. 휴지통 비우기(`purge`)는 사람만 한다.
- 위키링크·마크다운 링크·캔버스·짝 메모는 따라 고친다. 같은 이름이 둘 이상인 링크와 코어·코드·설정의 옛 경로는 고치지 않고 알린다.
- 기계 파생물(`_index`·`_색인`·캐시)은 장부에 남지 않는다. 옵시디언에서 한 일은 brain-base 가 기록하고, 옵시디언 밖에서 옮기거나 지운 것은 `follow.py`가 알아채 장부·링크·색인을 맞춘다.
- 이전: `3_시스템/migrations/NNNN-<이름>.json`. `fileops migrate`로 미리 보고 `--apply`로 적용, `migrate --undo <id>`로 되돌린다.

# 시험과 창
사용자는 Claude 가 일하는 동안 같은 PC 에서 일한다. 창을 띄워야 하는 시험은 사용자 화면 밖에서 돌린다(ADR-044).
- 노드 시험의 창: `quietwin.mjs` 의 `spawnQuiet`(spawn 과 같은 꼴). 그 밖의 프로그램: `py -3 3_시스템/quietwin.py run -- <명령>`. 격리 옵시디언을 `spawn(EXE…)` 로 바로 띄우지 않는다.
- 크롬·엣지는 `--headless=new`, 에뮬레이터는 `-no-window`, 오피스 COM 은 `Visible=$false`.
- 콘솔 없는 부모(`pyw`·예약 작업)에서 부르는 프로그램에는 `CREATE_NO_WINDOW` 를 준다. 노드는 `windowsHide: true`.
- 믿지 말고 잰다: `py -3 3_시스템/winwatch.py watch` 를 켜고 시험을 돌린 뒤 `report`. 입력 없이 바뀐 전경과 위로 뜬 창이 0 이어야 한다.
- 진짜 전경이 꼭 필요한 시험(마우스 흉내 등)은 사용자가 자리를 비운 때로 미루거나 말한다. 사람이 보려면 `BRAIN_SHOW_WINDOW=1`.
