# 세션 기록 확정

이번 세션이든 며칠 전 밀린 세션이든 절차는 같다. 재고 자르는 기계 일은 `3_시스템/record.py` 가 한다. recent·open-loops 를 즉석 코드로 고치지 않는다(글자 붕괴와 재실행의 원인이었다).

## 0. 대상과 수준을 먼저 정한다

**대상** — 이번 세션인가, `3_시스템/_index/.pending-sessions.txt`에 뜬 밀린 세션인가.

**수준** — 모든 세션에 노트가 필요하지 않다.

| 수준 | 언제 | 무엇을 하나 |
|---|---|---|
| **A 세션노트** | 코드·설정·시스템을 바꿔(볼트 밖 저장소 포함) 결론이 대화에만 남아 사라지는 작업 | 1~5 |
| **B recent 한 줄** | 산출물·제출물이 이미 결론 전부인 경우(보고서·계획·학습노트) | 2·3·5 |
| **C 생략** | 볼트에 아무것도 안 남긴 질의응답(문제 풀이, 단발 조사) | 없음 |

근거: 볼트 편집 0인 세션에 노트를 쓴 것은 31건 중 1건뿐이었다 → [[세션종료-자동화-설계]]. 애매하면 한 줄로 묻는다. 추측으로 A 를 고르면 쓸모없는 노트가 볼트를 늘린다.

사용자가 «넘어가»라고 하면 수준 C: `py -3 3_시스템/record.py skip <세션 id>`(영구 제외).

## 1. 세션노트 (A)

`<sessions>/YYYY-MM-DD-<주제>.md`(자리 = `py -3 3_시스템/roles.py path sessions`). `type:episodic`, 프론트매터는 `3_시스템/conventions.md` 스키마.
담을 것: **발단 · 한 것 · 산출물 · 주요 결정 · 실측 · 검증 · 미결**. 산출물 노트가 따로 있으면 복사하지 말고 링크한다.

## 2. recent (A·B)

`py -3 3_시스템/record.py recent "- YYYY-MM-DD **제목**: 한 일 · 다음 = … → [[노트]]"` — 150자 이하, 9줄로 자동 정리. 넘으면 거부되니 줄여서 다시 낸다.

## 3. open-loops (A·B)

`2_지식/open-loops.md` 를 Edit 로 고친다.
- **삭제는 이중 주체** — ①Claude 가 이번 세션에서 종결을 확인한 항목 ②사용자가 `- [x]`로 체크한 항목. 하위 불릿까지 통째 삭제한다. 확신이 없으면 지우지 말고 보고한다(원문이 링크 노트에 남아 있는지 확인 후 삭제).
- 새 미결은 `- [ ]`로 추가한다.
- 항목 2줄/300자 · 파일 6KB 까지. 매 세션 전량 주입되는 파일이라 이력을 덧붙이지 말고 gist+링크 한 항목으로 **교체**한다(상세는 세션·프로젝트 노트에).

## 4. incident (해당 시)

버그를 해결했으면 `3_시스템/_ref/`에 incident 노트(`type:incident` + 증상/근본원인/해결/재발방지).

## 5. 점검 (A·B)

`py -3 3_시스템/record.py check` — 나온 줄을 고친다.
- MOC 미등재 = 그 영역(##)·주제(###) 칸에 `[[파일명]]` 150자 이하 한 줄로 등재. 세션로그·incident 는 대상이 아니고(`_ref`는 weekly-review 몫) `modules/`는 프론트매터만 요구한다.
- 프론트매터 없는 노트는 바로 보강한다.
- Stop 훅(`stop-check.ps1`)이 같은 항목으로 종료를 막으니 여기서 먼저 처리한다.

## 밀린 세션을 뒤늦게 기록할 때

**원본 세션을 다시 열지 않는다** — 재개 1회에 in_std 약 170만이 든다. 스텁이 그걸 피하려고 있다.

1. `3_시스템/_index/stubs/<sid>.md`를 읽는다(약 in_std 5,000). `<sid>.save.md` 세이브포인트가 있으면 그것이 1차 재료다('왜' 포함).
2. 스텁에 '왜'는 없다. 결론·결정·수치가 필요하면 스텁의 `[L숫자]`가 가리키는 원본 줄만 잘라 읽는다. 한 줄이 수 MB일 수 있어 통째로 열지 않는다.
   ```bash
   py -3 -c "import itertools;print(next(itertools.islice(open(P,encoding='utf-8'),N-1,N))[:4000])"
   ```
3. 프론트매터에 `confidence: hypothesized` 와 `session: <세션 id 8자>`, 본문 첫 줄에 **"사후 재구성(스텁 기반, 원본 발췌 N곳)"**을 적는다. 표시하지 않으면 추정이 사실로 굳고 다음 요약이 그것을 근거로 삼는다.
4. 대화 기록이 이미 없으면 뼈대만 쓰고 그 사실을 적는다. 없는 '왜'를 지어내지 않는다.
5. 그 세션이 목록에서 빠지는 근거는 3의 `session:` 키다(빼먹으면 계속 뜬다). recent 한 줄만 남겼으면 `record.py skip <id>`.

## 하지 않는 것

- **커밋** — Stop 훅이 매 턴 한다.
- **`.pending-sessions.txt` 직접 편집** — `session-stub.py`가 매 턴 다시 쓴다.
- **없는 결론 채우기** — 스텁에 없고 원본에도 없으면 "미상"으로 남긴다.
