# canvas — Obsidian 캔버스 제작

**진실원본** = 2026-08-21·08-22 두 세션의 실측. 캔버스 1장을 만드는 데 든 도구호출 49건 중
**32건(65%)이 형식**이었다. 그 65%를 여기 상수와 스크립트로 고정했다. **형식을 다시 발견하지 마라.**

## 0. 먼저 — 캔버스가 맞는 형태인가 (4조건)

넷 다 통과할 때만 캔버스다. 하나라도 깨지면 **표나 산문이 이긴다.**

| 조건 | 근거 |
|---|---|
| ① 항목이 5개 이상인가 | `_inbox` 동시 적재 실측 최대 2건(7주). 2건은 산문이 낫다 |
| ② 축이 2개 이상인가 | 표는 1축. 시간순·우선순위순 나열이면 표를 써라 |
| ③ 항목이 실제 노트인가 | 임베드해 열어볼 값이 없으면(집계 숫자 등) 표가 이긴다 |
| ④ 사람이 위치로 판단을 표시할 여지가 있는가 | 없으면 Obsidian 그래프뷰로 충분하다 |

소급 적용 결과(08-22): MOC·open-loops·ADR·세션·스킬표·훅구조 **전부 탈락**, 통과 1건.
**캔버스는 드문 도구다.** 만들자는 말이 나왔다고 자동으로 맞는 게 아니다.

## 1. 절차

1. **4조건 판정.** 깨지면 그 자리에서 말하고 표를 제안한다.
2. **스펙 작성** — `<이름>.spec.json`. 픽셀을 손으로 찍지 않는다. **열·행 인덱스만 쓴다.**
3. **빌드** — `py -3 scripts/canvas-build.py <spec> <out.canvas>` (경로는 이 스킬 base 디렉터리 기준)
   끝에 `canvas-check.py`가 자동으로 돈다. 라벨 폭 경고와 필요 축척도 같이 나온다.
4. **축척 보고를 읽는다.** 본문이 12px 미만이면 안 읽힌다 — 밴드를 줄이거나 나눈다.
5. **사용자에게 열어 보게 한다.** 렌더는 내가 못 본다. ⑴ 글자 크기 ⑵ 라벨 가림 ⑶ 카드 본문 양.

스펙은 볼트에 남긴다(캔버스 옆 `_canvas/`). 다음에 고칠 때 스펙을 고쳐 다시 빌드한다.

## 2. 소유 경계 — 하드규칙

**기계 = 노드 집합 · 엣지 · 라벨 · 크기 · 그룹 박스. 사람 = `x`, `y`.**

빌더는 기존 파일에 같은 `id`가 있으면 **좌표를 절대 덮지 않는다.** 새 노드만 배치하고
스펙에서 사라진 노드만 지운다. 전면 재배치는 `--regrid`뿐이고 **승인 없이 쓰지 않는다**
(08-22에 이 경계를 넘어 손좌표 y=1510을 덮은 전례가 있다).

## 3. 측정 상수 — 왜 이 값인가

| 값 | 근거 |
|---|---|
| **카드 폭 400 통일** | 폭이 다르면 넓은 카드가 옆 열로 가는 차선을 막아 **엣지가 관통한다.** v6(파일 800/텍스트 540)에서 관통 4건 → 400 통일로 0건 |
| 텍스트 높이 220 · 파일 440 | kepano json-canvas 권고(medium text 300-450×150-300, file preview 300-500×200-400). 파일 높이만 스크롤 위해 초과 |
| 열간격 기본 120 | 라벨이 이 틈에 그려진다. `정규화 MD`가 화면 108px인데 틈이 60px이면 카드 밑으로 들어간다 |
| 열간격 상한 | **밴드 폭과 창 폭이 균형 잡히는 지점까지 공짜.** 그 너머는 축척이 가로에 묶여 글자가 작아진다. 빌더가 매번 보고한다 |
| 스냅 20 | kepano 권고 "multiples of 10 or 20" |
| 저장형식 = 노드 1줄 | Obsidian 자신의 형식. 예쁘게 들여쓰면 카드 하나만 옮겨도 283줄 전량 churn |

## 4. 렌더 사실 — 문서에 없어서 직접 잰 것

- **축소하면 텍스트카드는 `≡` 아이콘으로 무너진다.** 파일카드는 파일명을 계속 렌더한다.
  → 전체보기에서 뜻을 나르는 건 **그룹 라벨 · 파일명 · 엣지 라벨** 셋뿐. 텍스트카드 열에는 그룹 라벨을 달아라.
- **그룹 라벨은 상자 바깥 위**에 그려진다. 안쪽에 여백을 비울 필요 없다.
- **프론트매터는 기본 펼침**이고 파일카드 높이의 약 45%를 먹는다. 접는 방법은 CSS 스니펫뿐 —
  `.obsidian/snippets/canvas-card-properties.css`(설정 → 모양 → CSS 스니펫에서 켜야 적용).
  ⚠ 이 볼트에만 있다. 배포판 v0-template에는 없으므로 새 설치에서는 다르게 보인다.
- 본문 폭은 Obsidian `readable line length` 700px에 걸린다. 카드를 700보다 넓혀도 글자 줄이 안 길어진다.

## 5. 스펙 형식

```json
{
  "gap_col": 120,
  "bands":  [{"id":"gA","label":"설계한 경로 — 발동 0건","color":"1"}],
  "nodes":  [
    {"id":"n1","band":"gA","col":0,"row":0,"text":"**organize**\n코어"},
    {"id":"n2","band":"gA","col":1,"row":0,"file":"2_지식/notes/어떤노트.md"},
    {"id":"n9","band":null,"col":-1,"row":0,"file":"2_지식/notes/참조.md"}
  ],
  "groups": [{"id":"gCore","label":"코어","members":["n1"]}],
  "edges":  [{"from":"n1","to":"n2","label":"학습노트"}]
}
```

- `col`·`row`는 인덱스다. **행은 열마다 독립으로 쌓인다.** 열끼리 가로로 맞추고 싶으면 노드에 `"y"`를 직접 준다.
- `band: null` = 밴드 밖 참조 카드. 밴드 흐름을 밀지 않는다.
- `groups`는 밴드 안 중첩 그룹. 멤버 id에서 박스를 자동 계산한다.
- 엣지 방향(`fromSide`/`toSide`)은 좌표에서 자동 추론된다. 같은 열이면 세로, 다른 열이면 좌우.
- 색은 프리셋 `"1"`~`"6"` 또는 hex.

## 6. 검사기 — `canvas-check.py <파일>`

기하 7종(스키마 키·20 스냅·카드 겹침·그룹 포함·그룹 부분겹침·라벨 여백·엣지 관통)
+ kepano Validation Checklist 4종(id 중복·`type` 열거·side/end 열거·색상값).

**`CROSS`(엣지 관통)는 직선 근사다.** Obsidian은 베지어로 그리므로 과대일 수 있다 —
다만 08-22 실측에서는 맞았다(엣지 라벨이 카드에 가려진 것이 증거였다).
`어느 그룹에도 속하지 않음`은 일부러 밴드 밖에 둔 카드면 무시한다.

## 7. 안 하는 것

- **3rd-party 캔버스 플러그인** — 기각(2026-08-21). 엣지가 캔버스 파일명을 프론트매터 키로 만든다 + [[설계노트]] "플러그인 의존 0".
- **MOC·open-loops를 캔버스로 대체** — 기각. gist를 못 담고 T1 주입에서 순손실.
- **훅으로 자동 생성·갱신** — 수요 없음으로 기각(2026-08-22). 붙일 때의 본보기는
  `search.py --link-write`의 네 성질(소유 경계·멱등·색인 제외·SessionEnd 끝 fail-soft 디태치).
