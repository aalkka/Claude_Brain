# /dist-sync:publish — 이 볼트를 배포판으로

**P0 = 진단뿐이다. 파일을 하나도 고치지 않는다.** 적용은 P1 이후다.
근거·미결 → 제작자 볼트의 dist-sync 설계 노트(배포판 미포함).

## 이 방향이 어려운 이유

보존 대상이 `update`와 **정반대**다. 여기서 지켜야 하는 것은 사용자 데이터가 아니라 **익명성**이고, 그것이 네 번 새어 나갔다 — 2026-07-27 주석 실명 · 2026-08-03 실명 11곳 · 2026-09-12 2건. 배포판 규칙은 *"개인정보 전수 스캔 0건"* 이다.

## 절차

### 1. 진단

```bash
git fetch dist
py -3 .claude/skills/dist-sync/scripts/dist-diff.py --a . --b <배포판 worktree> --mode publish --out 3_시스템/_index/dist-sync/publish-<날짜>.md
```

실명·호칭·개인 저장소 이름은 스크립트에 적지 않는다(스크립트도 배포된다). 볼트마다 `3_시스템/_index/dist-sync/leak-patterns.txt`(gitignore)에 «정규식<TAB>이름» 으로 적어 두면 검사에 더해진다 — 없으면 리포트가 경고한다.

리포트가 내는 것: 층별 괴리 · 지워질 파일 · **익명화 후보** · 대상 볼트의 **치환 파손**.

### 2. 익명화 후보를 읽고 문구를 직접 쓴다

**스크립트는 찾기만 한다. 치환은 하지 않는다.** 기계 일괄치환이 `<호칭>님이`를 **`사용자이`** 로 만들었고 그것이 한 달 넘게 배포판에 남았다. 한국어 조사는 선행 음절에 결합하므로 문자열 치환으로 다룰 수 없다.

표준 어휘 — 배포판이 이미 일관되게 쓰는 것을 따른다.

| 볼트 | 배포판 |
|---|---|
| 실명·호칭(`leak-patterns.txt` 에 적은 것) | **사용자** (조사 결합을 확인하고 쓴다) |
| <호칭> 볼트 실측 · 이 볼트 실측 | **제작자 볼트 실측** |
| 세션 id(`a1b2c3d4`) | 일련번호(`세션 1`·`조사세션 A`) |
| 배포판에 없는 노트로의 `[[위키링크]]` | 서술로 풀어 쓴다 (`badLinks` 차단 회피) |

### 3. 옮기기 전에 대상의 «세대»를 확인한다

배포판 파일이 볼트보다 **여러 세대 낡아 있을 수 있다.** 2026-09-12에 배포판 `deep-loop`가 세 세대 뒤진 상태였고, 그것을 모른 채 새 개정을 얹으면 **존재하지 않는 조항을 가리키는 문서**가 된다. 목차·절 제목을 먼저 대조한다.

### 4. 커밋은 파일을 **명시적으로 나열**해서만 한다

```bash
git add <파일1> <파일2>   # ⛔ git add -u / git add . 금지
```

`git add -u`가 사용자가 보류해 둔 미커밋 변경을 함께 커밋한 사례가 있다(2026-09-12, 되돌림). 커밋 메시지 형식은 `sync(dist): <내용> (볼트 <해시> 대응)`.

### 5. 검증 — 스크립트로 다시 센다

익명화 스캔을 **재실행**해서 0건을 확인한다. 사람·Claude 의 눈으로 끝내지 않는다. 이 세션에서 grep 이 Claude 의 누락을 두 번 잡았다.

### 6. push 는 별도 승인

공개 저장소 전송이다. 커밋까지 하고 **멈춰서 확인을 받는다.**

## 하지 않는 것

- **개인 층을 배포판으로 옮기지 않는다** — `1_수집/**` · `2_지식/notes·sessions·decisions/**`(설계노트·사용자설명서 제외) · `_index/` · `_claude-memory/`.
- **일괄 치환하지 않는다.** 후보는 스크립트, 문구는 사람·Claude.
- **`git add -u`·`git add .` 를 쓰지 않는다.**
- **사용자가 보류한 미커밋 변경을 건드리지 않는다.**
- **push 를 임의로 하지 않는다.**
