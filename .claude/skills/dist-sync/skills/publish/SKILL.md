# /dist-sync:publish — 이 볼트를 배포판으로

진단 → 문구 작성 → 옮기기 → 검증 → 커밋까지 하고, push 만 별도 승인을 받는다.
근거·미결 → `외부뇌-dist-sync-모듈`(제작자 노트 · 배포판에 없음) · ADR-012.

## 이 방향이 어려운 이유

보존 대상이 `update`와 **정반대**다. 여기서 지켜야 하는 것은 사용자 데이터가 아니라 둘이다.

- **익명성** — 네 번 새어 나갔다(2026-07-27 주석 실명 · 2026-08-03 실명 11곳 · 2026-09-12 2건). 규칙 = *"개인정보 전수 스캔 0건"*.
- **범위** — 배포판에는 **배포 목록(`ship.json`)에 적힌 기능만** 싣는다. 목록 밖은 기본으로 안 싣는다. 2026-11-09~15 에 개인 프로젝트의 알림 대본·폰 사건 기록·서버 시험·제작자 측정 기록이 «코어 자리에 있다»와 «배포판 코어가 부른다»는 까닭만으로 실렸다 — 익명화 검사를 다 통과한 채로. 익명이어도 배포판 사용자에게 없는 기능이면 싣지 않는다.

## 절차

### 1. 진단

```bash
git fetch dist
py -3 .claude/skills/dist-sync/scripts/dist-diff.py --a . --b <배포판 worktree> --mode publish --out 3_시스템/_index/dist-sync/publish-<날짜>.md
```

실명·호칭·개인 저장소 이름은 스크립트에 적지 않는다(스크립트도 배포된다). 볼트마다 `3_시스템/_index/dist-sync/leak-patterns.txt`(gitignore)에 «정규식<TAB>이름» 으로 적어 두면 검사에 더해진다 — 없으면 리포트가 경고한다.

리포트가 내는 것: 층별 괴리 · 지워질 파일 · **배포 목록 밖(정할 것)** · **빼기 후보** · **익명화 후보** · 대상 볼트의 **치환 파손**. «코어 — 통째 교체 가능»에는 목록에 있는 것만 든다.

### 1-1. 범위를 정한다 — 싣기·안 싣기·빼기

```bash
py -3 .claude/skills/dist-sync/scripts/dist-check.py      # ⑤ 정할 것·빼기 후보 · ⑥ 배포판에 없는 것을 가리킴
```

항목마다 «배포판 사용자에게 이 기능이 있는가 — 부르는 쪽과 내주는 쪽이 배포판에 다 있는가»로 정한다.

- **싣는다** — `ship.json` 그 기능 칸에 경로를 더한다(새 기능이면 칸을 만든다). 여러 기능이 같이 쓰는 자리(`3_시스템/`·`_ref/`·`_eval/`·`hooks/`·`설명서/`·`tutorial/`·`.claude/skills/`)는 폴더째 적지 않는다.
- **안 싣는다**(개인 프로젝트·특정 학교·이 PC·실험·제작자 기록) — `--ack <경로> --always --why "까닭"`. 판과 상관없이 다시 안 뜬다.
- **빼기 후보**(배포판에 있는데 목록 밖) — 배포판에서 지운다. 받는 쪽은 업데이트에서 «배포판이 뺀 것 휴지통»으로 받는다(안 고친 판만 · 고친 파일은 남음). 커밋 메시지와 사용자 보고에 무엇을 왜 뺐는지 적는다.
- **⑥ 가리킴** — 실린 파일이 배포판에 없는 모듈·코드·이름을 가리킨다. 그 갈래가 없으면 꺼지는지(선택 호출) 배포판 사본에서 잰다. 꺼지면 `--ack <배포판 파일> --ref --why "까닭"` · 안 꺼지면 부르는 쪽을 고친다(그 기능이 있을 때만 보이게). 안내 글이 없는 기능을 권하면 그 줄을 고친다.
- **⑧ 모듈 계약** — 이 볼트 모듈(꺼진 것·배포판에 안 싣는 것까지)이 쓰는 코어 이름(`module.json` `uses_core`)이 배포판에 없다. 그 모듈을 배포판 꼴 볼트에 붙이면 깨진다. 그 코어를 싣거나(목록에 더함) 모듈이 그 이름 없이 돌게 고친다. 안 싣는 모듈이라도 «배포판 꼴로 범용화»(mobility)는 이것이 0 이어야 한다.
- **모르면 사용자에게.** 프로젝트가 «아직 배포 아님»인지는 Claude 가 정하지 않는다.

«배포판 코어가 부른다»(«필요 ←»)는 싣는 까닭이 아니다. 부르는 쪽이 없어도 도는지 먼저 잰다.

### 2. 익명화 후보를 읽고 문구를 직접 쓴다

**스크립트는 찾기만 한다. 치환은 하지 않는다.** 기계 일괄치환이 `<호칭>님이`를 **`사용자이`** 로 만들었고 그것이 한 달 넘게 배포판에 남았다. 한국어 조사는 선행 음절에 결합하므로 문자열 치환으로 다룰 수 없다.

표준 어휘 — 배포판이 이미 일관되게 쓰는 것을 따른다.

| 볼트 | 배포판 |
|---|---|
| 실명·호칭(`leak-patterns.txt` 에 적은 것) | **사용자** (조사 결합을 확인하고 쓴다) |
| <호칭> 볼트 실측 · 이 볼트 실측 | **제작자 볼트 실측** |
| 세션 id(`a1b2c3d4`) | 일련번호(`세션 1`·`조사세션 A`) |
| 배포판에 없는 노트로의 `[[위키링크]]` | 서술로 풀어 쓴다 (`badLinks` 차단 회피) |

### 3. 옮기기 전에 대상의 «세대»를 확인한다

배포판 파일이 볼트보다 **여러 세대 낡아 있을 수 있다.** 2026-09-12에 배포판 `deep-loop`가 세 세대 뒤진 상태였고, 그것을 모른 채 새 개정을 얹으면 **존재하지 않는 조항을 가리키는 문서**가 된다. 목차·절 제목을 먼저 대조한다.

### 3-1. 옮기기 = 3방향 합치기(볼트 판을 그대로 복사하지 않는다)

```bash
py -3 .claude/skills/dist-sync/scripts/pub_merge.py <옮길 파일 목록.txt> --dist <배포판 worktree> --old <지난 공개판 rev>          # 갈래만 셈
py -3 .claude/skills/dist-sync/scripts/pub_merge.py <목록> --dist <worktree> --old <rev> --write [--show all]                       # 씀
```

볼트 판을 그대로 복사하면 배포판에만 있는 손 익명화가 되돌아가는데 유출 검사는 꼴에 없는 표현(진단 기록 속 사람·과목·기기)을 못 잡는다(2026-11-26 · 진단 기록 30개). 대본은 파일마다 지난 공개판(손 익명화) · 볼트 이력에서 그와 가장 닮은 판(기준) · 지금 볼트 판을 합친다 — 손 고침이 없으면 볼트 판, 볼트가 안 바뀌었으면 배포판 판, 같은 줄의 두 익명화는 배포판 글. 글 아닌 파일은 맨 먼저 갈라 바이트 그대로 둔다. 종료 1 = «읽을 것»이 남음 — 그 칸을 읽고 손으로 정한다. 볼트가 낱말을 한꺼번에 바꾼 적이 있으면(호칭 → «사용자» 등) 개인화 파트 `personal/renames.json` 에 적는다.

더 좋은 길은 볼트 쪽 글을 처음부터 일반 표현으로 써서 두 판을 하나로 맞추는 것이다(§2 표준 어휘) — 맞춘 파일은 이 대본이 «바뀐 것 없음»·«그대로»로 지나간다.

### 4. 커밋은 파일을 **명시적으로 나열**해서만 한다

```bash
git add <파일1> <파일2>   # ⛔ git add -u / git add . 금지
```

`git add -u`가 사용자가 보류해 둔 미커밋 변경을 함께 커밋한 사례가 있다(2026-09-12, 되돌림). 커밋 메시지 형식은 `sync(dist): <내용> (볼트 <해시> 대응)`.

**커밋은 익명 작성자로 한다.** 배포판 worktree 는 제작자 저장소와 설정을 나눠 써서, 그냥 커밋하면 실명·메일이 공개 이력에 들어간다(2026-11-03 커밋 2개 · 파일 스캔은 이 칸을 못 본다).

```bash
git -c user.name="External Brain" -c user.email=noreply@localhost commit -m "sync(dist): ..."
```

### 5. 판 해시 표를 다시 만든다 — 커밋 뒤에

```bash
py -3 <배포판 worktree>/.claude/skills/dist-sync/scripts/dist-diff.py --build-known <배포판 worktree>
```

바뀐 표(배포판의 이 모듈 폴더 `known-hashes.json`)만 따로 커밋한다. 이 표가 사용자의 «안 고친 파일»을 가르는 근거라서, 이번 판까지 표에 들어 있어야 다음 업데이트가 이번 판을 사용자 수정으로 오해하지 않는다. 이력만 읽고 해시만 싣는다.

### 5-1. 폴더 뼈대와 받는 길 — 새 설치가 받는 꼴

```bash
py -3 .claude/skills/dist-sync/scripts/dist-diff.py --a . --b <배포판 worktree> --skeleton   # 리포트 «폴더 뼈대» 가 0 이 아닐 때
```

새 설치에 있어야 하는 빈 폴더(받은함·작업 폴더)는 개인 층 안이라 층 비교가 안 본다. `ship.json` «뼈대»(역할 이름)에 맞춰 `<자리>/.gitkeep` 을 만들고 옛 자리를 지운다 — 만든 것은 `git add`, 지운 것은 `git rm` 으로 커밋에 넣는다. 역할 자리를 옮겼으면 `3_시스템/migrations/` 에 그 줄(옮기기 + 없으면 만들기)을 넣어야 이미 쓰는 사람의 폴더가 따라온다.

README 의 받는 명령은 태그를 붙이지 않는다(기본 가지 = 최신). 태그를 새로 찍어도 README 에 적지 않는다 — 옛 태그를 받게 적어 두면 처음 받는 사람이 옛 판을 깐다(2026-11-26 · 72 커밋 뒤 판을 받게 돼 있었다).

### 5-2. 릴리스 첨부 — 실행 파일은 저장소에 싣지 않는다

받는 문 구동부 셋(`brain-key.exe` · `brain-inbox-menu.dll` · `brain-inbox-menu.msix`)은 서명 없는 실행 파일이라 저장소 밖이다(`.gitignore` · 층 = 개인). 저장소에는 해시 표 `3_시스템/door-app/release.json`(판 꼬리표 · 주소 · 크기 · sha256)만 싣고, 받는 쪽 `door.py install` 이 표와 같을 때만 놓는다.

구동부를 다시 빌드했을 때만 한다(안 바뀌었으면 건너뛴다):

```bash
py -3 <첨부 검사 대본> <구동부 폴더>                      # 글자열 유출(사용자 경로·pdb·이름·기기) 0 · 게시자 = CN=BrainInbox
py -3 3_시스템/door.py relhash <구동부 폴더> door-app-<N> <릴리스 내려받기 주소>   # release.json 다시 씀 → 볼트 커밋 → 배포판에 반영
gh release create door-app-<N> <구동부 폴더>/brain-key.exe <구동부 폴더>/brain-inbox-menu.dll <구동부 폴더>/brain-inbox-menu.msix --repo <공개 저장소> --title "받는 문 구동부 <N>" --notes "서명 없는 실행 파일 — door.py 가 sha256 을 확인한다"   # 사람 승인
```

판 꼬리표는 올릴 때마다 새 번호다 — 같은 꼬리표의 첨부를 바꿔 올리면 이미 받은 표와 어긋나 옛 판 사용자의 설치가 거절된다. 올린 뒤 `py -3 3_시스템/door.py relcheck` 가 «맞음»(종료 0)이어야 push 한다 — 표가 가리키는 첨부를 실제로 받아 크기·sha256 을 견준다. 표만 올라가고 첨부가 없으면 새 설치의 `door.py state` 가 «못 받음»이다.

글 아닌 파일(그림·wasm·번들)을 배포판에 놓을 때는 바이트 그대로 복사한다 — 줄끝을 바꾸는 길로 지나가면 깨진다(2026-11-26 · 새로 실은 실행 파일·그림 넷이 CRLF→LF 로 깨진 채 후보에 들어갔다 · 글자열 검사는 통과했다). 놓은 뒤 볼트 파일과 sha256 이 같은지 본다.

### 6. 검증 — 스크립트로 다시 센다

**새 설치로 잰다(판마다 한 번).** 배포판 후보를 빈 폴더에 `git clone` 해 README 의 설치 순서를 그대로 가고, 그 볼트에서 `brain.py doctor` · `external.py check` · 튜토리얼(사람 입력 재생)을 돌린다. 시험 볼트를 손으로 조립해 돌리는 시험은 «받은 그대로»에 없는 폴더를 못 본다.

`dist-check.py` ⑤·⑥ 이 0인지 본다(정할 것·빼기 후보·가리킴 · 목록 잘못). 익명화 스캔을 **재실행**해서 리포트의 «배포판에 남은 개인 패턴»과 «올라갈 커밋의 작성자»가 둘 다 0건인지 확인한다(«익명화 후보»는 볼트 쪽 목록이고 60건에서 잘린다). 플러그인 CSS·번들도 이 안에 든다. 커밋을 고쳐 지웠으면 커밋마다 다시 잰다 — 나중 커밋에서 지워도 옛 커밋에 남으면 공개된다. 사람·Claude 의 눈으로 끝내지 않는다. 이 세션에서 grep 이 Claude 의 누락을 두 번 잡았다.

`dist-check.py` ⑨(지금 배포판 트리에 남은 개인 값 · 개인 꼴 파일이 실렸나)와 ⑩ «올릴 커밋»(파일·커밋 글·작성자)이 0인지 본다. 꼴 = 내장(메일·홈 경로·세션 id) + 볼트 전용 `leak-patterns.txt`·`mobility-leak.txt`·바꿈 짝 + **자동 꼴**(개인 층에서 만든 작업 세션 이름·수집 출처 id·과목 이름·작업 폴더 경로 · `leak-auto.txt` 로 보인다). 배포판이 일부러 쓰는 값은 `leak-allow.txt`(개인 층 · 까닭과 함께)에 적는다. ⑩ «이미 공개된 이력»은 목록만 — 고치려면 이력을 다시 써 강제 push 해야 하고 그것은 사람이 정한다. 그림(png·jpg)은 글자를 OCR(`3_시스템/ingest.py`)로 뽑아 같은 꼴에 댄다(배터리면 안 잼).

### 6-1. push 전 한 번 — 개인 맥락 읽기(사용량 듦)

꼴은 «사람 말 인용·일정·과목·기기·개인 사정»처럼 값이 정해지지 않은 맥락을 못 잡는다. push 할 커밋이 다 모이면 한 번만 부른다.

```
py -3 .claude/skills/dist-sync/scripts/context_read.py --dry        # 읽을 줄 수(부르지 않음)
py -3 .claude/skills/dist-sync/scripts/context_read.py              # 원격 짝..HEAD + 커밋 안 한 고침 · 기본 sonnet
```

### 8. 남은 어긋남을 센다

```bash
py -3 .claude/skills/dist-sync/scripts/dist-check.py --fetch
```

목표는 **«정할 것 0»** 이다 — 항목마다 싣기·안 싣기·빼기를 정했다는 뜻이지 다 실었다는 뜻이 아니다. «안 올린 고침»(①)은 목록 안의 것만 든다. 항목 뒤의 까닭으로 가른다.

- **«필요 ←»**(배포판 코어가 부르는데 배포판에 없음) — 싣는 까닭이 아니다. 그 기능이 목록에 있으면 싣고, 없으면 부르는 쪽이 없어도 도는지 재서 고친다. «안 싣기로 했는데 배포판이 부름»도 같다.
- **«익명화할 곳 N»·«안내 없는 바깥 설정 N»·«층 미정»** — 그것을 풀고 싣는다. 이번에 못 풀면 남겨 둔다(아직 — 건강 줄에 남는 것이 맞다).
- **일부러 안 싣는 것**(개인·특정 학교·이 PC·실험) — 목록 밖 코어는 `--ack <경로> --always --why "까닭"`(자리째). 목록 안 파일의 이번 판만 안 싣는 것(익명화한 배포판 판 등)은 `--ack <경로> --why` — 다시 고치면 다시 잡힌다. 새 플러그인은 폴더째(`.obsidian/plugins/<id>`) 적는다.
- **층 규칙 밖 자리**(옵시디언 설정·스니펫·새 플러그인·씨앗 머리말·시스템 문서) — dist-diff 가 옮기지 않는다. 실을 것은 배포판의 그 파일을 손으로 고치고(익명화), 개인 값만 다른 것은 ack 한다.

적은 것과 까닭은 `--acks` 로 본다(«까닭 없음»이 많으면 다음 배포 때 채운다). push 를 기다리는 동안은 «push 안 함»이 건강 줄에 남는 것이 맞다.

## 하지 않는 것

- **배포 목록 밖 코어를 싣지 않는다** — 목록에 더하는 것이 싣는 결정이다. 익명화 검사 통과·«필요 ←»·«안 올린 고침 0» 은 싣는 까닭이 아니다.
- **개인 층을 배포판으로 옮기지 않는다** — `1_수집/**` · 역할 `notes`·`sessions`·`decisions`·`modules`·`canvas` 자리(설계노트·사용자설명서 제외 · 목록 = `dist-diff.py` `PERSONAL`) · `_index/` · `_claude-memory/`.
- **일괄 치환하지 않는다.** 후보는 스크립트, 문구는 사람·Claude.
- **`git add -u`·`git add .` 를 쓰지 않는다.**
- **사용자가 보류한 미커밋 변경을 건드리지 않는다.**
- **push 를 임의로 하지 않는다.**
