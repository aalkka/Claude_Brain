# /dist-sync:update — 배포판을 이 볼트로

**P1(2026-10-29 · 볼트 개혁 R3)**: 코어 · CLAUDE.md(§0 보존) · 이전(migration) · 배포 플러그인을 **승인 1번 뒤** 적용한다. 볼트 내용을 바꾸는 것은 배포판의 `3_시스템/fileops.py`(옛 판은 휴지통 · 장부 · 묶음 하나로 되돌리기). 씨앗·미분류는 아직 손으로.
배포판에 `3_시스템/fileops.py` 가 없으면(개혁 전 판) **P0 — 진단만** 하고 «이 배포판은 적용 장치가 없습니다»라고 끝낸다.
근거·미결 → [[외부뇌-dist-sync-모듈]] · ADR-012 · ADR-018 · [[외부뇌-볼트개혁-로드맵]] R3.

## 왜 `git pull`을 쓰지 않는가

배포판이 추적하는 파일 중 **사용자가 매일 쓰는 6개가 함께 추적된다** — `recent.md`·`open-loops.md`·`MOC.md`·`profile.md`·`CLAUDE.md`·`config.json`. git은 로컬 수정이 있으면 덮어쓰지 않고 **충돌을 낸다.** 손상보다 **마비**가 먼저 온다. 그래서 파일 단위가 아니라 층 단위로 옮긴다.

## 절차

### 1. 배포판을 가져온다 (읽기만)

```bash
git fetch dist && git worktree add <임시경로> dist/main
```

원격이 없으면 사용자에게 배포판 위치를 묻는다. **`git pull`·`git merge`를 이 볼트에 실행하지 않는다.**

### 2. 진단 + 계획 + 미리 보기 (아무것도 안 바뀐다)

```bash
py -3 <배포판>/.claude/skills/dist-sync/scripts/dist-diff.py --a <배포판> --b . --mode update --out 3_시스템/_index/dist-sync/update-<날짜>.md --plan-out 3_시스템/_index/dist-sync/update-plan.json
py -3 <배포판>/3_시스템/fileops.py --vault . update 3_시스템/_index/dist-sync/update-plan.json
py -3 <배포판>/3_시스템/fileops.py --vault . migrate
```

**배포판 쪽 대본을 돌린다.** 이 볼트의 대본은 옛 판이라 새 판이 들인 규칙(거둔 플러그인·새 층 분류·새 이전)을 모른다.
계획 = 코어 중 없거나 다른 것 + CLAUDE.md(배포판 본문에 이 볼트 §0 을 끼운 합본). 씨앗·미분류·배포 플러그인은 계획 밖이다.

### 3. 사람이 읽을 형태로 요약해 보인다

반드시 앞에 세우는 것:

- **바뀔 코어 N개**(목록) · CLAUDE.md = «배포판 본문 + 내 §0».
- **사용자가 고친 코어도 새 판으로 바뀐다** — 진단은 사용자 수정과 배포판 변경을 가르지 못한다(공통 조상 3자 비교는 아직). 그래서 옛 판은 지우지 않고 휴지통(`.trash/<날짜>/…`, 30일)에 둔다.
- **이전(migration)** 이 있으면 무엇이 어디로 가는지 · 코드에 남는 옛 경로 알림.
- **배포 플러그인 교체 계획**(리포트 끝) · 옵시디언을 닫아야 한다.
- **손으로 할 것**: «미분류»·씨앗 차이·계획의 `notes`. 지워질 파일은 계획에 없다(배포판이 지운 것인지 이 볼트가 만든 것인지 가르지 못하므로).

### 4. 승인 1번 → 적용 (옵시디언을 닫고)

```bash
py -3 <배포판>/3_시스템/fileops.py --vault . update 3_시스템/_index/dist-sync/update-plan.json --apply
py -3 <배포판>/.claude/skills/dist-sync/scripts/dist-diff.py --a <배포판> --b . --apply-plugins
py -3 3_시스템/fileops.py migrate --apply
```

- 첫 줄에서 코어 게이트가 **한 번** 묻는다(파일마다 묻지 않는다 — 승인 피로 해소). 승인은 3단계 요약을 본 사람이 한다.
- 플러그인 교체: 배포 플러그인 폴더를 배포판과 같게 · 거둔 플러그인 파일 지우기 · 켜짐 목록 조정. **`data.json`(사용자 설정)은 어느 쪽도 건드리지 않는다.** 배포판에 들일 플러그인이 없으면 거두기도 하지 않는다. 옵시디언이 켜져 있으면 멈춘다(종료 코드 3). 금고 층 2(플러그인 폴더 관리자 전용)가 있는 볼트는 관리자 설치기로.
- 이전은 업데이트로 들어온 `3_시스템/migrations/` 의 밀린 것만 돈다 · 이미 된 행위는 건너뛴다.
- 다시 돌려도 같다 — 두 번째 진단의 계획은 0건이다.

### 5. 보고

- 업데이트 묶음 id · 되돌리기 = `py -3 3_시스템/fileops.py undo <묶음 id>`(바뀐 코어를 옛 판으로 · 새 파일은 휴지통) · 이전 되돌리기 = `py -3 3_시스템/fileops.py migrate --undo <이전 id>`.
- 손으로 할 것 목록 · 임시 worktree 정리(`git worktree remove <임시경로>`).

## 층 (근거 = ADR-012)

| 층 | 무엇 | 적용 시 동작 |
|---|---|---|
| **코어** | `.claude/skills/**` · `settings.json` · `hooks/**` · `search.py` · `session-stub.py` · `conventions.md` · `_ref/**` · `_eval/**` · `fileops.py` · `migrations/**` · `ingest.py` … | **P1: 교체(옛 판 = 휴지통)** · 삭제 반영은 공통 조상 비교 전까지 안 함 |
| **씨앗** | `recent.md` · `open-loops.md` · `MOC.md` · `profile.md` · `config.json` · 설계노트 · 사용자설명서 | 머리말만 갱신 · 항목 보존 — **아직 손으로** |
| **`CLAUDE.md`** | — | **P1: §0 보존 · 나머지 교체**(합본) |
| **개인** | `1_수집/**` · 역할 `notes`·`sessions`·`decisions` 자리 · `_index/` · `_claude-memory/` · `ledger/` · `장부.md` | **열지 않는다** — 구조가 바뀌면 이전(migration) 파일이 행위 목록으로만 다룬다 |

씨앗 규칙의 근거는 **표본 2건**이다(초판→현재에서 `open-loops.md`는 머리말만 바뀌고 항목 변경 0, `recent.md`는 머리말 한 줄). 항목이 바뀐 개정을 만나면 **멈추고 보고한다** — 규칙이 깨진 것이다.

## 하지 않는 것

- **개인 층을 열지 않는다.** 목록조차 만들지 않는다(이전 파일의 행위만 그 자리를 다룬다).
- **영구로 지우지 않는다.** 바뀌는 코어의 옛 판은 휴지통으로. 배포판이 지운 파일의 반영은 공통 조상 비교가 생길 때까지 하지 않는다. 예외 = 배포 플러그인 교체(4단계 · 승인 뒤).
- **`git pull`·`git merge`·`git checkout`을 이 볼트에 쓰지 않는다.** 사용자 데이터가 있는 작업 트리다.
- **승인 없이 `--apply` 하지 않는다.** 미리 보기 → 3단계 요약 → 승인 → 적용.
- **커밋하지 않는다.** 자동 커밋 훅이 남긴다.
