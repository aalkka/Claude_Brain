# /dist-sync:update — 배포판을 이 볼트로

**P0 = 진단뿐이다. 파일을 하나도 고치지 않는다.** 적용은 P1 이후이고 아직 열려 있지 않다.
근거·미결 → 제작자 볼트의 dist-sync 설계 노트(배포판 미포함).

## 왜 `git pull`을 쓰지 않는가

배포판이 추적하는 파일 중 **사용자가 매일 쓰는 6개가 함께 추적된다** — `recent.md`·`open-loops.md`·`MOC.md`·`profile.md`·`CLAUDE.md`·`config.json`. git은 로컬 수정이 있으면 덮어쓰지 않고 **충돌을 낸다.** 손상보다 **마비**가 먼저 온다. 그래서 파일 단위가 아니라 층 단위로 옮긴다.

## 절차

### 1. 배포판을 가져온다 (읽기만)

```bash
git fetch dist && git worktree add <임시경로> dist/main
```

원격이 없으면 사용자에게 배포판 위치를 묻는다. **`git pull`·`git merge`를 이 볼트에 실행하지 않는다.**

### 2. 진단

```bash
py -3 .claude/skills/dist-sync/scripts/dist-diff.py --a <배포판> --b . --mode update --out 3_시스템/_index/dist-sync/update-<날짜>.md
```

### 3. 리포트를 사람이 읽을 형태로 요약해 보인다

반드시 앞에 세우는 것 셋:

- **지워질 파일 목록** — 승인 없이는 어떤 경우에도 실행하지 않는다.
- **«미분류» 항목** — 층 규칙에 없는 파일이다. 분류를 정하기 전에는 옮기지 않는다.
- **«내용 다름»에 사용자 자신의 수정이 섞여 있을 수 있다** — 현재 진단은 그것을 구분하지 못한다(공통 조상 3자 비교가 P1 과제).

### 4. 여기서 멈춘다

P0의 산출물은 리포트다. *"적용은 아직 열려 있지 않습니다"* 라고 말하고 끝낸다.

## 층

| 층 | 무엇 | 적용 시 동작(P1~) |
|---|---|---|
| **코어** | `.claude/skills/**` · `settings.json` · `hooks/**` · `search.py` · `session-stub.py` · `conventions.md` · `_ref/**` · `_eval/**` | 교체 + 삭제 반영 |
| **씨앗** | `recent.md` · `open-loops.md` · `MOC.md` · `profile.md` · `config.json` · 설계노트 · 사용자설명서 | **머리말만 갱신 · 항목 보존** |
| **`CLAUDE.md`** | — | **§0 보존 · 나머지 교체** |
| **개인** | `1_수집/**` · `2_지식/notes·sessions·decisions/**` · `_index/` · `_claude-memory/` | **열지 않는다** |

씨앗 규칙의 근거는 **표본 2건**이다(초판→현재에서 `open-loops.md`는 머리말만 바뀌고 항목 변경 0, `recent.md`는 머리말 한 줄). 항목이 바뀐 개정을 만나면 **멈추고 보고한다** — 규칙이 깨진 것이다.

## 하지 않는 것

- **개인 층을 열지 않는다.** 목록조차 만들지 않는다.
- **파일을 지우지 않는다.** 삭제는 목록 제시 → 승인 → P1에서만.
- **`git pull`·`git merge`·`git checkout`을 이 볼트에 쓰지 않는다.** 사용자 데이터가 있는 작업 트리다.
- **커밋하지 않는다.** 진단은 읽기 전용이다.
