# /dist-sync:update — 배포판을 이 볼트로

**P1(2026-10-29 · 볼트 개혁 R3 · 판 해시 표 2026-11-03)**: 코어 · CLAUDE.md(§0 보존) · 이전(migration) · 배포 플러그인을 **승인 1번 뒤** 적용한다. 볼트 내용을 바꾸는 것은 배포판의 `3_시스템/fileops.py`(옛 판은 휴지통 · 장부 · 묶음 하나로 되돌리기). **사용자가 고친 파일은 덮어쓰지 않는다** — 합치고, 못 합치면 그대로 두고 묻는다.
배포판에 `3_시스템/fileops.py` 가 없거나 계획이 «판 해시 표가 없다»고 멈추면 **진단만** 하고 «이 배포판은 적용 장치가 없습니다»라고 끝낸다.
근거·미결 → [[외부뇌-dist-sync-모듈]] · ADR-012 · ADR-018 · ADR-030 · [[외부뇌-볼트개혁-로드맵]] R3.

## 왜 `git pull`을 쓰지 않는가

배포판이 추적하는 파일 중 **사용자가 매일 쓰는 6개가 함께 추적된다** — `recent.md`·`open-loops.md`·`MOC.md`·`profile.md`·`CLAUDE.md`·`config.json`. git은 로컬 수정이 있으면 덮어쓰지 않고 **충돌을 낸다.** 손상보다 **마비**가 먼저 온다. 그래서 파일 단위가 아니라 층 단위로 옮긴다.

## 절차

### 1. 배포판을 가져온다 (읽기만)

```bash
git fetch dist && git worktree add <임시경로> dist/main
```

원격이 없으면 사용자에게 배포판 위치를 묻는다. **`git pull`·`git merge`를 이 볼트에 실행하지 않는다.**

### 2. 진단 + 계획 + 미리 보기 (아무것도 안 바뀐다)

```bash
py -3 <배포판>/.claude/skills/dist-sync/scripts/dist-diff.py --a <배포판> --b . --mode update --out 3_시스템/_index/dist-sync/update-<날짜>.md --plan-out 3_시스템/_index/dist-sync/update-plan.json
py -3 <배포판>/3_시스템/fileops.py --vault . update 3_시스템/_index/dist-sync/update-plan.json
py -3 <배포판>/3_시스템/fileops.py --vault . migrate --from <배포판>/3_시스템/migrations
```

**배포판 쪽 대본을 돌린다.** 이 볼트의 대본은 옛 판이라 새 판이 들인 규칙(거둔 플러그인·새 층 분류·새 이전)을 모른다.
계획의 근거 = 배포판의 판 해시 표(이 모듈 폴더의 `known-hashes.json`). 이 볼트의 코어 파일을 과거 공개 판의 해시와 견준다.

| 이 볼트의 파일 | 계획 |
|---|---|
| 없음 | 새로 넣음 |
| 과거 판과 같음(안 고침) | 새 판으로 바꿈 |
| 과거 판과 다름(사용자가 고침) | 내 수정과 합침 · 못 합치면 **그대로 두고** `conflicts` 로 알림 |
| 배포판이 뺐고 과거 판과 같음 | 휴지통으로 |
| 배포판이 뺐는데 사용자가 고침 | 남기고 `kept` 로 알림 |
| 표에 없는 경로(사용자가 만듦) | 손대지 않음 |

합치는 법: `.gitignore`·`.gitattributes` = 양쪽 줄을 다 남김 · `.json` = 값 단위(사용자가 더한 키·항목을 살리고, 둘 다 바꾼 값은 사용자 것) · 나머지 = 3자 합치기(`.py` 는 문법 확인까지) · CLAUDE.md = §0 은 이 볼트 것 그대로, §0 밖은 같은 방식으로. 줄바꿈 차이는 고친 것으로 치지 않는다.

### 3. 사람이 읽을 형태로 요약해 보인다

리포트 맨 위 «이 업데이트가 할 일»이 원본이다. 반드시 앞에 세우는 것:

- **⛔ 못 합친 파일**(`conflicts`) — 이 파일들은 옛 판으로 남아 다른 코어와 어긋날 수 있다. 파일마다 ①그대로 둠 ②새 판으로 ③Claude 가 두 판을 읽어 합친 안을 보임 중에서 사람이 고른다. 새 판 = 항목의 `new` 경로.
- **내 수정과 합친 파일**(목록) · **바뀔 코어 N개** · CLAUDE.md = «배포판 본문 + 내 §0».
- **배포판이 뺀 파일**(휴지통으로 가는 목록) · **없던 씨앗**(넣는 목록).
- **이전(migration)** 이 있으면 무엇이 어디로 가는지 · 옵시디언 설정(책갈피·그래프·열린 탭)도 함께 고친다는 것 · **사용자 쪽에 남는 옛 경로**(기억·플러그인 설정·사용자 대본 — 고치지 않고 목록만).
- **배포 플러그인 교체 계획**(리포트 끝) · 옵시디언을 닫아야 한다 · 처음 들어오는 플러그인은 지금 배치·기본 탐색기를 바꾸지 않는다(켜는 것은 사람이).
- **손으로 할 것**: «미분류»·씨앗 머리말 차이·계획의 `notes`.
- **새 기능 단계 N개** — 배포판 `3_시스템/options.registry.json`·모듈 `contributes.options` 의 id 중 이 볼트 `3_시스템/options.local.json` 의 `levels` 에 없는 것(파일이 없으면 «처음 — 전체 추천»). 적용 뒤 옵시디언을 켜기 전에 추천한다는 한 줄.

### 4. 승인 1번 → 적용 (옵시디언을 닫고)

```bash
py -3 <배포판>/3_시스템/fileops.py --vault . update 3_시스템/_index/dist-sync/update-plan.json --apply
py -3 <배포판>/.claude/skills/dist-sync/scripts/dist-diff.py --a <배포판> --b . --apply-plugins
py -3 3_시스템/fileops.py migrate --apply
```

- 첫 줄에서 코어 게이트가 **한 번** 묻는다(파일마다 묻지 않는다 — 승인 피로 해소). 승인은 3단계 요약을 본 사람이 한다.
- 플러그인 교체: 배포 플러그인 폴더를 배포판과 같게 · 거둔 플러그인 파일 지우기 · 켜짐 목록 조정. **있는 `data.json`(사용자 설정)은 건드리지 않는다.** 없는 brain-base 에는 처음 설정을 만들어 지금 배치·기본 탐색기를 지킨다. 배포판에 들일 플러그인이 없으면 거두기도 하지 않는다. 옵시디언이 켜져 있으면 멈춘다(종료 코드 3). 금고 층 2(플러그인 폴더 관리자 전용)가 있는 볼트는 관리자 설치기로.
- 이전은 업데이트로 들어온 `3_시스템/migrations/` 의 밀린 것만 돈다 · 이미 된 행위는 건너뛴다 · 새 자리에 같은 이름 폴더가 있으면 덮지 않고 그 안으로 들어간다.
- 못 합친 파일을 사람이 정했으면: `{"version": "손으로", "ops": [{"op": "put", "rel": "<경로>", "src": "<새 판 또는 합친 파일>", "why": "사람이 고름"}]}` 을 저장하고 `py -3 <배포판>/3_시스템/fileops.py --vault . update <그 파일> --apply`(옛 판 = 휴지통).
- 다시 돌려도 같다 — 두 번째 진단의 계획은 0건이다(못 합친 파일은 계속 `conflicts` 로 뜬다).
- **적용 뒤 · 옵시디언을 켜기 전 = 기능 단계 추천**: `options` 스킬 절차 — 고른 값 파일이 없으면 전체(볼트개혁을 처음 받는 사람) · 있으면 `--new-only`(고른 값은 안 건드림). 확정 전에는 새 기능이 높음으로 돈다 — 저사양에서 켜자마자 느려지기 전에 정하게 한다. 건너뛰면 지금처럼 높음.

### 5. 보고

- 업데이트 묶음 id · **되돌리기 = 이전 먼저, 그다음 업데이트**: `py -3 3_시스템/fileops.py migrate --undo <이전 id>` → `py -3 <배포판>/3_시스템/fileops.py --vault . undo <묶음 id>`(바뀐 코어를 옛 판으로 · 새 파일은 휴지통). 되돌린 노트의 경로 링크는 표기만 긴 경로로 남을 수 있다(링크는 유효).
- **`git reset --hard` 로 되돌리지 않는다** — md 아닌 원본은 git 밖이라 안 돌아오고 노트만 돌아가 어긋난다. 이전 뒤 `git status` 에 개인 층 경로가 보이는 것은 정상이다.
- 찾기 색인은 옛 자리를 가리킨다 — `py -3 3_시스템/brain.py run search.reindex` 를 권한다(몇 분 걸림 · 사람에게 묻고).
- 손으로 할 것 목록 · 임시 worktree 정리(`git worktree remove <임시경로>`).

## 층 (근거 = ADR-012)

| 층 | 무엇 | 적용 시 동작 |
|---|---|---|
| **코어** | `.claude/skills/**` · `settings.json` · `hooks/**` · `search.py` · `session-stub.py` · `conventions.md` · `_ref/**` · `_eval/**` · `fileops.py` · `migrations/**` · `ingest.py` … | **안 고친 파일 = 교체(옛 판 = 휴지통)** · 고친 파일 = 합침, 못 합치면 그대로 · 배포판이 뺀 파일 = 안 고친 것만 휴지통 |
| **씨앗** | `recent.md` · `open-loops.md` · `MOC.md` · `profile.md` · `config.json` · `주제.md` · `보존.md` · 설계노트 · 사용자설명서 | 덮어쓰지 않음 · 뿌리 칸에 없는 것만 넣음 · 머리말 갱신은 **아직 손으로** |
| **`CLAUDE.md`** | — | **§0 보존 · 나머지 교체**(합본) · §0 밖을 고쳤으면 합침, 못 합치면 그대로 |
| **개인** | `1_수집/**` · `2_지식` 의 나머지 · `_index/` · `_claude-memory/` · `ledger/` · `장부.md` · 플러그인 `data.json` | **내용을 바꾸지 않는다** — 구조가 바뀌면 이전(migration) 파일이 옮기고 경로 링크만 고친다 |

씨앗 규칙의 근거는 **표본 2건**이다(초판→현재에서 `open-loops.md`는 머리말만 바뀌고 항목 변경 0, `recent.md`는 머리말 한 줄). 항목이 바뀐 개정을 만나면 **멈추고 보고한다** — 규칙이 깨진 것이다.

## 하지 않는 것

- **개인 층을 열지 않는다.** 목록조차 만들지 않는다(이전 파일의 행위만 그 자리를 다룬다).
- **사용자가 고친 파일을 덮어쓰지 않는다.** 합치거나 그대로 둔다. 표에 없는 경로는 사용자가 만든 것이라 손대지 않는다.
- **영구로 지우지 않는다.** 바뀌는 코어의 옛 판과 배포판이 뺀 파일은 휴지통으로. 예외 = 배포 플러그인 교체(4단계 · 승인 뒤).
- **`git pull`·`git merge`·`git checkout`을 이 볼트에 쓰지 않는다.** 사용자 데이터가 있는 작업 트리다.
- **승인 없이 `--apply` 하지 않는다.** 미리 보기 → 3단계 요약 → 승인 → 적용.
- **커밋하지 않는다.** 자동 커밋 훅이 남긴다.
