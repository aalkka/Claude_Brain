# rules-lib — 설계규율 라이브러리 (설계조력의 씨앗)

`/module-forge:new`의 설계 인터뷰가 구동하는 질문·체크리스트. 외부뇌와 부속 프로젝트의 축적경험(11방법론)과 A4b 4수단을 캡슐화. "설계부터 오류를 잡아내며 빌드"(원안)의 실체.

> P3 완성판(2026-07-27). §A·B·C = P1 씨앗, **§D·E = 실모듈 2개(실험 모듈 1 + 실사용 모듈 1) 도그푸드로 측정된 것만** 추가. 여전히 투기적 확장 금지(측정우선 D2). 아래 "실측"은 전부 제작자 볼트에서 난 것이고, 그 모듈들은 배포판에 포함되지 않으므로 경위만 요약해 실었다.

---

## A. 설계조력 4수단 (A4b — 능동 co-design, 자동 아님)

### A1. 분해·경계·인터페이스 co-design
경계를 어디 그을지 **후보를 제시하고** 사용자가 판단. 휴리스틱:
- **응집(Parnas 정보은닉)**: 같은 개념·이름·데이터를 공유하는 것끼리 한 모듈. "이 둘은 같이 바뀌나?" → yes면 한 모듈, no면 분리.
- **인터페이스 우선**: 구현 전 인터페이스(입력/출력/부작용)를 먼저 정의. 변경에 둔감한 계약을 노출.
- **단방향 의존**: A→B는 되지만 A↔B(순환)는 금지. `dependencies`로 선언, `check`가 순환 차단.
- 질문: "이 기능, X와 Y로 나누는 게 어떤가?" / "이건 새 모듈인가, 기존 모듈의 스킬인가?" / "무엇을 계약으로 노출하고 무엇을 감추나?"

### A2. 효율 로드맵 (riskiest-first)
모듈마다 **가장 불확실한 것부터** 걷어내는 순서:
1. **아키텍처 스파이크**(폐기용): 최대 리스크 가정을 최소 프로토타입으로 런타임 검증.
2. **워킹 스켈레톤 / tracer bullet**: 전 레이어 관통하는 가장 얇은 end-to-end 한 줄기.
3. **수직 슬라이스**: 기능 하나를 끝까지 관통, 하나씩 인도.
4. 각 phase에 **DoD 게이트**(산출물 ≠ 통과). module-forge 자신의 로드맵(§트랙A)이 본보기.

### A3. 예방접종 (postmortem-driven preflight)
설계 시점에 과거 인시던트·결정을 소환 → 신규 모듈용 preflight 체크리스트 자동 생성.
- 소스: `3_시스템/_ref/`(외부뇌 인시던트) + 프로젝트 `_ref/` + `2_지식/decisions/`(ADR).
- 방법: 모듈 성격 키워드로 `search` → 관련 `## 재발방지` 섹션 재사용. "이 류 모듈은 X 함정 자주 남."
- 근거: postmortem = 같은 카테고리 재발 차단 · 항공 preflight · 자동화 > 인간기억.
- 한계(정직): cold start(초기 인시던트 적음) → 기존 `_ref`(예: CP949·정합퇴화) + 웹 common-pitfall로 시드, 축적되며 강화.
- **외부뇌 §9 '_ref 생존 인프라(버그 시 먼저 검색)'를 debug시점 → 설계시점으로 당김.**

### A4. 결정 기록 (ADR)
왜 이 경계·인터페이스·스코프인지 `2_지식/decisions/`에 기록. 나중 "왜 이렇게 했지" 복원. 최소 1건/모듈.

## B. §2 11방법론 체크리스트 (설계 인터뷰 게이트)

- [ ] **1. 측정 우선** — 측정 전 아키텍처 금지. 불확실하면 스파이크부터.
- [ ] **2. 연구/전문자료 우선** — 추론 대신 근거. 재발명 전 기존 것 조사.
- [ ] **3. 원안 보존** — 사용자 원안 verbatim 유지 후 그 위에 구조. 요약 ≠ 원문 대체.
- [ ] **4. 비판적 리스크 섹션** — 낙관 프레임 거부. "리스크가 본체" 섹션 필수.
- [ ] **5. 단계 로드맵 + 완료 관문** — P0~Pn, 각 DoD 게이트. 산출물 존재 ≠ 통과.
- [ ] **6. 스코프 가지치기 + DEFERRED 창고** — 잘라도 복원조건과 함께 보존.
- [ ] **7. 하드코딩 금지 = config 외부화** — 파라미터는 코드 밖. 모듈별 격리(코어 config 불가침).
- [ ] **8. 진짜 차별점 검증** — "직접 쓰기 대비 차별점" 필수. 재발명 회피.
- [ ] **9. 결정론 훅** — 강제는 규약(모델 의존)이 아니라 훅으로. 단 예약훅(I2) 금지.
- [ ] **10. 의존 그래프 + phase순 목차 + 설치검증 게이트**.
- [ ] **11. 문서-코드 쌍둥이, 코드가 진실원본** — 어긋나면 코드 우선.

## C. 설계 인터뷰 최소 질문 세트 (`new`가 물음 — P1 축약 3~5문)
1. **무엇 / fit**: 이 모듈이 하는 일 한 줄. 외부뇌 어디에 붙나?
2. **진짜 차별점**: 기존 스킬·직접작업 대비 왜 별도 모듈인가?(§8) 재발명이면 중단.
   **7단 사다리를 순서대로 내려가며 확인**(ponytail 차용 — MIT / DietrichGebert): ①존재할 필요 있나(YAGNI) → ②이미 있나 → ③표준 라이브러리 → ④플랫폼 네이티브 → ⑤이미 깔린 의존성 → ⑥한 줄 → ⑦그제야 최소구현.
   **⑦에 닿기 전에 멈추면 그게 답이다.** 실증(2026-08-04): 외부 저장소 5종을 하베스트 조사했더니 전부 ①·②에서 걸려 채택 0건이었다.
3. **분해·경계 제안**(A1): 후보 경계 제시 → 스킬 몇 개로 나눌지, 무엇을 계약으로 노출할지.
4. **스코프 P0~**: riskiest-first 로드맵 골격 + P0 DoD(A2).
5. **touches**: 쓰는 볼트 경로(파생은 `_index/<모듈명>/` 강제). `1_수집` 침범 = 즉시 거부.

→ 답을 모으면 `module-note.md.tmpl`로 볼트 설계노트 생성 + MOC 등재 + ADR 1건 + `preflight` 시드.

## D. 경계 휴리스틱 — 실측판 (모듈 2개 도그푸드 산출)

### D1. 어댑터 경계 (학습보조 모듈 실증 — 1순위 후보)
입력 형태가 여럿인데 **처리는 하나**면: **코어 1개 + 입출력 플러그블 스킬**, 계약 = 마크다운.
- 예: `organize`(코어) ← `ingest-vision`[필기] · `ingest-lecture`[영상] → `illustrate`[도해] · `mock-exam`[시험지].
- **왜 통했나(실측)**: 그 모듈이 방향전환(카드→자료정리)했는데 **모듈 골격은 무수정으로 흡수**. 어댑터 경계는 "무엇을 만드나"가 바뀌어도 안 깨진다.
- 반대 신호: 입력마다 처리가 다르면 어댑터 아님 → 별도 모듈.

### D2. 실험 모듈 ≠ 실모듈 (조기추상화 방지 — 실측 손해)
실험 모듈이 방향전환하자 **측정된 마찰점 6건 중 절반이 무효화**. ⇒ **실험 모듈이 낳은 요구로 툴을 심화하지 마라.** 심화는 실모듈 2개 이상에서 같은 통증이 반복될 때(rule of three).

### D3. 선언은 썩는다
`surfaces`·`touches`는 손으로 쓴 순간부터 실물과 어긋난다(실측: 실사용 모듈이 스킬 하나를 추가한 뒤 선언을 갱신하지 않았다). ⇒ **선언 ↔ 실물 대조는 사람이 아니라 툴이** (`check --sync-surfaces`). 모듈 설계 시 "이 선언을 누가 갱신하나"를 물어라.

### D4-0. 산출물 폴더 = `2_지식/modules/<모듈명>/` (2026-07-27 규약 · 전 모듈 공통)
모듈이 만든 **지식노트**는 전부 여기. `2_지식/notes/`는 **코어 지식 전용**(선언 시 block).
- **프론트매터 필수 · MOC 등재 면제** — 모듈은 MOC에 *설계노트 1줄*로 대표된다. 산출물마다 등재하면 MOC 폭증(도그푸드 실측 마찰점②의 **구조적 해소** — 묶음 모노노트 우회가 더는 필요없다).
- 검색·중복basename·수식검사·B1 이웃블록은 notes/와 **동일 적용**(코어 글롭에 반영 완료) → 교차링크 차별점 무손상.
- 파생·캐시는 `3_시스템/_index/<모듈명>/`(gitignore). **모듈 설계노트만 예외** — `2_지식/notes/외부뇌-<모듈명>-모듈.md`(MOC 등재 대상).
- 타모듈 폴더·`modules/` 루트 선언 = block(소유권 1:1).

### D5. 토글 응집 = 경계 기준, 크기는 아니다 (2026-07-30 실측)
모듈은 **on/off 단위**다. 스킬 개별 off는 불가(`skillOverrides`는 플러그인 스킬에 무효), `claude plugin disable <모듈>@skills-dir`만 유효하고 끄면 description·훅이 **전부 0**(실측).
- 경계 질문 **2축**: **"같이 바뀌나?"**(D1 응집) + **"같이 켜지나?"**(토글 응집).
- **크기는 경계 기준이 아니다.** 스킬 5개·2KB라도 항상 함께 켜고 끈다면 한 모듈이 맞다(학습보조 모듈이 그랬다). 필요기능을 합계 바이트 때문에 쪼개면 사용자가 매번 여러 모듈을 같이 켜야 하고, 경계 수만 늘고 얻는 게 없다.
- 분리 신호는 크기가 아니라 **사용주기 불일치**: 하나는 상시 필요한데 나머지는 가끔 → 상시분을 떼라. **켜는 이유가 서로 다르면 다른 모듈.**
- 합계 바이트는 경계 판정이 아니라 **description 품질 신호**로만 쓴다(§F4).

### D4. touches 귀속 규칙
`touches` = **모듈이 소유하는** 경로. 모듈이 *대신 써주는* 산출물(module-forge가 만드는 설계노트·ADR)은 **대상 쪽 경계**에 귀속. 넓게 선언하면 타모듈과 포함관계 warn만 늘고 경계 의미가 사라진다 → **좁게**.

## E. 게이트 규율 (산출물 품질 — 실사용 모듈 실측)

### E1. 품질은 규약이 아니라 스크립트 게이트로
모델이 지키기로 한 규약은 조용히 드리프트한다(실측: 드리프트 3건). 산출물 품질 기준이 있으면 **판정 스크립트 + 훅**으로 못박아라(예: `check_exam.py` 17항목).
- **검증자도 검증한다**: 게이트를 회귀로 돌려 **지표 결함**을 잡아라(실측: 회귀가 게이트 자체의 결함을 노출).
- **대조군이 결정타**: 깨짐 진단은 "정상 산출물 vs 깨진 산출물" 대조로. 추론만으론 오진했다(실측 오진 2회).

### E2. 모듈발 코어규칙 승격 절차 (I1 압력 — 07-27 실물)
모듈 작업 중 "코어 훅에 검사 하나 넣으면 되는데"가 나온다(실물: 실사용 모듈의 산출물에서 수식이 깨져 코어 Stop훅에 `$$` 검사를 추가했다). 판정:
- **전 볼트에 일반적인 규칙인가?** → yes면 코어 승격 OK(설계노트에 근거 기록). no면 **모듈 자체 훅**(안전 이벤트만, I2 준수).
- 코어를 건드리면 **I1 예외를 명시적으로 기록**하라. 조용한 코어 수정 누적 = 규약 비대(뿌리②) 재발.

### E3. 체감 ≠ 실측
"토큰 많이 쓴 것 같다"류 체감은 실측과 **반대일 수 있다**(로그 크기 ≠ 토큰). 모듈 비용·성능 주장은 재보고 말해라.

## F. description 작성법 — 짧고 **정확하게** (2026-07-30 확정)

description은 설명문이 아니라 **라우팅 신호**다. 모델이 SKILL.md 본문을 읽기 *전에* 보는 유일한 것이고, 모듈이 켜져 있는 한 상주비용이다. 그래서 목표는 "짧게"가 아니라 **발동에 기여하지 않는 바이트를 0으로**다. 짧아져서 안 걸리면 절감이 아니라 **고장**이다 — 절감분보다 미발동 1회의 손해가 크다.

### F1. 넣을 것 4개 (이 순서)
1. **행위 1구** — 무엇을 하는가. 명사구·동사로 짧게. (`PDF를 볼트 지식으로`)
2. **발동 조건** — *언제* 부르는가. **이게 본체다.**
3. **사용자 어휘 트리거 3~5개** — 사용자가 실제로 칠 말을 따옴표로 나열. 내부 용어·모듈 전문어 금지(모델은 그 말을 듣지 못한다).
4. **음성 경계 1구** — 헷갈릴 이웃(형제 스킬·유사 코어스킬)과의 구분. **바이트 대비 정확도 이득이 가장 큰 항목.** 예: `※플래시카드/Anki 아님 — 자료정리(무손실) 전용`.

### F2. 빼야 할 것 — 전부 본문이 할 일
| 빼는 것 | 왜 |
|---|---|
| 절차·단계 나열(`A → B → C로 끝난다`) | 발동 *후에만* 쓸모. 발동 판단 기여 0 |
| 산출물 포맷·경로·파일명 | 동 |
| 아키텍처·구현 방식 | 동 |
| 하위 스킬 위임 설명 | 하위 스킬이 자기 행을 이미 갖는다. 순수 중복 |
| 모듈명 반복 | 리스팅이 `모듈:스킬` 프리픽스를 이미 붙인다 |
| 품질 형용(`능동`, `정교한`) | 트리거 아님. **단 구분에 필요하면 F1-4로 남긴다** |

### F3. 정확도 자기점검 3문 (작성 직후 필수)
- **오발동**: 이 문장만 보고, 부르면 안 되는 요청에도 부를까? → 음성 경계 추가.
- **미발동**: 이 기능이 필요할 때 사용자가 쓸 말 중 여기 없는 표현은? → 트리거 보강. **줄이다 트리거를 지우는 것이 최대 실패모드.**
- **형제 충돌**: 같은 모듈 다른 스킬과 첫 구가 겹치나? → 겹치면 둘 다 못 고른다. 차이를 앞으로 끌어와라.

### F4. 예산 — 하드블록 아니라 신호
- 환산: **한글 description 바이트 ÷ 5.8 ≈ 토큰**(실측 3건 평균 5.8. 영문 기준 3.6~4를 쓰면 2배 과대추정한다 — 실제로 틀렸던 값).
- 기준선 **스킬당 ≤ 350B(~60tok)**. 넘으면 삭제가 아니라 **§F2가 섞였는지 점검**하라. F1 4항목만 남기면 대개 250B 안에 든다.
- **모듈 합계엔 상한 없음** — 크기는 경계 기준이 아니다(D5).
- 검증: `/context` Skills 세부표의 해당 모듈 행.
