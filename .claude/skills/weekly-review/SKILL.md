1. 지난주 sessions/ 훑기(제목+gist만) → 통찰노트 1개 작성(type:semantic, confidence:hypothesized, 소스 링크).
2. inbox-sort 실행.
3. `2_지식/open-loops.md`: **이중 주체 정리** — ①사용자가 `- [x]` 체크한 항목 삭제 ②Claude가 종결로 판단한 항목도 삭제. 판단이 애매한 스테일 항목은 지우지 말고 **체크 후보로 나열해 보고**. 아울러 **형식 위반 건수 보고** — `## ` 섹션 아래 최상위 `- ` 줄인데 `- [ ]`/`- [x]` 가 아닌 것(설계노트 §10 훅 복원조건의 측정값). **300자 초과 항목은 gist+링크 1항목으로 교체**(상세는 세션·프로젝트 노트에) — 교체 건수도 보고.
4. **골든셋 있으면** 5문 샘플 재측정(`py -3 3_시스템/search.py --eval <골든>`) → `_eval/results-weekly.md` 추가, 낙폭 시 보고. **없으면**(배포 초기 — 사용자 미작성) `_eval/measure.md` 절차로 골든 작성 권유 후 이 스텝 스킵.
5. _ref 신규 incident 있으면 MOC 반영.
6. 헬스: 인덱스·백업·노트 수 보고. **T1 크기**(`recent.md`+`open-loops.md` 바이트, 상한 open-loops 6KB) + `_index` 총용량 + `_index/work/` 잔여 개수 함께 보고. **삭제하지 않는다** — 설계노트 §10 임계(`_index`>200MB 또는 `work/`>50개) 초과 시에만 사용자에게 정리를 제안. **마지막 커밋 경과시간**(`git log -1 --format=%cr`) — **24시간 초과면 경고**. 자동커밋은 조용히 죽는다(제작자 볼트 실측: 0바이트 `.git/index.lock`이 62시간 동안 커밋을 막았는데 사용자에게 가는 신호가 0이었다).
7. **코어 게이트 계측**(→ `_ref/코어수정-준수사항-체크리스트.md`). 읽기 전용 2줄 실행 → 보고:
   - `git log --since="7 days ago" --oneline -- "3_시스템/hooks/" "3_시스템/search.py" CLAUDE.md "3_시스템/conventions.md" .claude/settings.json` → **코어 변경 커밋 수**, 그중 메시지가 `session:`인 것(=절차 흔적 없는 익명 수정) 수를 함께.
   - `3_시스템/_index/core-gate.log` 줄 수 → **게이트 발동 횟수**. **판정태그별로 나눠 센다**(`ASK`·`TOKEN-ALLOW`·`TOKEN-DENY`·`TOKEN-OTHERSESSION`·`TOKEN-EXPIRED`·`TOKEN-NOSESSION`·`TOKEN-BINDFAIL`·`GATE-BROKEN`). **`GATE-BROKEN`이 1건이라도 있으면 최우선 보고** — 판정부(`core-gate-decide.ps1`)가 사라져 게이트가 죽은 상태다(fail-open이라 조용하다). `TOKEN-*`가 있으면 그 주에 무인 위임이 있었다는 뜻이므로 대상 경로를 함께 나열한다.
   판정: 발동 0인데 코어 변경이 있으면 **게이트가 죽었거나 우회됐다**(교차검증 — 두 수의 불일치가 유일한 생존 신호). 익명 커밋이 있으면 해당 해시를 나열해 사후 검토 대상으로 보고. **고치지 말고 보고만** 한다.
   - **나열한 익명 코어 커밋마다 근거 문서를 붙인다** — 같은 날짜(`%cs`)의 `2_지식/sessions/`·`decisions/`·`3_시스템/_ref/` 노트를 찾아 커밋 해시 옆에 적는다. 날짜가 안 맞으면 전후 1일까지 본다(incident는 발생일로 `created`가 박혀 후속 섹션이 다음 날 붙는다). **못 찾은 것만** 사후 검토 대상으로 올린다.
     > Stop 훅 자동커밋은 `session: 날짜`라 그 자체로는 근거가 없다 — 이건 버그가 아니라 durability 설계다(§12.6). 근거는 ADR·incident·세션노트에 남고, **이 대조가 git 이력과 문서를 잇는 유일한 지점**이다. 제작 볼트 전수 측정(2026-08-17) = 절차 도입 이후 익명 코어 커밋 5건 **전부** 근거 문서 보유(소실 0). 그래서 자동커밋에서 코어 경로를 빼는 방지층은 채택하지 않았다 — 새 정보를 만들지 않고, 매 턴 도는 커밋 경로를 건드리는 위험만 남는다. 이 대조를 빼면 그 전제가 여전히 참인지 아무도 확인하지 않는다.
   - **frontmatter YAML 위반 건수**(§10 임계 측정값):
     `find 2_지식 3_시스템/_ref -name '*.md' -type f | while read f; do awk 'NR==1&&$0!="---"{exit} NR>1{if($0=="---")exit; if(match($0,/^[A-Za-z_][A-Za-z0-9_]*:[ \t]*/)){v=substr($0,RLENGTH+1); if(v~/^"/){if(v!~/^"[^"]*"[ \t]*$/)bad=1} else if(v!~/^[["{]/&&v~/:[ \t]/)bad=1}} END{exit bad?1:0}' "$f" || echo "$f"; done`
     → 출력된 파일이 **누적 2건 이상이면** 프론트매터 실파싱 검사 도입을 제안(적용은 사용자 승인 후 — 코어 수정).
   - **스키마 밖 `type`·이물 필드 건수**(계측만 — 강제하지 않는다):
     `type` 허용값은 `semantic|episodic|procedural|decision|moc|incident` 6종. 그 밖의 값과, 프론트매터 키가 스키마 11종(`type·title·created·updated·tags·links·status·importance·confidence·source·sensitive`) 밖인 것을 센다. **`created` 누락은 상시 갱신 핵심파일**(MOC·recent·open-loops·profile·설계노트·사용자설명서)**에서 정상**이므로 그 6개는 제외하고 센다.
     > **왜 강제하지 않나**: `type`을 읽는 코드가 볼트에 없다 — `search.py` 미사용·훅 미검사·Dataview 대시보드 0건이라 값이 틀려도 아무 일도 일어나지 않는다. 피해가 실측되지 않은 상태에서 검사층을 넣는 것은 체크리스트 §0 위반이다. **소비자가 생기면**(대시보드 신설 등) **그때 강제를 논의한다.** 이 계수가 그 판단 재료다. 제작 볼트 실측(2026-08-17) = 방치 상태에서 6주간 10건 누적, 발생이 한 번이 아니라 지속적이었다.
8. **토큰 회계·출력 품질**. `py -3 3_시스템/tokens.py --n 10 --tools --batch --quality` → 보고.
   > ⚠ 아래 괄호 안 **기준선은 전부 제작자 볼트 실측값**이다. 사용 패턴이 다르면 그대로 적용되지 않는다. **이 스텝을 처음 돌린 주차의 수치를 자기 기준선으로 삼고** 이 문단을 갱신하라. 남의 기준선과 비교하면 없는 추세를 본다.
   - **출력 품질 지표**(`lean` output-style이 활성일 때 의미가 있다): 답변당 가시자(기준선 **2,426자**) · 3행 미만 표 비율(기준선 **13%**) · 인라인 `$…$` 횟수(기준선 **3**/36답변, 렌더 안 되므로 **감소해야 정상**). **답변당 가시자가 2주 연속 +2% 이상이면 압축 규칙이 안 먹는다는 신호**로 보고. ⚠ **승인 프롬프트가 뜰 것 같으면 시도하지 말고 "미실행"으로 보고**한다 — 무인 실행에서 승인 대기는 조용한 사망이다(제작자 볼트 실측: 자동 실행이 첫 `Write` 승인 대기에서 3시간 54분 뒤 abort).
   - **도구 결과 : 가시 텍스트 배수**와 최대 유입원. 기준선 1.1~4.3배(Bash·WebFetch·Read 순). 컨텍스트의 89%가 Messages이므로 **여기가 유일한 실질 레버**다. `WebFetch` 평균이 크면 `defuddle` 미사용 신호, `Read` 평균이 크면 §2 위반 신호 — **보고만 하고 고치지 않는다.**
   - **배치 구조**(도구 규약 준수의 직접 지표): 연속 단독런 수·낭비율, 그리고 **도구 구성비를 반드시 함께**. 기준선 = 명백 절약가능 개발 37~43%·설계 21%·리서치 10%, 실행 런 개발 22~28개. ⚠ **구성비 없이 주차를 비교하면 교락된다** — 실측에서 `read` 43%→8% 구간에 배치율 1.48→1.02가 동행했다. 배치율 하락이 규칙 미준수인지 작업 성격인지는 구성비로만 갈린다.
   - **배치 규약 철회 신호 4개 중 하나라도 뜨면 보고**: ⓐ 도구결과 배수가 기준선 위로 상승(투기적 병렬) ⓑ 배치율은 오르는데 턴당 요청 불변(효과 없음) ⓒ 2주 연속 세 지표 무변화(규칙 미작동) ⓓ `3_시스템/`에 1회용 스크립트 누적.
   - 세션별 **출력 · 표준입력환산 · `cache_read`**, 그리고 `cache_read ÷ 출력` 비(관측 45배).
   - **가시%** = 사용자에게 보인 텍스트 / 출력 토큰. 압축 규칙의 사정거리다. 기준선 12~28%.
   - **style 열** 귀속(`lean` / `(default)`)이 의도와 다르면 보고.
   - `bad`(깨진 줄)가 0이 아니면 원인 확인 대상으로 보고.
   **임계를 만들지 않는다** — 표본이 부족하다. 수치와 추세만 보고하고 판정은 하지 않는다. 임계는 데이터가 쌓인 뒤 별도 결정.
   원자료가 필요하면 `--raw <파일>`로 저장한다. **stdout에 원자료를 붙이지 않는다** — 계측이 스스로 컨텍스트를 먹는다(모듈 리스크 1).
   - **결과를 `_eval/results-weekly.md`에 주차별로 추가한다**(4스텝과 같은 파일, 별도 섹션). 안 남기면 주차 간 비교도, 이 스텝이 실행됐는지 확인도 불가능하다 — 트리거만 있고 카운터가 없는 상태가 된다.
   - **모델이 섞인 주차는 모델별로 나눠 보고한다.** 기준선은 전부 단일 모델(Opus 5) 기준이고, 다른 모델 세션을 합산하면 지표 해석이 교락된다.
