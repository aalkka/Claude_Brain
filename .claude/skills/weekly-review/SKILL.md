측정은 대본 하나로 받는다. `py -3 3_시스템/weekly.py --save`(읽기 전용 · `_eval/results-weekly.md`에 덧붙임 · 무겁거나 모델이 없으면 `--no-eval`). 공휴일 표도 함께 받는다(`py -3 3_시스템/holidays.py --if-old 30` · 받기만). 리포트를 읽고 아래 판단만 한다. **무인 실행이면 승인 질문으로 멈추지 않는다**(승인 대기는 조용한 사망이다) — 승인이 필요한 일은 보고만 남긴다.

1. 지난주 세션노트(`py -3 3_시스템/roles.py path sessions`) 훑기(제목+gist만) → 통찰노트 1개(type:semantic, confidence:hypothesized, 소스 링크).
2. 받은함: `py -3 3_시스템/inbox.py` = 제안 · `--apply` = 확신 높음만 옮기고 색인 · `--take <이름> <새 자리>` = 고른 자리로. md 승격 규칙은 `conventions.md` §원본·색인. 애매한 것은 두고 보고한다.
3. 정리 후보: `py -3 3_시스템/cleanup.py` → 후보 줄(같은 내용 사본 · 제출·승격된 작업 파일 30일 · 빈 파일·폴더 · 받은함 승격 끝)과 계획 파일 경로를 보고. **지우지 않는다** — 사용자가 대화에서 승인한 것만 `py -3 3_시스템/fileops.py plan <계획> --apply`. 휴지통 30일 넘은 것은 «비우기 = 사람(`fileops purge --older 30`)»으로만 알린다.
4. `2_지식/open-loops.md`: 사용자가 `- [x]` 체크한 항목과 Claude 가 종결로 판단한 항목을 지운다. 애매한 스테일 항목은 지우지 말고 체크 후보로 보고한다. 형식 위반 수는 리포트에 있다. 300자 넘는 항목은 gist+링크 한 항목으로 교체하고 건수를 보고한다.
5. 리포트를 절별로 판단한다. **고치지 말고 보고만** 하는 절은 표시했다.
   - **코어 게이트(보고만)** — `GATE-BROKEN`은 최우선 보고(판정부가 없어 게이트가 죽었다). 코어 변경이 있는데 발동 0이면 게이트가 죽었거나 우회됐다. `TOKEN-*`는 그 주 무인 위임이니 대상을 함께 적는다. 근거 문서를 **못 찾은** 익명 코어 커밋만 사후 검토로 올린다. 왜 = [[ADR-006-코어파일-수정-게이트]].
   - **어긋남** — 코어·기억·스킬 글이 볼트 현실과 다른 곳. 옛 이름·없는 경로·상한 위반을 고친다(코어는 diff → 승인). 건수가 줄지 않으면 원인을 보고한다.
   - **프론트매터(보고만)** — YAML 위반 누적 2건 이상이면 `_ref/incident-2026-07-27-frontmatter-title-부분인용-YAML파싱오류`의 pre-commit 패치 적용을 제안한다(코어). 스키마 밖 값은 세기만 하고 강제하지 않는다.
   - **헬스(보고만)** — 마지막 커밋 24시간 초과면 경고. `_index`·work 는 임계 넘을 때만 정리를 제안한다.
   - **incident** — 미반영분을 MOC 시스템 진단 칸에 올린다.
   - **스킬 사용** — 호출 0 만으로 제거 후보로 올리지 않는다. 그 일이 실제로 있었는지 사람 말에서 확인해 가른다: 있었는데 없이 처리됨 = 쓸모없음 후보 · 일 자체가 없음 = 아직 안 씀. 지우는 것은 사용자 결정.
   - **골든셋** — 낙폭이 있으면 보고. 파일이 없으면 작성을 권유한다.
6. **토큰·출력 품질(보고만)** — 수치와 추세만 보고하고 판정은 하지 않는다(표본이 부족하다).
   - §5 품질: 답변당 가시자(기준선 2,426자)가 2주 연속 +2% 이상이면 §5 철회 신호(ADR-009). 3행 미만 표(13%)·인라인 `$…$`(3회/36답변)는 줄어야 정상.
   - 도구 결과 : 가시 텍스트 배수(기준선 1.1~4.3배)와 최대 유입원. `WebFetch` 평균이 크면 defuddle 미사용, `Read` 평균이 크면 통독 신호.
   - 배치(ADR-007): 연속 단독런·낭비율은 **도구 구성비와 함께** 본다(구성비 없이 주차를 비교하면 교락된다). 기준선 = 명백 절약가능 개발 37~43%·설계 21%·리서치 10%. 철회 신호 ⓐ 도구결과 배수 상승 ⓑ 배치율은 오르는데 턴당 요청 불변 ⓒ 2주 연속 세 지표 무변화 ⓓ `3_시스템/`에 1회용 스크립트 누적.
   - 가시%(기준선 12~28%) · `cache_read ÷ 출력` · style 열 귀속 · `bad`(깨진 줄). 모델이 섞인 주차는 모델별로 나눈다(기준선은 Opus 5 — 지금 모델 Opus 5.5 와 비교할 땐 모델 차이를 함께 적는다).
7. **같은 신호가 4주 넘게 이어지면 보고로 끝내지 말고 사용자에게 결정 항목으로 올린다** — 원인을 재 고칠지, 지표를 버릴지. 판정 없는 지표는 입력만 먹는다.
8. 통찰·판단 결과를 `_eval/results-weekly.md` 그 주 절 아래에 덧붙인다.
